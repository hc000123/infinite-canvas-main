# 交付审计规则

## 清单对账

以已批准镜头集合为左表，以实际生成结果和导出文件为右表。逐个 `shotId` 对账，检查缺失、重复、错配、失败状态和文件不存在。不用“大部分完成”掩盖具体缺口。

## 成功判定

同时满足才能记为成功：镜头 ID 属于已批准清单；结果已完成；质量门通过；输出可定位；未被更新的分镜或资产版本污染。

## 失败定位

`reason` 写直接事实，例如请求失败、输出缺失、哈希不匹配、身份漂移、动作未完成或导出文件不存在。不用“效果不好”这类无法路由的结论。

## 重试路由

建议必须对应失败原因，并遵循单变量原则：身份漂移先减少次要运动或加强身份引用；动作混乱先收束为一条因果动作链；运镜未执行先保留一个主运镜；版本不一致先重建当前输入快照。

## 导出清单

`file` 是可定位的实际输出文件或产物标识。`status=ready` 只用于已核实可交付的行；其余使用 `failed` 并在 `failed` 数组中给出原因。清单不执行上传、删除、覆盖或发布。
