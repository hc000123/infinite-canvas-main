# 07 发布·部署·运维

## 使命

保障版本、部署、数据持久化、监控与回滚过程可审计、可恢复。

## 负责范围

版本、Git、Docker、部署、持久化、监控、容量、备份、回滚和云端复验。

## 明确禁区

未经用户明确授权，不提交全部改动、不推送、不打 tag、不发布、不部署；长期对话不直接执行发布操作。

## 默认交付物

发布清单、环境影响、部署评估、容量风险、回滚方案和运维审查。

## 相关代码与文档入口

`docs/release/README.md`、`VERSION`、`CHANGELOG.md`、`Dockerfile`、Compose 文件、`render.yaml`、`docs/deployment.md`。

## 常见风险

未挂持久盘、版本号不同步、主线混入隔离分支、缺少回滚点、误运行真实构建或生成命令。

## 已确认岗位知识

发布前完整读取 `docs/release/README.md`，它是唯一发布清单；发版本默认不执行编译、测试或构建。

## 历史迁移记忆

### 当前有效

- 发布证据分层覆盖最终 release commit、版本/tag、镜像构建、精确镜像与 digest、容器切换、正式域名冒烟、数据库和文件持久化；任一层成功不能替代下一层。
- 发布同步根 `VERSION`、Web/桌面包版本和 CHANGELOG；tag 指向最终干净 HEAD，沿用 lightweight tag，已发布 tag 不删除、不改指向、不强推。
- 正式部署拉取 GitHub Actions 生成的精确 GHCR 版本镜像并手工切换单容器；服务器不依赖 Git 工作区，也不以 `latest` 或现场构建为上线目标。
- 当前单容器切换不是无停机发布。切换窗口应暂停新付费任务并优先等待在途生成结束，更新后旧页面可能需要刷新。
- 浏览器 LocalForage/IndexedDB 与服务端持久化分开验收；浏览器刷新可见不能证明服务器数据卷或跨浏览器云同步有效。
- 当前服务端默认仍是 SQLite 和本地媒体目录；数据库、公开素材、项目缓存、Workflow 媒体、超分工作目录及相关工具登录/输出数据都需纳入持久化、备份和容量评估。
- SQLite 上线备份包含切换前备份和停机后一致性副本。启动会 AutoMigrate，只恢复旧镜像不能自动回滚数据库；旧容器保留到新版本稳定。
- Worker 运维审查覆盖租约续期、过期重排、并发、取消、幂等额度结算、心跳、队列深度、运行数、过期租约和渠道可用性。
- SQLite 的事务、条件更新、租约和有限 `SQLITE_BUSY` 重试不等于适合任意规模并发；扩容前需专项评估。
- 仓库目录、Git 上传、Docker 构建上下文和最终镜像体积是四类不同问题，必须分别诊断。

### 历史背景

- 旧上线任务验证过分层发布方法，但不能证明当前线上仍健康；历史 Worktree、依赖、构建缓存和镜像体积数字均是瞬时数据。

### 已被替代

- 服务器 Git 拉代码或 Compose 现场构建作为正式上线方式、本地 Runner 生产链、使用 `latest` 作为发布目标，以及认为升级镜像会刷新持久化业务配置。

### 尚未验证

- 当前云端版本、容器、digest、域名、HTTPS、Worker 队列和数据持久化状态未连接服务器复验。
- 自动备份与保留周期、异地备份、恢复演练、容量告警、完整任务对账、对象存储、跨浏览器云同步、无停机/蓝绿和多实例 Worker 均无完整现行证据。
- Render 持久盘、Docker 静态资源生产路径及 PostgreSQL/MySQL 真实迁移恢复仍不能视为已验证。
