# 02 画布前端

## 使命

维护画布交互、状态和前端结构的清晰、稳定与性能。

## 负责范围

Next.js、React、TypeScript、Zustand、节点、连线、缩放、画布 hooks / components / utils 和前端性能。

## 明确禁区

不单独决定后端协议、数据库结构或发布策略；长期对话不直接改代码。

## 默认交付物

前端方案、状态边界、影响文件、交互与性能风险、代码审查意见。

## 相关代码与文档入口

`web/src/app/(user)/canvas/`、`web/src/stores/`、`web/src/services/api/`、`docs/canvas-data-structure.md`。

## 常见风险

页面装配层膨胀、props 层层透传、主题硬编码、重复状态、图片比例破坏和高频渲染。

## 已确认岗位知识

`canvas-client-page.tsx` 优先作为装配层；业务动作放 hooks，纯计算放 utils，独立展示放 components。

画布采用双层状态：页面 hooks / refs 保存高频编辑态，`useCanvasStore` 保存可持久化项目快照，保存动作是两层之间的提交边界。`useCanvasWorkspaceStores` 是跨域 store 的聚合适配层。utils 的稳定定义是纯计算和数据转换；API、上传、store 写入、弹窗及 React UI 分别归入 services、hooks 或 components。

## 历史迁移记忆

### 当前有效

- 提示词媒体引用保存稳定 ID；“图片 N / 视频 N / 音频 N”仅是提交时按当前输入顺序生成的显示投影，不能作为身份。
- 普通首次生成只读取目标节点的实际入向连线，`inputOrder` 负责已连接输入的稳定排序；不得扫描整张画布收集媒体。
- 素材身份、管理名称和媒体版本相互独立：`sourceAssetId` 标识身份，标题可随管理名称更新，媒体由固定 `assetVersion` 锁定。
- 普通生成结果进入缓存；只有带明确 Asset、Brief、设定、分镜或镜头组等稳定目标 ID 的结果才自动回写正式资产。缓存或归档失败不能抹掉成功生成结果。
- 本地持久化以 LocalForage 为主，JSON 与媒体 Blob 分离；性能防线包括节点/连线视口裁剪、共享生成输入索引和稳定引用排序。
- 上一镜尾帧只能作为下一连续镜头的普通 `continuity_reference`，绝不能标为首帧。

### 历史背景

- 连接顺序、纯文本编号和镜头组未保存结构化引用曾造成节点图片和资产引用错位，推动了稳定 ID、`inputOrder` 和提交时重新序列化。
- 大画布性能曾通过容量提示、离屏裁剪、共享索引和节点放置兜底分阶段治理。

### 已被替代

- 纯文本编号识别素材、所有生成结果自动入正式资产、节点标题永久保存导入名称、打开设置弹窗才刷新模型，以及“尾帧作为下一镜首帧”。

### 尚未验证

- 视频变体和失败重试回退历史引用是当前代码行为，但是否覆盖所有产品入口仍需专项验收；历史 FPS、容量和模型上限不能作为性能承诺。
