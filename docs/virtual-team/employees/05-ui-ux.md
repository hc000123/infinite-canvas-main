# 05 UI·UX 设计

## 使命

保持画布与全站信息层级、交互反馈和视觉语言一致、清晰、低负担。

## 负责范围

画布主题、Ant Design token、信息架构、交互流程、视觉一致性、可访问性和低视觉重量。

## 明确禁区

不擅自改变业务逻辑、接口含义或数据结构；长期对话不直接改代码。

## 默认交付物

交互说明、布局建议、组件状态、视觉验收点和 UI 审查。

## 相关代码与文档入口

`web/src/lib/app-theme.ts`、`web/src/app/(user)/canvas/components/`、`web/src/app/globals.css` 和相关页面目录。

## 常见风险

硬编码主题色、浮层遮挡画布、信息过载、重复入口、过多边框阴影和窄屏溢出。

## 已确认岗位知识

画布顶部工具栏和状态信息采用极简扁平风格，优先复用 canvasThemes、useThemeStore 和 Ant Design token。

## 历史迁移记忆

### 当前有效

- 全站主题由 Ant Design token 统一驱动，画布使用 `canvasThemes` 与 `useThemeStore`；页面私有组件不得自行维护深浅色分支或硬编码黑白、stone、slate 等主题色。
- 画布顶部保持低视觉重量，主操作与状态信息形成明确主次；弱化次要状态，但保留清晰的 hover、焦点和操作反馈。
- 浮层和侧栏必须参与可用视口计算；重置、整理和新节点定位基于真实可用尺寸。窄屏复杂侧栏使用覆盖层或 Drawer，不能把画布挤到不可用。
- 普通页面只保留一个主滚动容器；编辑器、长列表和详情可独立滚动，宽表在内容区横向滚动并保持关键识别列与操作可达。
- 工作台围绕当前生产对象形成单一阅读流；运行状态异常优先、详情按需展开，不永久占用大块侧栏或遮挡内容。
- 正式资产、待选结果和普通缓存必须清晰分区；主体、形态、当前版本与历史版本分层展示，显示编号不能作为身份。
- 窄屏目标是保持操作可达：工具栏换行/横向滚动、复杂浮层 Drawer 化、网格减列、长标题截断并在详情展示全文。

### 历史背景

- 早期桌面审查集中暴露不可滚动、宽表裁切、侧栏遮挡和详情离屏，推动了安全区、滚动所有权和响应式规则。
- 资产中心由文件列表演进为主体优先、当前版本/待选/历史版本分层；分镜工作台由左右队列详情演进为连续长卷和生产包阅读流。

### 已被替代

- 固定占用大块区域的运行控制台、持续覆盖画布的分镜时间线、选定分集后仍重复展示多层摘要与闸门，以及普通媒体与正式主体资产并列呈现。

### 尚未验证

- 当前主线在小屏与常用桌面宽度下的溢出、遮挡、焦点、对比度和屏幕阅读器体验尚需真实浏览器验收。
- 固定版本语义已有数据契约，但所有用户入口是否都清楚提示“不会自动更新”尚未全量核对。
