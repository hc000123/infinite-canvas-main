## 总控复核原则

同一知识如果跨岗位重复，只在最匹配岗位写完整版本，其他岗位写短交叉引用。历史任务说法与当前正式文档冲突时，以当前代码和正式文档为准。

## 第一批已复核发现

- 架构：项目承载长期上下文，分集是生产单位，Workflow 编排生产链，Skill 提供版本化能力；Invocation / Artifact 是执行与产物真相，页面和画布不得另建状态真相。
- 架构：固定岗位 Agent、项目专属 Skill 管理、本地 Runner 和画布节点承载正式生产状态均已被当前 Workflow / Skill / Invocation 路线替代。
- 画布：媒体引用必须保存稳定 ID；显示编号只在提交时按当前入向连接和 `inputOrder` 生成，不能作为资产身份。
- 画布：素材身份、管理名称和媒体版本相互独立；普通生成结果只缓存，只有带稳定业务目标的结果才自动回写正式资产。
- 画布：高频页面编辑态与可持久化项目快照分层；本地持久化以 LocalForage 为主，JSON 与媒体 Blob 分离。
- 后端：单有效会话、密钥掩码恢复保护、Invocation / Agent Run 幂等与租约、异步视频上游任务映射、云端超分持久任务均已形成当前边界。
- 后端：服务端管理员模型渠道与浏览器本地画布 AI Key 是两套安全边界；当前主线仍以 SQLite 和本地媒体目录为主，不能宣称对象存储或跨设备云同步已完成。

## 已发现冲突与待协调项

- `docs/workflow.md`、`docs/todo.md` 把分集 `/workflow` 描述为唯一正式入口，但当前路由仍跳转到 `/agent` 并内嵌同一工作台。具体 canonical URL 标为“尚未验证”。
- `docs/canvas-node-manual.md` 仍描述“上一镜尾帧作为下一镜首帧”，与 `AGENTS.md` 和当前 `continuity_reference` 实现冲突。旧描述不得迁入岗位事实。
- `docs/todo.md` 的版本基线与根 `VERSION`、近期 Git 发布记录存在漂移；版本号不进入岗位长期记忆。

## 第二批已复核发现

- AI Runtime：Invocation 预检冻结精确 Skill 版本、输入 Artifact/哈希、Schema、执行策略、确认要求和幂等指纹；重试与变体必须继承冻结快照并产生新尝试/版本。
- AI Runtime：Artifact 类型与 Schema 校验、确定性质量门、人工审核和幂等 Apply 是分离门禁；不同渠道/部署必须使用稳定引用和显式适配器，不得静默切换更贵渠道。
- AI Runtime：只读查询和非生成预检不得创建付费任务；排队或等待上游完成不是重建任务的理由，创建超时时应先对账，不能盲目重发。
- UI/UX：主题由 Ant Design token、`canvasThemes` 和 `useThemeStore` 统一驱动；画布顶部维持低视觉重量，浮层和侧栏必须纳入可用视口计算。
- UI/UX：普通页面保持单一主滚动所有权；工作台围绕当前生产对象形成单一阅读流；异常优先、详情按需展开，窄屏通过 Drawer/覆盖层保证操作可达。
- UI/UX：正式资产、待选结果和普通缓存需明确区分；主体、形态、当前版本和历史版本必须分层呈现，显示编号不能充当身份。
- 质量：静态检查、定向测试、全量测试/构建、真实运行态和线上人工链路是不同证据等级；未执行项一律标记未验证。
- 质量：长期回归矩阵应覆盖稳定引用的增删重排、连续性尾帧、Invocation 幂等/租约/并发、跨用户隔离、单会话、密钥掩码恢复、生成归档与部署版本一致性。
- 质量：`docs/release/README.md` 是当前上线门禁；`docs/pending-test.md` 记录本版本待用户验证，`docs/todo.md` 记录后续路线，历史验收报告不能作为当前版本通过证据。

## 第三批已复核发现

- 发布：唯一清单和分层证据覆盖 release commit、版本/tag、镜像、digest、容器、域名、数据库与文件持久化；任何单层成功不能替代下一层。
- 发布：当前是精确 GHCR 版本镜像的单容器手工切换，不是无停机发布；上线窗口需控制新付费任务并等待在途任务。
- 运维：浏览器 LocalForage 与服务端 SQLite/媒体目录需分开验收；SQLite 回滚不能只恢复旧镜像，需一致备份或审核过的前向修复。
- 运维：Worker 健康需关注心跳、队列深度、运行数、过期租约与渠道可用性；已有租约/重排/幂等额度结算不代表完整对账告警已实现。
- 容量：仓库目录、Git 上传、Docker 构建上下文和最终镜像体积必须分别诊断。
