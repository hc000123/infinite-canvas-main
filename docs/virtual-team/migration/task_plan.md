# 历史记忆迁移计划

## 目标

把本仓库既有 Codex 对话、Git 历史、设计/实施文档和正式项目文档中的稳定知识，按岗位整理给七名长期员工。只迁移经当前代码或正式文档支持的内容，不复制旧对话全文。

## 阶段

| 阶段 | 内容 | 状态 |
|---|---|---|
| 1 | 清点旧任务、Git、设计计划和正式文档来源 | completed |
| 2 | 01–03 岗位只读审计与候选记忆提取 | completed |
| 3 | 04–07 岗位只读审计与候选记忆提取 | completed |
| 4 | 总控交叉复核、去重和状态分类 | completed |
| 5 | 写入七份岗位记忆与迁移报告 | completed |
| 6 | 七名员工接收确认与最终核验 | completed |

## 迁移状态

- 当前有效：当前代码、正式文档或近期已合并提交直接支持。
- 历史背景：解释现状来源，但不再指导新实现。
- 已被替代：旧方案已经被新架构或代码取代，只保留警示。
- 尚未验证：有历史线索但缺少当前证据，不写成事实。

## 约束

- 不修改产品代码，不运行构建、测试、发布、推送或付费调用。
- 不迁移密钥、密码、令牌、用户隐私或大段日志。
- 不把对话标题和摘要当作可信结论，必须读取正文或用代码/文档复核。
- 不覆盖根目录既有 `task_plan.md`、`findings.md`、`progress.md`。
- 同时最多三条员工审计工作线。
