# 创作工作流程

本文档用于约束后续工具设计和功能开发。目标是让每个新工具、入口和 Skill 能力都落在同一条短剧制作链路里，避免把产品重新做成分散功能集合。

## 总原则

- 项目是总入口，分集是生产单位，画布是承接和编排空间。
- 剧本按集导入，避免一次性把整部剧本塞进工作流；每一集独立运行 Workflow、Skill、资产、提示词和视频生成。
- 新能力必须说明服务于哪一段流程、读取什么输入、产出什么结果、写回哪里。
- Skill 只生成分析、草案和待审核 Artifact；写入剧本、资产、分镜、素材、画布或触发扣费生成前必须经过用户确认。
- Skill、图片、视频和 CLI 任务的渠道绑定、模型选择、预检、费用、fallback 和环境隔离规则见 `docs/api-channel-workflow.md`。
- 图片、视频、音频、文本和后处理结果都要沉淀为素材，并尽量保留来源、参数、模型、任务和引用关系。
- 已确认的结构化产物优先写入项目、分集、设定库、分镜表、生产包或素材库，不把关键状态只藏在画布节点里。
- 画布不再作为所有能力的前置入口；画布负责承接、连接、试验和局部再生成。

## 编排与能力边界

- 正式生产链由 Workflow 负责确定性 DAG、依赖、条件、重试、审核和恢复；Workflow 新节点只允许引用已发布 Skill。
- 剧本整理、内容分类、资产、分镜、提示词和交付审核都是可独立版本化的 Skill。项目剧本入口直接创建 Skill Invocation，不经过固定岗位 Agent 或 Agent Plan。
- 画布对话只保留一个系统“画布总控”。它基于当前用户可见的 Skill Catalog 决定直接回答或生成临时计划，不承载领域规则，也不能虚构 Skill 或绕过契约校验。
- 临时计划仍冻结 Agent、Skill、Artifact、参数和确认指纹，并沿用 Agent Plan → Invocation → Artifact 的审核与幂等 Apply；普通回答不创建 Plan。
- 旧 Agent Registry、岗位 Agent 页面和 Workflow Agent 节点仅作为兼容 / 管理能力保留，不再作为正式生产入口。

## 主链路

```text
项目
  -> 分集剧本
  -> 单集统一视频工作台
  -> 已确认剧本快照 / 服化道 / Seedance 分镜
  -> 审核后写入项目素材与视频生产包
  -> 同页逐条检查与视频生成
  -> 质量门与人工确认
  -> 成品素材归档
  -> 画布承接与二次编排
  -> 剪辑包 / 交付导出
```

## 用户工作方式基线

当前工作流按“单集生产、项目资产复用、视频提示词逐条生成”的方式设计。

当前唯一正式入口为 `/projects/:projectId/episodes/:episodeId/workflow`。页面在同一路由组合阶段轨道、上下文队列、当前编辑区和结果控制台；阶段与当前分镜写入 URL，刷新后可恢复。`/original-workflow`、`/workbench` 与 `/video` 只保留兼容跳转或项目选择说明，不再形成第二套生产界面。

1. 用户把一集剧本导入项目。
2. 用户在统一页面按“剧本确认 → 导演与美术 → 资产准备 → 分镜提示词 → 视频生成 → 审核交付”推进；云端阶段启动后立即进入持久化队列。
3. 资产 Skill 完成后，资产先是空壳：有名称、类型、说明、提示词和来源，但图片可能还没有生成或上传。
4. 用户先在同页查看资产映射预览，确认后写入当前项目素材；已有图片与版本记录不会被文本设定覆盖，补图和素材深度管理继续使用“我的素材”。
5. 用户也可以批量上传资产图，系统按名称、别名或编号自动匹配同名资产。
6. 项目素材库在同一个项目的不同集之间共享。遇到相同或相近资产时，系统提示用户选择合并到已有资产，或创建新版本 / 新变体。
7. 资产图完成后，用户在同页切到分镜提示词或视频生成。视频生产包自动匹配每条提示词需要的资产图，同时允许用户逐条检查、保存和确认。
8. 每条视频提示词都相当于一个视频节点，只是以工作流列表的形式展示；它拥有和视频节点一致的生成设置、生成状态、任务信息和结果预览。
9. 点击生成后，每条提示词按视频节点的逻辑显示进度、失败、同步结果和最终视频。
10. 视频生成后，固定结果控制台展示主预览、历史版本、实际设置、任务同步、失败原因和素材归档状态；较窄桌面通过抽屉保持可用。
11. 保存到“我的素材”时，视频按项目和提示词编号归档；同编号再次调整提示词并生成时，保存为该编号下的新版本。

## 云端 Worker 执行边界

- 视频工作流只走后端内嵌 Worker，不读取用户本机目录，不执行 Codex CLI 或 local-runner。
- 创建阶段任务立即返回 `queued`；Worker 通过数据库租约领取、续租、恢复、取消和重试，默认全局并发 2、单用户并发 1。
- 剧本快照、工作流版本、输入产物、实际模型/渠道、费用、错误、质量门、审核哈希和应用回执均可追溯。
- Worker 只调用后台已经发布的文本模型渠道；工作流页面只显示模型摘要，不提供渠道或密钥编辑。
- 未通过确定性质量门或未人工批准的产物不能应用到本地正式数据。
- 项目、分集、素材和视频生产包当前仍保存在浏览器本地；服务端保存远程任务、产物和回执，不宣称已经支持项目素材云同步。
- 部署配置使用 `WORKFLOW_WORKER_*` 环境变量，不进入后台模型设置。服务退出时先停止领取，再取消当前请求并优雅关闭 HTTP。

## 阶段职责

### 1. 项目

项目负责承载全局设定、分集列表、项目素材、Workflow 配置、生产进度和验收状态。任何跨分集、跨页面或需要长期追溯的配置，都优先挂到项目上下文下。

新增工具时应先判断它是否属于项目级能力：

- 适合项目级：Workflow、全局角色设定、项目素材库、任务日志、质量门报告、剪辑包导出。
- 不适合项目级：单个素材编辑、单个镜头提示词微调、画布节点局部操作。

### 2. 分集剧本

分集是短剧制作的最小主流程单位。剧本导入、剧本优化、导演分析、资产拆解、分镜生产和视频生产包都应围绕同一个 `episodeId` 运行。

工具设计要求：

- 输入必须能追溯到本集剧本或本集确认稿。
- 默认一次只导入一集剧本；跨集共享依赖项目资产库，不依赖一次性导入整部剧。
- 剧本优化结果先作为候选稿展示，用户确认后才成为本集生产稿。
- 后续阶段读取确认稿，不默认读取未确认草稿。

### 3. 导演分析

导演分析负责把剧本转成创作判断，包括叙事节奏、人物状态、场景重点、视觉基调和镜头策略。它不直接生成资产，不直接写画布，也不触发视频生成。

工具设计要求：

- 输出必须可读，不能只保存原始 JSON。
- 具体步骤、顺序和 Skill 版本以已发布 Workflow 为准；页面只提供运行本集流程和必要的阶段状态。
- 需要保留规范读取记录、输入剧本快照和 Agent 配置版本。
- 通过人工确认后，才允许下游资产拆解和分镜生产读取。

### 4. 资产拆解

资产拆解负责把本集需要的角色、场景、道具、服化道、氛围和特效整理成资产卡片。资产卡片是后续生图、加白、视频参考图和素材复用的连接点。

工具设计要求：

- 资产卡片必须包含名称、类型、用途、描述、生图提示词和来源。
- 候选资产不能冒充已生成封面；没有生成图时使用明确占位状态。
- Skill 产出的资产默认先进入“待补图”的空壳状态，可以一键全量生成、单张生成或批量上传匹配。
- 批量上传资产图时，优先按资产名称、别名、编号和文件名匹配；匹配结果需要给用户确认，避免同名误绑。
- 资产进入“我的素材”后，应保留项目、分集、来源阶段和 importKey，便于重复导入时更新同一张卡。
- 项目素材库在同项目不同集之间共享。发现同名、同角色或相近资产时，必须提示用户选择“合并复用”“创建新版本”或“创建新变体”。
- 新变体命名要支持类似“小李-白色衣服”“小李-黄色衣服”的区分方式，避免把不同造型覆盖成同一个资产。

### 5. 资产图生成

资产图生成负责把资产卡片转成可用参考图。生成结果应回写素材卡，并按版本管理，不直接覆盖旧引用。

工具设计要求：

- 生图入口可以来自资产卡、Brief、生图工作台或画布节点，但结果都要能回到素材体系。
- 资产界面应同时支持批量生成、单项生成、批量上传、自动匹配和人工改绑。
- 参考图用于视频生成前，需要能显示是否已匹配、是否已加白、是否可作为 `asset://` 参考。
- 缺参考图时可以允许文本生成，但必须提示风险。

### 6. 分镜与视频提示词生产包

分镜与视频提示词生产包负责把导演分析、资产卡片和剧本确认稿转成可审核、可编辑、可逐条生成的视频生产单元。

工具设计要求：

- 生产包必须按镜头或 P 编号展示，包含剧情、参考资产、视频提示词、时长、画幅、状态和生成结果。
- 视频生产界面需要在同一条记录里看到对应剧情、提示词、资产缩略图、生成设置、生成进度和生成结果，不把用户必须同时检查的信息拆到过远的区域。
- 资产图不单独强制占一列；优先在提示词正文对应位置显示资产占位和缩略图，让用户知道提示词中哪一段使用了哪张资产图。
- 即使资产图尚未生成，提示词中也要保留资产占位。用户后续只是替换占位里的图片，而不是重新理解整条提示词。
- 提示词中允许手动插入其他项目资产或本地上传资产，用来补充细节和临时增强镜头。
- Skill 输出先进入映射预览，不直接写入正式分镜表、设定库或画布。
- 用户确认后才能写入正式分镜、设定库、视频生产包或画布配置节点。
- 阶段三类分镜 / Seedance 提示词应支持按场次推进，避免整集一次性失控生成。

### 7. 质量门与人工确认

质量门负责阻断明显不合格的阶段产物，人工确认负责决定是否进入下一阶段。两者是工作流的安全阀，不是装饰信息。

工具设计要求：

- 未通过、未校验或已过期的阶段产物，不能直接导入下游生产包。
- 文件或草案被重新生成、手动编辑后，对应质量门应标记为已过期。
- 质量门报告需要能说明失败原因和下一步修复动作。

### 8. 视频生成

视频生成负责把已确认生产包提交到真实视频通道，记录任务状态，并把成功结果保存为视频素材。

工具设计要求：

- 每条视频提示词等价于一个视频节点。工作流页面可以不用展示成画布节点形态，但生成参数、任务状态、失败重试、同步结果和结果 metadata 应与视频节点保持一致。
- 每条提示词都能单独调整视频生成设置；批量生成时使用各自保存的设置，而不是一个全局设置覆盖全部镜头。
- 生成前必须能看到实际通道、实际模型、关键参数和参考资产状态。
- 企业 Ark / Seedance 等扣费通道要先做非扣费预检。
- 生成中断后应保留任务 ID，允许继续同步结果，不强迫重新创建任务。
- 成功视频写入“我的素材”，并保留生产包、提示词、模型、任务和参考资产 metadata。
- 成功后在提示词记录后方显示视频预览图或预览入口；点击后打开详情抽屉，展示视频播放、提示词、视频信息、生成时间、任务 ID、模型、参数和归档状态。
- 视频保存到素材库时默认归入当前项目，名称使用提示词编号或 P 编号；同编号再次生成时保存为新版本，而不是覆盖旧视频。

### 9. 画布承接

画布负责把已确认内容变成可视化节点、连线和局部试验空间。它可以承接生产包、素材、提示词和生成结果，但不应该成为绕过上游确认的捷径。

工具设计要求：

- 从工作流进入画布时，应创建或复用明确绑定项目和分集的画布。
- 画布节点可保存来源 metadata，但业务主状态仍应回到项目、分集、素材或生产包。
- 画布里的再生成结果仍需归档到素材，避免只存在于临时节点。

### 10. 交付导出

交付导出负责把已确认视频、字幕、素材引用和剪辑信息整理给后续剪辑或发布环节。

工具设计要求：

- 导出内容必须来自已确认的生产包或素材版本。
- 导出前应能提示缺素材、失败任务、过期引用和未确认项。
- 导出不是新的创作入口，不应在导出环节偷偷修改上游内容。

## 新工具设计检查

开发任何新工具前，先回答以下问题：

1. 它属于主链路的哪一阶段？
2. 它读取项目、分集、剧本、资产、分镜、素材、画布还是外部文件？
3. 它产出的是草案、正式数据、素材、任务、报告还是导出文件？
4. 它是否需要人工确认后才能写入？
5. 它写回哪里，是否能被后续阶段继续读取？
6. 它是否触发扣费、远程任务或不可逆操作？
7. 它的失败状态能否继续修复，而不是把用户卡死？
8. 它是否重复了已有入口，能否挂到现有阶段或上下文动作里？
9. 它是否尊重“单集导入、项目资产共享、提示词逐条等价视频节点”的工作方式？
10. 它是否让用户能在关键检查点同时看到剧情、提示词、资产图、生成设置和结果状态？

如果回答不清楚，先补流程设计，不先做页面入口。

## 视频工作流 UI 约束

视频工作流页面优先服务“逐条检查和生成”，不是做成一个宽表堆满字段。

- 每条提示词是一张紧凑的生产记录，核心信息按“编号 / 剧情 / 提示词 / 资产占位 / 生成设置 / 状态 / 结果”组织。
- 剧情用于理解镜头目标，提示词用于编辑生成内容，资产缩略图直接嵌在提示词对应位置或紧邻提示词，不默认拆成远离正文的独立列。
- 资产占位有三种状态：未生成、已匹配、需人工确认。状态要轻量可见，不打断阅读。
- 生成设置应和视频节点保持一致，但在列表中只展示关键摘要；展开后再调整模型、时长、画幅、清晰度、音频等完整参数。
- 单条生成、批量生成、同步结果、失败重试都围绕生产记录本身操作。
- 生成结果预览放在记录末端。点击预览进入详情抽屉，不跳出当前工作流。
- 详情抽屉展示视频播放、最终提示词、引用资产、生成参数、任务信息、生成时间、错误诊断和保存到素材 / 版本管理动作。
- 页面要支持快速扫一集的所有 P 编号，也要支持展开单条做精修；默认信息密度应该服务连续生产，不做营销式大卡片。

## 入口放置规则

- 项目级配置放到项目工作台、项目详情或全局设置。
- 分集生产动作放到本集生产流程或视频工作流控制台。
- 素材查看、筛选、版本和加白放到“我的素材”或素材上下文动作。
- 生图参数和单次图片生成放到生图工作台或资产卡片动作。
- 视频生产包审核和真实视频生成放到视频生产台；视频生产台的每条提示词应按视频节点能力设计，只是以工作流记录形态呈现。
- 画布只放承接、编排、节点局部生成和素材插入，不堆完整生产流程。

## 不做事项

- 不把所有能力都塞进画布。
- 不新增只有跳转作用的空壳页面。
- 不让画布总控或 Skill 自动改正式数据或自动扣费。
- 不把未确认草案写成正式功能结果。
- 不在导出、下载、复制等末端动作里隐藏生产逻辑。
- 不把只属于本集的状态提升成全局状态。
- 不把资产图和提示词拆得太远，导致用户看不到哪张图服务于哪段提示词。
- 不用单一全局视频设置覆盖所有提示词，除非用户明确选择批量套用。
