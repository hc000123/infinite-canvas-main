# 外部 Skill 文件夹导入与阶段运行设计

## 背景

当前 Skill 中心同时承担在线编写、底层契约配置、版本管理和评测，创建时要求手工填写 Capability、Artifact、Schema、质量门等运行字段，试运行还依赖已有 Workflow Run ID。这与实际使用方式不匹配：内容 Skill 通常已在外部按某个生产阶段制作完成，系统真正需要解决的是完整加载、版本冻结、快速试跑和跨入口调用。

本设计把 Skill 分为“内容 Skill”和“固定转换 Skill”。内容 Skill 决定内容产出，可由制作人员导入和切换；固定转换 Skill 属于 Workflow 基础设施，只负责阶段之间的格式适配和硬性规则，不参与内容创作。

## 目标

- 支持从浏览器选择或拖入一个完整 Skill 文件夹。
- 完整保存文件夹快照，包括 `SKILL.md`、规则、模板、示例和其他附属文件。
- 导入时只要求用户选择所属阶段，不要求填写运行时底层配置。
- 通过阶段模板自动生成 Manifest、Artifact 契约、Schema 和质量门。
- 不依赖 Workflow Run，直接使用粘贴内容或项目阶段产物试运行。
- 试运行自动串联该阶段的固定转换 Skill，并分别展示内容原始产出和标准化产物。
- 通过同一精确版本供 Workflow、画布、图片页和 API 调用。
- 保留不可变版本、内容哈希、推荐版本、停用和历史运行追溯。

## 非目标

- 不在网页中重新实现完整 Skill 编辑器。
- 不让制作人员手工维护 Capability、Artifact、Schema 或质量门。
- 不根据 Skill 内容自动猜测所属阶段。
- 不允许导入文件夹中的脚本被服务器直接执行。
- 不允许固定转换 Skill 润色、摘要、补写或删除业务内容。
- 不在导入后自动替换正在使用的推荐版本。

## 核心概念

### 内容 Skill

内容 Skill 由用户在外部制作，每个 Skill 明确归属于一个生产阶段。同一阶段允许存在多个 Skill Definition，同一个 Definition 允许存在多个不可变版本。内容 Skill 的完整文件夹是内容真相，系统生成的运行配置只是阶段适配信息。

### 阶段模板

阶段模板是系统维护的运行合同，至少包含：

- 阶段标识与中文名称。
- 输入 Artifact 类型和 Schema 兼容范围。
- 内容 Skill 的统一原始输出类型。
- 固定转换 Skill Version ID。
- 转换后的标准 Artifact 类型和 Schema 版本。
- 默认执行器类别、确认要求和质量门。
- 允许调用该阶段 Skill 的入口。

用户导入时只选择阶段，服务端根据阶段模板生成完整 `SkillPackage`，并把外部文件夹中的文本运行资料写入 `files`。阶段模板是底层配置的唯一来源。

### 固定转换 Skill

固定转换 Skill 位于内容 Skill 与标准阶段产物之间：

```text
阶段输入
  → 内容 Skill 精确版本
  → 原始内容 Artifact
  → 固定转换 Skill 精确版本
  → 标准阶段 Artifact
  → 下一阶段
```

转换 Skill 只能执行以下操作：

- 统一名称、编号、字段和排序。
- 建立角色、场景、道具、镜头等引用。
- 把内容放入下一阶段要求的结构。
- 标记缺失、冲突和无法映射的信息，并由质量门阻断。

转换 Skill 不得新增剧情、改写正文、压缩摘要、删除信息或改变人物关系。运行时保存转换前后快照及差异摘要，便于确认内容未被改变。

## 用户流程

### 导入新 Skill

1. 管理员进入 Skill 中心，点击“导入 Skill 文件夹”。
2. 选择或拖入完整文件夹。
3. 系统读取文件树并检查 `SKILL.md`。
4. 用户只选择“所属阶段”。
5. 系统从 `SKILL.md` frontmatter 读取名称、说明和版本；缺失名称时使用文件夹名，缺失版本时生成 `1.0.0`，并允许用户在确认页修正这三个展示字段。
6. 服务端套用阶段模板、计算完整文件夹哈希并创建待测试草稿。
7. 页面直接进入试运行。

顶部“导入新 Skill”始终创建新的 Definition，不根据名称自动合并，避免不同 Skill 被误判为同一个能力。

### 导入新版本

1. 在现有 Skill 卡片中点击“导入新版本”。
2. 选择新的完整文件夹。
3. 新版本固定继承现有 Definition 和所属阶段。
4. 系统读取外部版本；缺失时按现有最高版本生成下一个版本。
5. 确认页展示新增、修改、删除的文件清单。
6. 同版本号但文件夹哈希不同必须拒绝；内容和哈希完全一致时提示无需重复导入。
7. 新版本保持待测试，不自动替换推荐版本。

### 试运行

试运行不要求 Workflow Run ID，也不写入正式项目。用户可以：

- 粘贴一份阶段输入。
- 从有权限的项目中选择一份现有阶段 Artifact。

一次“运行测试”依次完成：

1. 创建临时输入 Artifact。
2. 调用内容 Skill 精确版本。
3. 保存原始内容 Artifact。
4. 调用阶段模板锁定的固定转换 Skill 精确版本。
5. 保存标准阶段 Artifact。
6. 执行阶段 Schema、内容保真和业务规则检查。

结果页并排展示“内容 Skill 原始产出”和“转换后的标准产物”，下方只显示可操作的中文问题与转换差异。底层 JSON、Invocation ID、Workflow Run ID 和完整 Trace 收进“技术详情”。

### 启用和替换

- 导入版本初始状态为“待测试”。
- 至少完成一次当前内容哈希的成功试运行后，才可点击“设为可用”。
- “设为可用”发布不可变版本，但不自动设为推荐。
- 用户通过独立操作将已发布版本设为该 Skill 的推荐版本。
- 已发布版本继续使用现有停用机制；无引用草稿可删除。
- 已启动的 Workflow、画布或 API 调用继续使用冻结版本，不随推荐版本变化。

## Skill 中心界面

主界面按生产阶段分组展示内容 Skill，默认只保留以下日常操作：

- 导入 Skill 文件夹。
- 导入新版本。
- 运行测试。
- 设为可用。
- 设为推荐。
- 停用版本。

Skill 卡片展示名称、所属阶段、推荐版本、最近试运行状态和可用入口。版本详情以只读文件树和文件预览为主，不再默认展示 Manifest、Schema、Artifact 合同和质量门编辑器。

底层运行配置、哈希、Invocation、审计和阶段模板信息放入“技术详情”。固定转换 Skill 不出现在普通内容 Skill 列表中，只在管理员的“系统转换规则”区域只读查看；后续如果需要更新转换规则，应通过单独的系统发布流程完成。Workflow 编辑器把它显示为内容节点之后的折叠锁定步骤，便于理解运行链，但不能删除、替换、跳过或改写配置。

## 文件夹解析与保存

### 浏览器上传

前端使用目录选择能力读取相对路径，并以 multipart 上传文件集合；同时提供拖放文件夹。相对路径必须保留，顶层文件夹名仅用于默认名称，不参与内部路径。

### 服务端规范化

服务端应使用成熟 YAML 解析库读取 `SKILL.md` frontmatter，并使用 Go 标准库 `archive/zip` 生成确定性快照。规范化规则包括：

- 路径统一为 `/` 分隔的相对路径。
- 拒绝绝对路径、`..`、符号链接、隐藏系统垃圾文件和重复路径。
- 文件按路径排序后计算哈希。
- 文本文件统一保存 UTF-8 内容；运行时只装载允许的文本类型。
- 二进制文件保留在压缩快照中，但不会直接拼入模型提示词。
- 限制单文件大小、总文件数和总压缩前体积，并返回明确中文错误。

完整压缩快照以不可变 BLOB 随 Skill Version 保存，新增文件索引 JSON、快照哈希和顶层 `SKILL.md` 元信息。现有 `SkillPackage.Files` 继续保存运行时需要的文本文件，不承载二进制内容。发布后的快照不可修改。

## 数据结构调整

### Skill Definition

新增稳定的 `StageKey`。一个 Definition 创建后不可修改所属阶段；如需迁移阶段，应作为新的 Skill 导入，避免已经冻结的运行合同漂移。

### Skill Version

新增：

- `SourceKind`: 固定为 `folder_import` 或系统种子来源。
- `SourceArchiveBlob`: 规范化压缩快照，只在服务端持久化，不进入普通 JSON 响应。
- `SourceFileIndexJSON`: 路径、大小、MIME、文本/二进制标记和单文件哈希。
- `SourceHash`: 完整文件夹哈希。
- `ImportMetadataJSON`: 原始文件夹名和解析到的 frontmatter 展示字段。

阶段生成的 Manifest、输入输出合同和质量门仍冻结在版本上，保证现有 Invocation Resolver 无需读取可变阶段配置。

### 阶段模板注册表

阶段模板使用服务端代码注册表维护，不开放给制作人员自由编辑。每次导入时把模板版本和固定转换 Skill Version ID 一并冻结到 Skill Version，之后模板升级不影响旧版本。

## API 设计

新增管理员接口：

- `POST /api/v1/admin/skills/import-folder`：创建新 Definition 和首个草稿版本。
- `POST /api/v1/admin/skills/:id/import-version`：向现有 Definition 导入新版本。
- `GET /api/v1/admin/skill-versions/:id/source-files`：读取文件索引。
- `GET /api/v1/admin/skill-versions/:id/source-files/*path`：只读预览允许的文本文件。
- `POST /api/v1/admin/skill-versions/:id/trial`：使用粘贴内容或现有 Artifact 建立独立试运行。
- `GET /api/v1/admin/skill-trials/:id`：读取试运行状态、原始产物、转换产物和可读问题。

现有发布、推荐、停用和删除接口继续复用。普通制作入口只读取已发布且启用、阶段匹配的内容 Skill，不暴露固定转换 Skill 选择权。

## 运行与保真门

内容 Skill 输出统一进入阶段原始 Artifact。固定转换 Skill 输出标准 Artifact 后，质量门至少检查：

- 标准 Schema 是否通过。
- 原始内容中的必保留文本是否仍存在。
- 原有实体是否被删除或新增。
- 名称映射是否一一对应。
- 转换报告是否只包含允许的结构操作。

任一保真门失败时，试运行标记为“转换未通过”，保留两份产物供查看，不允许把该次结果计为可启用依据。

## 错误处理

错误按用户动作分组，不返回底层堆栈：

- 导入错误：缺少 `SKILL.md`、非法路径、文件过大、版本冲突、frontmatter 格式错误。
- 内容运行错误：模型不可用、输入不符合阶段要求、内容 Skill 执行失败。
- 转换错误：固定转换 Skill 不可用、标准结构失败、内容保真失败。
- 发布错误：当前内容哈希没有成功试运行、版本已经发布或存在并发修改。

失败不会自动创建推荐版本、覆盖旧版本或写入业务项目。每一步保留可重试状态。

## 安全边界

- 导入文件夹视为不可信输入。
- 不执行任何导入脚本、二进制文件、命令或安装声明。
- 文本资料在传给模型时继续使用不可信数据边界，不能覆盖系统安全约束。
- 文件预览必须做权限校验和安全响应头，禁止路径穿越和主动内容执行。
- 试运行产生模型费用前继续显示明确确认，但不要求用户理解执行器或渠道配置。

## 兼容与替换范围

项目尚未上线，本次直接把新的文件夹导入流程作为 Skill 创建主路径，不保留旧的复杂新建表单作为普通入口。已有系统种子 Skill 继续作为已注册版本存在，并由相同阶段模板和运行时解析；旧的在线底层编辑器仅保留在技术详情中供管理员排障，后续可单独移除。

项目级 Skill 页面同步采用“导入文件夹、试运行、启用、更新版本”的交互，但只能导入当前项目所有权的内容 Skill。Workflow 编辑器仍只选择内容 Skill；固定转换 Skill 由阶段模板自动插入并冻结，以折叠锁定步骤显示，不进入可选节点列表。

## 验收标准

- 用户能从完整文件夹创建一个阶段内容 Skill，除阶段外无需填写运行字段。
- 文件夹层级和所有文件均进入不可变快照，文本运行资料可预览，未知脚本不会被执行。
- 从现有 Skill 导入新版本时能看到文件差异，重复版本和重复内容有明确结果。
- 用户可粘贴测试输入完成内容 Skill 与固定转换 Skill 的完整试运行，无需 Workflow Run ID。
- 结果页能同时查看原始产出、标准产物、转换差异和中文质量问题。
- 未成功试运行的内容哈希不能设为可用；启用新版本不会自动替换推荐版本。
- Workflow、画布、图片页和 API 对同一精确版本读取到一致文件快照、阶段合同和内容哈希。
- 固定转换 Skill 无法被制作人员替换，且内容保真失败时不能进入下一阶段。
- 历史 Invocation 在推荐版、阶段模板或转换规则更新后仍能按冻结版本复现。
