# 用量报表导出设计

## 背景与目标

管理员需要按历史日期范围查看每位成员的 AI 用量，并将数据交给剪辑环节继续核算素材采用情况。报表需要同时回答：

- 每位成员消耗了多少净积分；
- 使用了哪些生成类型和模型；
- 成功生成了多少条视频、多少秒视频；
- 剪辑后实际采用了多少秒，以及素材采用率是多少；
- 上述指标按日、按周和按月分别如何分布。

平台只负责导出系统内可验证的数据。“实际采用秒数”和“剪辑备注”在下载后的 Excel 中填写，不上传、不回写平台。

## 范围

### 本期包含

- 管理员从数据中心“全部成员”视图导出 XLSX。
- 选择任意历史日期范围，最长一年。
- 可按成员、模型筛选；生成类型保留在报表中用于拆分统计。
- 积分覆盖图片、视频、文本、Agent 和无法识别来源的全部 AI 净消耗。
- 只有成功的视频任务统计生成秒数。
- 同一工作簿提供总览、按日、按周、按月和用量明细。
- 用量明细允许离线填写实际采用秒数和剪辑备注，汇总公式自动更新采用秒数与采用率。

### 本期不包含

- 不把剪辑采用数据保存到服务端。
- 不接入剪辑软件、EDL、XML 或工程文件。
- 不提供定时导出、邮件发送或云端报表历史。
- 不允许普通用户导出全员数据。
- 不以进入剪辑包的完整视频时长冒充实际采用时长。

## 方案选择

采用后端生成 XLSX。后端可以在管理员权限边界内读取完整账本，不受前端表格分页限制，并能统一生成多工作表、公式、校验和下载响应。

不采用前端逐页拉取后生成 XLSX，因为大范围数据会增加请求次数、内存占用和漏页风险。不采用 CSV 压缩包，因为它不能自然承载跨表公式和离线采用时长登记。

实现时使用成熟的 Go Excel 库，不手写 XLSX 压缩包或 XML。

## 统计口径

### 时间

- 所有归组使用 `Asia/Shanghai`。
- 查询范围为左闭右开区间 `[startAt, endAt)`。
- 日统计使用北京时间自然日。
- 周统计固定为周一 00:00 至下周一 00:00。
- 月统计使用北京时间自然月。
- 任务归属时间沿用当前用量账本的首次扣费时间，跨期返还仍回到原任务净积分。

### 积分

- `credit_logs` 是积分权威来源。
- 原始扣除为同一用户、同一稳定用量键下 `ai_consume` 的绝对值之和。
- 已返还是扣费发生后、同一用户和关联 ID 下 `ai_refund` 的绝对值之和。
- 净消耗为 `max(原始扣除 - 已返还, 0)`。
- 图片、视频、文本、Agent 和未知来源均计入积分。
- 无法关联任务的流水仍保留，生成类型和模型显示为“其他”“未知”。

### 视频秒数

- 仅 `kind=video` 且任务状态为 `succeeded` 的任务计入生成秒数。
- 失败、取消、排队和运行中的视频任务生成秒数为 0。
- 视频任务增加结构化秒数字段，在创建任务时按实际提交给上游的有效时长固化。
- 上游成功响应若提供可信的实际成片时长，则完成任务时用该值更新；否则保留有效提交时长。
- 成功但没有可靠秒数的任务显示 0，并在明细中标记“时长缺失”，不得通过积分或当前模型价格反推。
- 完全返还但确实成功的视频可以同时出现净积分 0 和正生成秒数。

### 实际采用秒数

- 导出时为空，由剪辑人员在 Excel 中填写。
- 只有成功视频行可填写。
- 允许范围为 0 至该行生成秒数；空值表示尚未登记，不等同于 0。
- 采用率为已填写实际采用秒数之和除以成功生成秒数之和。
- 平台不读取、不上传该列。

## 数据设计

### AI 任务

在 `model.AITask` 增加结构化视频时长字段，例如：

```go
GeneratedSeconds int `json:"generatedSeconds"`
```

创建视频任务时复用现有请求时长标准化规则写入有效提交时长；成功响应包含可信实际时长时允许更新。非视频任务保持 0。

### 用量记录

在 `model.AIUsageRecord` 和前端对应类型中增加：

```go
GeneratedSeconds int    `json:"generatedSeconds"`
DurationIssue    string `json:"durationIssue"`
```

`DurationIssue` 当前只需要空字符串或 `missing_duration`，用于在导出明细中解释成功视频为什么没有秒数。

### 导出查询

新增独立导出查询，不复用分页上限表达导出语义：

```go
type AIUsageExportQuery struct {
    User    string
    Model   string
    StartAt string
    EndAt   string
}
```

service 负责日期校验、最长一年限制、加载全部命中记录、聚合日周月数据和构建工作簿输入。repository 只负责数据库查询；handler 只解析参数、调用 service 并写下载响应。

## 接口设计

```http
GET /api/admin/ai-usage-export?startAt=2026-08-01T00:00:00%2B08:00&endAt=2026-09-01T00:00:00%2B08:00&user=&model=
```

- 路由放在现有管理员鉴权组内。
- `startAt`、`endAt` 必填，格式为 RFC3339。
- 结束时间必须晚于开始时间，范围不得超过一年。
- `user` 匹配用户名、昵称或稳定用户 ID；`model` 沿用当前模型筛选语义。
- 有数据时返回 XLSX 文件流。
- 文件名为 `用量报表_YYYY-MM-DD_YYYY-MM-DD.xlsx`。
- 无匹配记录时返回现有 `{ code, data, msg }` 失败响应，前端提示“当前范围暂无可导出的用量记录”。
- 普通用户调用时由现有管理员中间件拒绝。

## 工作簿设计

工作簿包含五个工作表。

### 总览

每位成员一行：

| 成员 | 用户 ID | 净消耗积分 | 成功视频数 | 生成秒数 | 实际采用秒数 | 素材采用率 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |

实际采用秒数和采用率使用引用“用量明细”的公式。总览顶部记录导出时间、查询起止时间和筛选条件。

### 按日统计

每个“日期 + 成员 + 生成类型 + 模型”一行，包含净消耗积分、成功视频数、生成秒数、实际采用秒数和采用率。

### 按周统计

每个“周起止日期 + 成员 + 生成类型 + 模型”一行。周一为开始日，周日为结束日。

### 按月统计

每个“月份 + 成员 + 生成类型 + 模型”一行，月份显示为 `YYYY-MM`。

### 用量明细

列顺序如下：

1. 时间；
2. 成员；
3. 用户 ID；
4. 生成类型；
5. 模型；
6. 状态；
7. 原始扣除；
8. 已返还；
9. 净消耗；
10. 成功生成秒数；
11. 实际采用秒数；
12. 剪辑备注；
13. 数据质量提示；
14. 关联任务 ID。

工作表启用保护并锁定固定系统数据，只解锁成功视频行的第 11、12 列；可编辑单元格使用明显但低干扰的样式。实际采用秒数添加数值校验，范围为 0 至本行生成秒数。非成功视频行的采用秒数单元格保持锁定。

日、周、月和总览中的离线采用指标使用公式引用明细行；修改采用秒数后由 Excel 自动重算。空白采用值不显示为“已采用 0 秒”，但计算总和时按 0 处理。

## 前端交互

- 仅管理员或超级管理员在数据中心“全部成员”视图看到“导出用量报表”。
- 按钮放在页面标题区的低频操作位置，不挤占消费明细筛选栏。
- 点击后打开导出弹窗。
- 日期范围默认本月，必填，最长一年。
- 成员和模型默认带入数据中心当前筛选，允许在弹窗中调整。
- 确认后直接请求下载接口；请求期间按钮 loading 并防止重复提交。
- 后端失败时使用现有消息机制显示可读错误，不产生损坏或空白文件。

## 安全与数据质量

- 全员导出只允许管理员鉴权组访问。
- 用户名、昵称、模型名、备注性系统字段均按纯文本写入，禁止把以 `=`, `+`, `-`, `@` 开头的值解释为公式。
- 只有由系统生成的固定公式可以作为公式写入。
- 工作簿不包含 API Key、完整请求体、提示词、响应体、错误详情、上游任务 ID 或前端追踪信息。
- 关联任务 ID 只使用平台内部稳定 ID，用于剪辑与运营定位。
- 未知来源和缺失时长必须显式标记，不静默丢弃或猜测。

## 错误处理

- 参数缺失、日期格式错误、结束时间不晚于开始时间或超过一年：返回明确业务错误。
- 无匹配记录：返回明确业务错误，不下载空文件。
- 数据库查询失败或 XLSX 构建失败：记录服务端错误并返回统一失败响应。
- 下载已经开始后发生写入错误：记录日志并结束连接，不再尝试写 JSON 响应。
- 单条记录缺少任务关联或秒数：保留该行并标记数据质量问题，不中止整份报表。

## 验收标准

1. 管理员可选择不超过一年的历史范围导出 XLSX，普通用户无法调用接口。
2. 文件包含“总览、按日统计、按周统计、按月统计、用量明细”五个工作表。
3. 所有工作表中的净积分汇总均与命中范围内账本净消耗一致。
4. 失败、取消、排队和运行中的视频不计生成秒数；成功视频按结构化秒数字段统计。
5. 图片、文本、Agent 和未知来源积分进入汇总，但生成秒数为 0。
6. 北京时间跨日、周一边界、月末边界和跨年周均归组正确。
7. 成员和模型筛选同时作用于明细及全部汇总工作表。
8. 在用量明细填写实际采用秒数后，总览、日、周、月中的采用秒数和采用率自动更新。
9. 实际采用秒数不能小于 0 或大于该行生成秒数，非成功视频行不可填写。
10. 缺少任务关联或成功视频时长的记录仍保留，并显示明确的数据质量提示。
11. 报表不包含密钥、提示词、完整请求/响应、上游任务 ID 或错误详情。
12. 用户名或模型名以公式控制字符开头时，Excel 中仍作为普通文本显示。
