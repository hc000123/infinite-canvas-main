# 管理员算力分配与超级管理员免余额设计

## 目标

补齐管理员账号的算力管理规则：只有超级管理员不受余额限制；普通管理员继续持有并消耗真实余额，并通过余额转移的方式向普通用户分配或收回算力。超级管理员在“管理员管理”中可以为普通管理员或普通用户直接设置余额。

## 角色与权限

| 操作 | 超级管理员 | 普通管理员 | 普通用户 |
| --- | --- | --- | --- |
| 调用 AI | 不校验、不扣减余额 | 校验并扣减余额 | 校验并扣减余额 |
| 调整超级管理员余额 | 禁止 | 禁止 | 禁止 |
| 调整普通管理员余额 | 允许，不扣减操作者余额 | 禁止，包括自己 | 禁止 |
| 调整普通用户余额 | 允许，不扣减操作者余额 | 允许，以自身余额双向转移 | 禁止 |

普通管理员不能直接调整自己、其他普通管理员或超级管理员的余额。超级管理员虽然余额不限，但 AI 任务、Agent Run、模型、本次折算算力、操作与 IP 仍正常记录。

## 后端设计

### 超级管理员免余额限制

现有 AI 代理和 Agent Run 继续计算模型折算算力并保存任务数据。算力服务读取调用账号角色：

- 超级管理员直接通过余额门禁，不修改 `users.credits`；
- 普通管理员和普通用户继续执行原有预扣、余额不足阻断和失败返还；
- 超级管理员不生成会伪造余额变化的消费或返还流水；用量由 AI 任务、Agent Run 和操作审计记录提供；
- Agent Run 的预留与退款状态需要识别超级管理员免扣，保证重试不会重复处理，也不会向超级管理员余额错误返还算力。

### 普通管理员与用户的双向转移

保留前端按“目标余额”提交的交互。后端根据目标用户当前余额计算差额：

- 差额大于零：从普通管理员余额扣除差额，并增加普通用户余额；
- 差额小于零：从普通用户余额扣除绝对差额，并返还普通管理员余额；
- 差额为零：直接返回当前用户，不生成流水；
- 增加用户余额时，普通管理员余额不足则整笔失败；
- 目标余额不得小于零。

双方余额更新与两条流水必须在同一个数据库事务内完成，并用共同的关联 ID 串联。管理员侧与用户侧流水均记录操作者、对方账号、转移方向和变化后余额。普通管理员可以从其有权管理的任意普通用户收回余额，这是已确认的管理规则。

### 超级管理员直接调额

超级管理员调整普通管理员或普通用户时，直接设置目标余额，不改变超级管理员余额。目标余额变化沿用后台调整流水，并记录超级管理员操作者。超级管理员账号本身不能成为调额目标。

### 服务边界

HTTP handler 只解析目标余额并调用 service。权限判断、角色判断、差额计算、事务、关联 ID、余额不足错误和流水内容均放在 service/repository；repository 负责原子数据库更新。接口继续使用现有 `{ code, data, msg }` 响应格式。

现有 `POST /api/admin/users/:id/credits` 可以继续复用：service 根据操作者与目标角色选择“超级管理员直接调额”或“普通管理员双向转移”，无需新增重复接口。

## 前端设计

“管理员管理”列表新增“算力余额”列：

- 超级管理员显示金色“余额不限”标签；
- 普通管理员显示实际数字余额；
- 普通管理员行提供“调整算力”操作；
- 超级管理员行不显示可操作的调额入口；
- 调额弹窗展示当前余额、目标余额与本次增减差额，提交前二次确认；
- 成功后刷新管理员列表和当前登录用户信息，保证超级管理员为普通管理员调额后页面立即同步。

普通管理员继续在“用户管理”调整普通用户余额，页面文案改为“额度转移”，明确增加用户余额会扣除管理员自身余额、减少用户余额会返还管理员余额，并在提交成功后同步刷新当前管理员余额。

## 错误处理

- 普通管理员余额不足：返回“管理员算力点不足”；不更新任何余额或流水。
- 目标账号不存在、角色不允许或尝试调整超级管理员：返回明确权限错误。
- 目标余额为负数：拒绝请求。
- 任一余额更新或流水写入失败：回滚整个事务。
- 并发分配通过条件更新或事务锁保证管理员余额不会被扣成负数。

## 测试与验收

后端测试覆盖：

- 零余额超级管理员仍能通过 AI 余额门禁且余额不变；
- 普通管理员和普通用户仍正常扣费、余额不足仍被阻断；
- 超级管理员可调整普通管理员和普通用户，但不能调整超级管理员；
- 普通管理员不能调整自己或其他管理员；
- 普通管理员向用户增加余额时双方等额变化，余额不足时原子失败；
- 普通管理员降低用户余额时额度等额返还；
- 双方流水具有相同关联 ID，余额和方向正确；
- Agent Run 在超级管理员免扣场景下重试与失败不会改变余额。

前端测试覆盖：

- 超级管理员显示“余额不限”且无调额动作；
- 普通管理员显示数值余额及调额动作；
- 调额弹窗展示差额与正确确认文案；
- 普通管理员给用户调额后刷新自身余额。

人工验收时分别使用超级管理员和普通管理员账号验证管理员管理、用户管理、AI 调用、余额不足提示和双方流水。

## 非目标

- 不改变模型费用配置或折算方式。
- 不允许普通管理员创建算力或管理其他管理员。
- 不把超级管理员余额保存成特殊负数或极大值。
- 不修改 IP 审批与管理员免 IP 限制规则。
