# 上线门禁与统一模型路由设计

## 目标

正式部署不再包含可触发 Codex CLI 的用户入口或服务端回退路径；后台渠道配置成为模型协议与能力的唯一来源；画布节点只选择公开模型，不再自行保存或猜测协议；上线前用前后端自动化检查和 Docker 真实运行验证这条链路。

## 当前问题

模型信息目前分散在六层：私有渠道、公开模型列表、浏览器 AI 配置、项目预设、节点 `metadata` 和生成请求。视频又同时使用 `videoModel`、`seedanceModel`、`seedanceEndpointId` 和 `provider`。节点内历史 `provider` 可以覆盖后台新的协议映射，模型名称启发式判断也可能覆盖明确能力，导致同一个模型在选择器、扣费和实际调用阶段走不同路线。

Codex CLI 虽然默认关闭，但前端仍保留开关，Next 路由仍把未识别的执行模式归一为 `local-runner`。生产部署仅依赖环境变量阻止回退，默认值不安全。

## 方案

### 1. 模型配置边界

- 私有渠道维护协议、地址、密钥、模型、能力、火山 EP 映射和启用状态。
- 公开配置只维护开放模型、图片 / 视频 / 文本默认模型、文本接口类型和算力点。
- 后端继续从私有渠道编译公开的 `modelProtocols`、`modelCapabilities` 和 `modelSources`，并在保存设置时拒绝同一公开模型跨不同协议的冲突配置。
- 前端增加单一模型目录解析器，把公开模型、能力、协议、来源和文本接口类型合并成按模型 ID 查询的目录。所有选择器、默认值校验和节点生成都使用该解析器。

### 2. 模型选择优先级

每次生成只按以下顺序解析一次：

1. 节点显式模型；
2. 项目对应类型的默认模型；
3. 系统对应类型的默认模型。

候选模型必须仍在公开模型目录中并具有目标能力，否则跳过。最终找不到模型时直接返回“未配置可用的图片 / 视频 / 文本模型”，不再猜测或跨类型兜底。

### 3. 节点模型与视频协议

- 新节点和修改后的节点只以 `metadata.model` 表示模型选择。
- `metadata.provider` 仅作为旧画布展示字段保留，不参与实际协议决策；实际协议由公开模型目录中的 `modelProtocols` 解析。
- 项目预设中的 `defaultVideoProvider` 不再覆盖模型路由；模型协议随 `defaultVideoModel` 解析。
- 火山 Endpoint 只存在于后台私有渠道，前台节点始终使用公开模型名。
- 模型选择器只显示具有当前生成能力的公开模型，不再把未知模型名称混入图片列表，也不允许生产用户输入自定义模型 ID。

### 4. Codex CLI 上线门禁

- 移除用户配置弹窗中的“本地 Codex CLI”开关。
- 浏览器持久化状态统一迁移为 `cloud-worker`。
- `/api/original-workflow` 和 `/api/original-workflow/script-optimizer` 默认且只接受 `cloud-worker`；收到 `local-runner` 时返回“生产环境已禁用本地 Codex CLI”。
- 原视频工作流与剧本优化的执行按钮在云端 Worker 未接入时禁用，统一显示“云端执行器尚未启用”。只读页面和已有项目数据保持可访问。
- Docker 镜像不安装 Codex CLI；部署环境显式设置云端模式作为双重门禁。

### 5. 验收

- Go：设置归一化、跨协议冲突、模型选择与路由测试。
- 前端：模型目录、能力过滤、节点优先级、视频协议与 Codex 路由门禁测试。
- 本地集成：启动 Go 与 Next，调用健康、公开设置、登录、模型任务相关接口，并检查禁用入口返回。
- Docker：构建生产镜像，使用全新临时数据目录启动，等待健康检查；验证页面、API、持久化、公开素材路径和容器内不存在 `codex` 可执行文件；验证 `local-runner` 请求被拒绝。

## 非目标

- 本次不实现云端视频工作流 Worker。
- 不重做数据库为独立模型表。
- 不改模型供应商的实际计费或任务执行协议。
- 不在节点中保存渠道密钥、Endpoint 或渠道 ID。

## 上线判定

只有以下条件同时成立才允许进入发版：生产 UI 无 Codex CLI 开关；服务端无法触发本地 Codex；模型协议由后台目录唯一决定；节点无跨能力模型错配；前后端测试通过；Docker 镜像构建、健康检查和关键接口验收通过；相关结果记录在 `docs/pending-test.md`。
