# 仅保留资产生图入口设计

## 背景

当前系统同时存在独立 `/image` 生图工作台和 `/assets/[subjectId]` 资产生图工作台。两者都包含提示词、模型参数、参考图和生成结果，造成入口重复、资产归属不清晰。

## 目标

- 取消顶部“生图”入口和独立生图工作台。
- 资产图片只在 `/assets/[subjectId]` 中生成、上传、选择和归档。
- Agent 资产生产卡片直接进入已绑定的资产详情，不再携带大段提示词到 `/image` URL。
- 历史 `/image` 链接不展示旧工作台，自动转到对应资产或当前项目资产库。
- `/storyboard` 和顶部“分镜”入口保持不变。

## 方案

### 导航与路由

`navigationTools` 移除 `image`。`/image` 保留为兼容转发页，不包含生成表单、历史记录或生成请求。它根据 `libraryAssetId` 查找本地资产绑定：

1. 找到 `subjectId` 时转到 `/assets/[subjectId]`；
2. 找不到时转到带 `projectId` 的项目资产库；
3. 无项目上下文时转到 `/assets`。

### 资产入口

Agent 资产卡的“图片工作台”改为“资产生图”，直接链接其 `assetBinding.subjectId`。资产库卡片的“生成”继续进入同一资产详情。已有图片的“继续修改”也回到该图片所绑定的资产详情，不再打开 `/image`。

### 数据与生成安全

不修改资产主体、形态、候选图和正式版本的存储结构。只有资产详情内用户明确点击“生成待选结果”时才调用图片模型；路由转发、页面打开和旧链接修复不触发付费生成。

## 测试与验收

- 导航测试确认无“生图”且仍有“分镜”。
- 路由测试确认 `/image` 不再渲染生图工作台，并能生成资产详情/项目资产库的兼容去向。
- 工作流资产链接测试确认 URL 直达 `/assets/[subjectId]`，不包含提示词。
- 资产生图工作台原有测试继续通过。
- 运行态验收确认顶部无“生图”，旧 `/image?...` 会转到资产页，Agent “资产生图”会打开对应资产工作台。
