# 工具稳定性与热路径优化设计

## 目标

修复 Skill 删除唯一草稿后无法继续创建版本的问题，降低 Skill 列表读取成本，统一分集主画布判定，并减少画布根页面不必要的全量状态订阅。

## 设计

- 后台与项目 Skill 管理页允许无可见版本时创建草稿：有历史版本时复制最近版本包；完全没有版本时使用默认包和 `1.0.0`；停用版本保持只读。
- Skill 种子只在服务启动阶段确保；列表接口批量读取版本、评测和审计，再按 Skill 分组，避免逐条查询。
- 分集主画布由统一工具函数解析：显式 `main` 优先；没有显式主画布时只选择最早的未标记子画布作为候选，并在写入时提升为 `main`。
- 画布根页面只订阅当前画布和它的直接子画布，不再订阅全部画布项目数组；节点、素材和队列的深层重构不在本轮范围内。

## 错误与边界

- 新草稿创建时若读取历史版本失败，显示现有 API 错误，不创建空壳版本。
- 同一分集存在多个旧的无角色画布时，只允许确定的候选主画布创建子画布，其他画布保持普通画布行为。
- 后端批量查询保持原排序、每版本最多 50 条评测、每 Skill 最多 100 条审计的现有语义；SQLite/PostgreSQL 在数据库内截取，MySQL 使用无窗口函数的兼容批量路径并在服务层截取。普通用户列表不返回管理端评测、审计和绑定数据。

## 验收

- 删除唯一草稿后仍能创建 `1.0.0` 草稿。
- 仅有停用版本时，无需先显示并选中停用版本也能基于最新历史创建草稿。
- Skill 列表不在请求路径重复执行种子初始化，聚合查询数量不随 Skill/版本数量线性增加。
- 同一分集只有一个画布可作为主画布创建子画布。
- 其他画布项目变化不会仅因全部 `projects` 数组引用变化而刷新当前画布页面。
