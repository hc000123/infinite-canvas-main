# Seedance 2.0 动态剧本转写 Skill 3.2 设计

## 目标

将用户提供的“短剧剧本转 AI 动态生成剧本”规则发布为系统剧本 Skill 的 `3.2.0` 版本。输入保持 `source_text`，输出保持 `production_script.productionScript`，使现有工作流、画布和项目页无需改变 Artifact 契约。

## 边界

- Agent 仍只负责调度、权限和版本冻结，不承载剧本业务规则。
- `3.1.0` 作为历史轻整理版本保留，`3.2.0` 成为系统推荐版本。
- 不新增剧情、人物、台词和场景；只补足空间、调度、节拍、可见表演和转场结果。
- 输出为 JSON 对象，其 `productionScript` 字符串内严格使用用户指定的“场景基础信息 / 情节节拍 / 正文转写 / AI生成重点”结构。

## Skill 结构

- `SKILL.md`：角色、目标、执行顺序和不可变边界。
- `rules/domain-rules.md`：完整收录空间、人物调度、节拍、表演、台词、Seedance 2.0 和暧昧戏规则。
- `templates/output-template.md`：固定生产剧本输出骨架。
- `examples/good-output.json`：同时通过 Skill Schema、Core Schema 和新业务质量门的样例。

## 版本与默认绑定

剧本阶段单独升级到 `3.2.0`，其他阶段继续使用 `3.1.0`。系统剧本 Agent 发布一个新推荐版本，默认引用剧本 Skill `3.2.0`；项目制作人员仍可手动选择已授权的旧版本。

## 业务质量门

新版 Skill 增加专属 validator，检查：

1. 必须存在场景基础信息、五个情节节拍、正文转写和 AI 生成重点。
2. 必须包含地点、时间、人物、空间关系和整体氛围。
3. 输出不能仅为原稿的排版修正，需有足够的增量可执行信息。
4. 原稿中不需切分的短台词必须保留。

该 validator 只在 Skill `3.2.0` 的冻结质量门中执行，不会追溯影响旧 Skill 产物。

## 验收

- 种子数据同时包含剧本 `3.1.0` 和 `3.2.0`，推荐版本为 `3.2.0`。
- 系统剧本 Agent 的推荐包冻结 `3.2.0`。
- 只改标点的产物无法通过新质量门，符合完整格式的样例可以通过。
- 现有其他 Skill 版本、Artifact 契约和手动选择机制保持不变。
