# 模型渠道快捷编辑与来源分组设计

## 背景

后台“系统设置”中的模型渠道同时承担连接信息、模型清单和公开范围配置。当前编辑已有渠道时仍从“选择渠道类型”开始，且只能逐步前进到最后一步保存；公开配置的“系统可用模型”下拉只显示模型名称，无法判断模型来自哪个渠道。

## 目标

- 新建渠道继续使用现有四步向导，保留逐步校验。
- 编辑已有渠道时减少无效点击，可直接进入和切换需要调整的配置区。
- 系统可用模型仍按模型名称保存，但在选择时清楚显示渠道来源。
- 不改变现有模型路由、渠道权重、密钥保留和公开配置数据结构。

## 交互设计

### 编辑已有渠道

- 打开已有渠道时默认进入第 2 步“连接信息”；新建渠道仍从第 1 步“选择渠道类型”开始。
- 编辑模式的四个步骤标题均可点击，允许直接跳转到任意配置区；新建模式继续按顺序点击“下一步”。
- 编辑模式始终显示“保存渠道”，不要求先进入第 4 步。
- “上一步 / 下一步”继续保留，用于习惯顺序浏览的用户。
- 保存时统一校验全部字段；如果校验失败，自动切换到第一个错误字段所在步骤，并保留 Ant Design 原有字段错误提示。
- 已保存 API Key 继续允许留空，留空代表不修改；不会因快捷保存被清空。
- “配置模型”的候选仅使用当前渠道已有模型与本次发现结果，不把其他渠道的模型作为候选；用户仍可手动输入模型名称。

### 模型来源分组

- “系统可用模型”仍以模型名作为唯一选中值，不把渠道 ID 写入公开配置，也不改变运行时路由语义。
- 仅由一个已启用渠道提供的模型，归入以该渠道名称命名的分组。
- 同名模型由多个已启用渠道提供时，只显示一个选项，归入“多渠道共享”分组，并在选项中列出全部来源渠道。
- 分组和来源展示基于当前私有渠道配置实时计算；禁用渠道不作为可选模型来源。
- 搜索同时匹配模型名称和渠道名称，方便按供应来源查找。
- 已选标签保持简洁，只显示模型名称，避免多选框被来源信息挤满。

## 数据与组件边界

- 在系统设置页面增加一个纯计算函数，将已启用渠道转换为 Ant Design 分组选项；输入为渠道列表，输出为分组及模型来源信息。
- `availableModels`、默认模型、模型费用和文本接口类型继续使用现有字符串模型名，不修改后端接口或数据库。
- 渠道向导只调整编辑模式的初始步骤、步骤跳转和保存入口；现有初始化、模型发现、发布范围计算与保存协调器保持不变。

## 错误处理

- 直接保存时若连接信息、模型配置或公开范围存在错误，定位到对应步骤，不提交设置。
- 若一个模型只存在于禁用渠道，则不出现在新的可选项中；已经保存但当前无有效来源的模型仍按现有清理和警告规则处理。
- 多渠道同名模型只代表可由多个渠道路由，不暗示用户选中了其中某个固定渠道。

## 验收

- 新建渠道仍从“选择渠道类型”开始，必须按现有顺序完成配置。
- 编辑已有渠道默认打开“连接信息”，可点击任意步骤，并可在当前步骤直接保存。
- 任一步存在无效字段时保存不会提交，并跳转到对应错误步骤。
- 已保存 API Key 留空保存后仍可继续使用。
- 系统可用模型下拉按渠道名称分组；同名多来源模型只出现一次，并显示在“多渠道共享”分组及全部渠道来源。
- 搜索模型名或渠道名均能找到对应模型，保存后的公开配置仍只包含模型名称。

## 非目标

- 不新增“固定模型到指定渠道”的绑定能力。
- 不调整渠道权重、故障转移或运行时选路逻辑。
- 不重构系统设置页面的其他配置区域。
