# 工作区导航与页面流转设计说明

## 状态

- 已确认采用方案 A「全局工作台 + 项目上下文 + 当前任务」。
- 已确认左侧导航采用 164px 展开态与 52px 收起态。
- 本说明细化并覆盖《2026 AI 原生制作工作台设计说明》中与全局导航、页面入口、返回路径有关的规则。
- 本轮只调整展示、导航入口和返回层级，不修改业务路由、Workflow、API、store、持久化或生成逻辑。

## 目标

每个页面只回答五个问题：

1. 用户从哪里进入？
2. 当前页面只负责什么？
3. 唯一主操作是什么？
4. 完成后去哪里？
5. 返回到哪里？

成功标准：

- 日常制作从“工作台 → 项目 → 制作本集 → Workflow”自然推进。
- 跨项目异常和待审核事项从“生产总控 → 待处理任务 → Workflow”直达。
- 项目详情不再出现与“制作本集”含义重复的“项目总控”入口。
- 深层页面只有一个明确父级返回，不同时展示多个同级返回动作。
- 画布、素材等全局工具保留自由入口；从项目进入时自动携带项目上下文。
- 兼容路由继续有效，但不再作为用户可见主入口。

## 方案选择

### 已采用：全局工作台 + 项目上下文 + 当前任务

保留少量全局工具入口，同时让项目、分集、Workflow、Canvas 和素材页继承来源上下文。

采用原因：

- 能复用现有路由、`workspaceProjectId`、`contextualToolHref` 和 `returnTo`。
- 同时支持项目闭环与自由画布，不强迫所有临时创作先建立项目。
- 主要改动集中在导航呈现和链接装配，不触碰现有生产状态机。

### 未采用：完全项目优先

所有画布、素材和分镜必须从项目进入。闭环最强，但会增加自由创作与跨项目整理的步骤，且需要更大范围改变现有使用习惯。

### 未采用：按创作阶段组织

一级入口变为规划、制作、管理、资源。概念更新，但学习和迁移成本最高，容易在当前阶段形成新的命名负担。

## 全局信息架构

桌面端一级导航固定为：

1. 工作台
2. 生产总控
3. 画布
4. 素材
5. 资源库

规则：

- “工作台”对应项目中心，是登录后的默认入口。
- “生产总控”对应 `/agent`，只负责跨项目运行、待审核、失败和阻塞事项。
- “画布”对应全局画布列表；从项目进入画布时仍保留项目筛选。
- “素材”对应全局素材库；从项目、Workflow 或 Canvas 进入时携带 `projectId` 与 `returnTo`。
- “资源库”承载提示词和缓存等低频能力，不让它们长期占用两个一级入口。
- “分镜制作台”不再作为全局一级入口，只在项目或分集上下文内出现。
- 旧 `/storyboard`、`/image`、`/video`、`/original-workflow`、workbench 和项目内兼容路由继续可访问，但不再新增显式主入口。

## 左侧应用栏

### 展开态

- 宽度为 164px。
- 显示品牌图标、品牌名称、导航图标和中文名称。
- 适合初次使用、全局管理和需要频繁切换页面的场景。
- 当前入口使用单一蓝紫强调色和低对比背景，不使用荧光黄。

### 收起态

- 宽度为 52px，不覆盖主内容。
- 只显示品牌图标、导航图标和底部必要图标。
- 导航图标悬停或键盘聚焦时显示中文 Tooltip。
- 版本文字隐藏，账号保留头像入口。
- 收起按钮始终可见，不依赖 hover 才能找到。

### 状态规则

- 用户手动切换后，在浏览器保存上次状态。
- 跨工作台、项目、分镜、素材和资源页面保持同一状态。
- 页面跳转不自动展开侧栏，避免打断创作。
- 小于 900px 时直接使用 52px 图标栏；不在本轮新增抽屉或底部导航。
- `/canvas/[id]` 保持现有沉浸式画布壳层，不额外叠加全局侧栏。

### 底部操作

- 展开态将配置、主题、版本和账号横向排列为一行。
- 收起态在 52px 图标轨道内纵向保留配置、主题和账号，隐藏版本文字；“横向排列”只约束展开态。
- 账号下拉继续承载数据中心、管理后台、快捷键和退出登录等低频动作。
- 底部图标使用现有行为，不新增设置入口或复制动作。

## 页面职责与流转矩阵

| 页面 | 主要入口 | 页面只负责 | 唯一主操作 | 正向出口 | 返回路径 |
| --- | --- | --- | --- | --- | --- |
| 工作台 `/projects` | 登录后默认、品牌入口、全局导航 | 决定今天推进哪个项目 | 继续最近项目；无项目时新建项目 | 项目详情 | 无上级返回 |
| 生产总控 `/agent` | 全局导航 | 跨项目查看运行、待审核、失败和阻塞 | 打开具体待处理任务 | 项目详情或分集 Workflow | 回到总控列表 |
| 项目详情 `/projects/[id]` | 工作台或总控任务 | 查看项目进度、选择分集、管理项目内资源 | 继续当前分集；无分集时新建分集 | Workflow、项目画布或项目素材 | 工作台 |
| 分集 Workflow | 项目详情“制作本集”或总控任务 | 完成当前分集当前阶段 | 当前阶段的唯一动作 | 下一阶段或 Canvas | 项目详情；总控来源则回总控 |
| 画布列表 `/canvas` | 全局画布入口或项目详情 | 查看全部或指定项目画布 | 打开画布；选中项目后可新建 | Canvas 详情 | 工作台或来源页 |
| Canvas `/canvas/[id]` | 画布列表、项目详情或 Workflow | 创作当前画布 | 保存或当前选中对象动作 | 当前画布产物 | 返回本集制作、返回项目、返回画布列表三者之一 |
| 素材 `/assets` | 全局导航、项目、Workflow 或 Canvas | 查找并选择素材 | 打开或选择素材 | 素材详情或原工作面 | 只返回实际来源 |
| 素材详情 `/assets/[subjectId]` | 素材列表 | 查看素材版本和可用动作 | 使用当前素材 | 原工作面 | `returnTo` 指向的来源 |
| 资源库 | 全局导航 | 进入提示词或缓存管理 | 打开一个资源工具 | 提示词或缓存页面 | 资源库 |

## 两条核心任务路径

### 日常制作

```text
工作台 → 项目详情 → 制作本集 → Workflow → Canvas（按需）
   ↑          ↑            └──────── 返回本集制作
   └──────────┴──────────────────── 返回项目 / 工作台
```

规则：普通创作不经过生产总控。项目详情只保留项目进度、分集和项目内资源，不再放“进入项目总控”。

### 异常与审核

```text
生产总控 → 待处理任务 → Workflow → 完成处理 → 返回生产总控
```

规则：生产总控只提供跨项目注意力入口，不承担项目编辑、剧本编辑或画布创建。

## 页面级交互规则

### 工作台

- 项目列表承担“选项目”，不直接跳过项目详情进入 Workflow 或 Canvas。
- 最近项目提供“继续项目”主操作。
- 新建项目只在无项目或明确创建意图时提升为主操作。

### 项目详情

- 顶部不再出现“进入生产总控”或“项目总控”。
- 分集行只保留一个“制作本集”主入口。
- 项目画布和项目素材是次级工具入口，视觉权重低于“制作本集”。
- 重复出现在顶部和分集区域的同义动作只保留更靠近对象的一处。

### Workflow

- Header 只保留一个来源感知的返回按钮：项目来源显示“返回项目”，生产总控来源显示“返回生产总控”。
- 如果 URL 没有来源信息，默认返回项目详情，不根据浏览器历史猜测。
- 去 Canvas 时传入明确来源；Canvas 不自行猜测返回目标。

### Canvas

- 顶部只显示一个返回按钮，并根据来源显示“返回本集制作”“返回项目”或“返回画布列表”。
- Canvas 菜单不得复制相同的返回动作。
- 全局画布列表负责选择画布；Canvas 详情不再增加第二套画布导航。

### 素材

- 全局进入时显示全部素材。
- 项目或制作页进入时自动过滤项目，并携带 `returnTo`。
- 详情页不同时显示“返回素材库”和“返回项目”两个同级按钮。

### 资源库

- 资源库是提示词和缓存的入口聚合，不合并它们的业务页面。
- 提示词是内容资源；缓存是系统维护，两者在资源库内分组呈现。
- 本轮不修改两个页面内部业务能力。

## 数据与状态边界

允许新增：

- 侧栏展开/收起的轻量本地配置。
- 根据当前 pathname、query 和已有来源参数计算的展示文案。
- 资源库入口的纯展示聚合。

必须复用：

- `navigationTools`
- `workspaceProjectId()`
- `contextualToolHref()`
- 现有素材 `returnTo` / `returnLabel`
- 现有 Canvas `returnTarget` / `returnToParent()`
- `videoWorkflowHref()` 与 `ensureEpisodeMainCanvas()`

不得修改：

- 后端 API 与响应结构。
- Zustand 业务 store、localforage 业务数据与节点结构。
- Workflow 状态机和阶段推进逻辑。
- 项目、分集、画布和素材的绑定关系。
- 节点创建、生成、重试、超分、插帧、字幕擦除及费用计算逻辑。

## 可访问性与反馈

- 侧栏展开/收起按钮提供明确 `aria-label` 和 `aria-expanded`。
- 收起态导航保留 `aria-label`、`title` 或 Tooltip。
- 当前页继续使用 `aria-current="page"`。
- hover 反馈控制在 100–150ms；点击收起即时响应，不使用延迟展开。
- 键盘焦点可见，不能只通过颜色区分当前入口。
- 中文导航名称完整显示，不用只有设计团队能理解的缩写。

## 验收场景

1. 用户展开侧栏后进入项目、素材和资源页，展开状态保持不变。
2. 用户收起侧栏后主内容即时释放 112px，刷新后仍保持收起。
3. 收起态每个图标都能通过悬停和键盘聚焦识别中文名称。
4. 底部配置、主题、版本、账号在展开态只占一行；收起态纵向排列必要图标且不显示版本文字。
5. 工作台进入项目详情后，页面上不存在与“制作本集”重复的“项目总控”按钮。
6. 分集“制作本集”进入现有 Workflow，业务数据与阶段状态不变。
7. 从项目、Workflow 和画布进入素材后，返回按钮只回实际来源。
8. 从不同入口进入 Canvas 时，顶部只出现一个符合来源的返回动作。
9. 生产总控中的具体任务能直达对应项目或 Workflow；普通项目制作不需要经过总控。
10. 旧兼容 URL 仍可访问，但全局导航不再展示重复入口。

## 不在本轮范围

- 重写页面路由或合并业务页面。
- 重做 Workflow、画布节点、生成任务或费用系统。
- 新增云同步、跨设备侧栏状态或服务端用户偏好。
- 重构提示词与缓存页面内部结构。
- 小屏抽屉导航、移动端底部导航和触控手势。
- 视觉系统的第二轮品牌动效或营销化装饰。
