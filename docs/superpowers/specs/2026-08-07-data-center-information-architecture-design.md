# 数据中心信息架构优化设计

## 目标

把现有偏管理员运维的“AI 使用”能力拆成面向业务用户的“数据中心”和面向管理员的“任务运维”，让用户能从统一入口查看余额、周期消耗和自己的消费明细，同时保留现有任务追踪、失败返还和流水维护能力。

本期只优化入口、权限、页面层级和已有数据的表达，不增加项目、剧集、团队或工作室维度，不修改当前项目与剧集主要保存在浏览器本地的产品边界。

## 设计原则

- 入口明确：所有登录用户都能从账户菜单进入数据中心；画布上的算力余额可直接点击进入。
- 权限明确：普通用户只能读取自己的余额、统计和明细；管理员可在“我的 / 全部用户”之间切换。
- 默认业务化：数据中心默认展示业务用户能理解的信息，不暴露上游任务 ID、渠道和手动返还等运维操作。
- 运维隔离：任务刷新、失败返还、流水新增、编辑和删除继续只存在于管理后台。
- 复用现有口径：实际消耗继续按照消费减返还后的净消耗计算，管理员调整不计入使用统计。
- 最小改动：复用现有 Ant Design、主题 token、用户展示方法、任务与流水接口结构，不引入新的状态管理或大型抽象。

## 方案

采用“统一数据中心 + 独立任务运维”。

新增 `/data-center` 作为所有登录用户的统一入口。普通用户进入后只看到自己的数据；管理员进入后默认看到全部用户视图，并可切换到自己的数据。现有 `/admin/ai-tasks` 保留，但后台菜单和页面标题改为“任务运维”，承载原有管理员任务明细和算力流水维护能力。

不采用普通用户与管理员各一套页面，因为会造成统计 UI、查询状态和空状态重复。不采用只改名现有后台页面，因为无法解决普通用户无入口、业务统计与技术运维混杂的问题。

## 页面与导航

### 数据中心入口

- 账户菜单为所有登录用户增加“数据中心”，指向 `/data-center`。
- 画布顶部算力余额由静态展示改为链接，点击进入 `/data-center`。
- 管理员账户菜单继续保留“管理后台”，两者语义独立。
- 非画布页面不强制额外常驻余额，避免扩大本期顶部导航改造范围。

### 数据中心页面

页面由三个自上而下的区域组成。

#### 1. 使用概览

- 显示当前账户算力余额。
- 显示今日、本周、本月实际净消耗、消费次数和使用人数。
- 普通用户的“使用人数”固定为自身是否产生实际消耗；管理员“全部用户”视图显示实际使用人数。
- 默认选择本月，点击周期卡片切换下方分布与明细的统计周期。
- 统计失败时只在概览区域显示错误和重试，不阻断明细查询。

#### 2. 使用分布

- 普通用户或管理员“我的”视图展示按生成类型的消耗分布。
- 管理员“全部用户”视图展示成员排行，复用现有用户、实际消耗、消费次数和占比表格。
- 管理员页面顶部提供“全部用户 / 我的”分段切换，切换时重置分布分页和明细分页。
- 本期不增加趋势图，避免为视觉丰富引入新的聚合接口。

#### 3. 消费明细

- 默认列为：时间、生成类型、模型、消耗、返还、状态。
- 支持按时间范围、生成类型、模型和状态筛选。
- 管理员“全部用户”视图额外显示用户筛选和用户列。
- 点击一行打开只读详情，展示任务 ID、渠道、上游任务 ID、错误摘要和关联前台产物。
- 数据中心不提供刷新上游状态、手动返还、编辑流水或删除流水操作。
- 空数据时显示“暂无消费记录”；查询失败时保留已加载的概览并提供明细重试。

### 管理员任务运维

- `/admin/ai-tasks` 的后台菜单和页面标题由“AI 使用”改为“任务运维”。
- 页面保留“任务明细 / 算力流水”页签及当前所有筛选、详情、刷新、返还、新增、编辑和删除能力。
- 移除页面顶部的使用统计，避免业务概览与技术运维再次混合。
- 管理员需要统计时通过后台顶部账户菜单或数据中心入口进入 `/data-center`。

## 权限模型

### 普通用户

- 可以访问 `/data-center`。
- 服务端从登录态确定用户 ID，不接受由前端指定其他用户。
- 只能读取自己的统计、任务消费明细和余额。
- 不能调用管理员统计、管理员任务、返还或流水写入接口。

### 管理员和超级管理员

- 可以访问 `/data-center` 和 `/admin/ai-tasks`。
- 数据中心可选择 `scope=all` 或 `scope=mine`；默认 `all`。
- `scope=mine` 使用与普通用户相同的自助接口和响应结构。
- `scope=all` 使用管理员统计与任务查询能力。
- 所有修改性操作仍只通过管理员路由执行。

前端的范围切换只影响展示，权限边界必须由后端鉴权和登录用户约束保证。

## 后端设计

### 自助统计接口

新增登录用户接口：

```text
GET /api/me/ai-usage-summary?period=month
```

响应继续使用 `{ code, data, msg }`，并复用现有日、周、月周期结构。响应增加当前余额与按生成类型聚合的数据：

```json
{
  "balance": 860,
  "periods": [
    { "key": "day", "startAt": "...", "endAt": "...", "netCredits": 20, "usageCount": 2, "userCount": 1 }
  ],
  "selectedPeriod": "month",
  "kinds": [
    { "kind": "image", "netCredits": 120, "usageCount": 12, "ratio": 0.6 }
  ]
}
```

普通用户 ID 从登录上下文读取。service 复用现有周期边界与净消耗规则；repository 增加按指定用户和任务类型聚合的只读查询。

### 自助消费明细接口

新增登录用户接口：

```text
GET /api/me/ai-usage-records?period=month&kind=image&model=&status=&startAt=&endAt=&page=1&pageSize=20
```

返回业务化任务摘要和分页信息：

```json
{
  "items": [
    {
      "id": "usage-id",
      "relatedId": "task-or-run-id",
      "sourceType": "ai_task",
      "kind": "image",
      "model": "model-name",
      "status": "succeeded",
      "credits": 4,
      "creditsRefunded": 0,
      "netCredits": 4,
      "provider": "provider-name",
      "upstreamTaskId": "upstream-id",
      "errorMessage": "",
      "createdAt": "...",
      "frontendTrace": {}
    }
  ],
  "total": 1
}
```

消费明细以算力流水为权威来源：按用户和稳定 `relatedId` 配对 `ai_consume` 与 `ai_refund`，形成只读使用记录，再按关联 ID 补充 AI 任务或 Agent Run 的生成类型、模型、状态和技术详情。无法关联到任务的异常流水仍显示为“其他”，不会从明细或总消耗中消失。

响应字段中的 `credits` 表示原始消费绝对值，`creditsRefunded` 表示累计返还，默认展示的实际消耗为 `max(credits - creditsRefunded, 0)`。按生成类型聚合也基于同一批使用记录；Agent Run 归为“智能工作流”，无法识别来源的记录归为“其他”，确保类型分布合计与周期净消耗一致。

普通用户查询始终附加登录用户 ID，不接受用户筛选。显式 `startAt/endAt` 存在时使用自定义时间范围，否则按 `period` 计算北京时间范围。

### 管理员全部用户视图

- 周期概览和成员排行继续使用 `/api/admin/ai-usage-summary`。
- 新增 `/api/admin/ai-usage-records`，复用自助消费明细的只读使用记录结构，并增加用户筛选与用户摘要。
- 管理员消费明细与普通用户消费明细共享相同的 service 聚合和补充逻辑，只有权限范围和用户信息不同。
- 管理后台“任务运维”继续使用原管理员任务列表接口，不与消费明细接口混用。

### 余额一致性

- 自助统计响应中的余额来自当前用户表。
- 页面加载成功后可以同步更新前端用户 store 中的余额，避免画布顶部继续显示旧值。
- 统计失败时不清空本地已有余额。

## 前端结构

新增页面私有目录：

```text
web/src/app/(user)/data-center/
  page.tsx
  use-data-center.ts
  data-center-view.ts
  components/
    data-center-overview.tsx
    data-center-distribution.tsx
    data-center-records.tsx
```

- `page.tsx` 作为装配层，读取当前用户角色并组合页面。
- `use-data-center.ts` 管理范围、周期、筛选、分页和查询，不保存到全局 store。
- `data-center-view.ts` 放标签、列定义和纯展示映射，方便以轻量测试验证默认信息层级。
- 三个组件分别负责概览、分布和消费明细，不接触权限判断。
- API 请求统一新增到 `web/src/services/api/`，继续使用现有请求封装。
- 管理后台 `/admin/ai-tasks/page.tsx` 只保留运维页签装配。

视觉沿用当前 studio 主题与 Ant Design token。整体采用低视觉重量、清晰数据层级：周期卡片弱高亮、表格为主、无额外渐变、阴影或页面私有全局 CSS。

## 数据流

1. 页面从 `useUserStore` 读取登录用户与角色。
2. 普通用户固定使用 `mine`；管理员默认使用 `all`，也可切换 `mine`。
3. `mine` 请求 `/api/me/ai-usage-summary` 和 `/api/me/ai-usage-records`。
4. `all` 请求管理员统计和 `/api/admin/ai-usage-records`。
5. 周期切换同时刷新分布和消费明细，并把明细页码重置为 1。
6. 明细筛选只刷新消费明细，不重复请求概览。
7. 余额更新只写回用户 store 的 credits 字段，不改变登录态其他数据。

## 错误与空状态

- 无登录态访问 `/data-center` 时沿用用户布局重定向到登录页。
- 自助接口返回未登录时清理无效会话；普通查询错误只显示区域错误，不清理有效登录态。
- 概览、分布和明细采用独立加载与错误状态，避免一个请求失败导致整页不可用。
- 管理员切换范围时保留周期，但重置筛选和分页，避免把成员筛选带入“我的”视图。
- 任务缺少模型、渠道或前台追踪信息时显示 `-`，不阻断整行渲染。

## 测试设计

### 后端

- 普通用户自助统计只包含自己的消费与返还，不能通过查询参数读取其他用户。
- 普通用户自助明细只返回自己的使用记录。
- AI 任务、Agent Run 和无法关联来源的消费都进入明细，消费与返还配对后不重复计数。
- 自助统计沿用北京时间日、周、月边界与净消耗口径。
- 管理员调整不进入自助使用统计。
- 按生成类型聚合的消耗、次数和占比正确。
- 明细类型、模型、状态、时间和分页筛选正确。
- 类型分布与选中周期净消耗合计一致，Agent Run 和未知来源分别进入“智能工作流”和“其他”。
- 未登录访问自助接口返回未登录错误。

### 前端

- 数据中心导航入口对所有登录用户可见，画布余额链接到 `/data-center`。
- 普通用户没有范围切换和管理员操作。
- 管理员默认全部用户，可切换到我的数据。
- 默认消费明细列不包含渠道、上游任务 ID、错误或操作列。
- 只读详情可以展示技术字段，但没有刷新和返还按钮。
- 管理后台显示“任务运维”，保留原任务与流水页签，页面不再渲染使用概览。
- 概览失败不影响明细，明细空数据和错误状态文案明确。

实现遵循测试先行：先增加会失败的权限、路由、视图结构和查询测试，确认失败原因是能力缺失，再做最小实现并复验。

## 非目标

- 不增加团队、工作室、子管理员或项目成员权限体系。
- 不增加项目、剧集、画布维度的后台聚合与筛选。
- 不把浏览器本地项目或剧集改为云同步。
- 不增加趋势图、费用预测、导出或预算告警。
- 不改变消费、返还或管理员调整的现有持久化语义。
