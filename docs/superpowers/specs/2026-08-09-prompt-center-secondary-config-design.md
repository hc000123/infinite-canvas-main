# 提示词中心收口为二级配置设计

## 目标

提示词配方不再作为主制作流程的独立顶级板块，而是作为一项按需进入的配置能力。主导航保留项目、Agent、画布、分镜、资产和缓存等主生产界面。

## 信息架构

- 从全局顶部主导航移除“提示词”入口。
- 在现有“配置”弹窗增加“提示词配置”二级入口，点击后关闭弹窗并进入 `/prompts`。
- `/prompts` 路由与页面保留，不重定向、不删除。
- 画布、分镜制作台和其他业务页内已有的“提示词库”或模板选择入口保留，它们属于当前任务的上下文工具，不是全局主导航。

## 数据与行为边界

- 不删除公司标准、项目风格、个人习惯、提示词模板或浏览器本地配置。
- 不修改提示词 API、store、模板变量、运行时合并顺序和画布 / 分镜调用方式。
- 不改变管理员在后台维护公司标准提示词的权限。

## 交互与错误处理

- “提示词配置”使用配置弹窗已有的次级按钮视觉，不引入新导航层级或新弹窗。
- 点击时先关闭配置弹窗，再由 Next.js Router 导航到 `/prompts`，避免页面切换后遮罩残留。
- 原有提示词页读取或保存失败时，继续使用它现有的错误提示，不在配置弹窗重复实现。

## 验收

- 所有使用全局顶部导航的主界面不再显示“提示词”。
- 打开“配置”可看到“提示词配置”，点击后进入 `/prompts` 且配置弹窗已关闭。
- 直接访问 `/prompts` 仍能正常显示原数据和配方功能。
- 画布和分镜制作台中的提示词模板选择入口仍可用。

## 范围外

- 不把完整提示词页内嵌到配置弹窗。
- 不将提示词配置改成仅管理员可用。
- 不删除历史数据或改动工作流的提示词产出逻辑。
