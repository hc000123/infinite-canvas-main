# 画布素材同步可靠性设计

## 目标

修复画布生成素材偶发未进入“我的素材”，以及下载或导出后素材看似丢失的问题。素材仍保存在浏览器本地，不新增云端同步或旧数据兼容逻辑。

## 根因

- `useAssetStore` 使用异步 localForage 恢复数据，但 `addAssetOnce` 没有等待恢复完成；恢复结果可能覆盖恢复期间新增的画布素材。
- 画布生图通过 `void archiveGeneratedAsset(...).catch(() => undefined)` 后台归档，生成流程既不等待归档，也不提示归档失败。
- 素材下载直接使用展示用临时 URL，没有优先读取 `storageKey` 对应的持久化 Blob，文件状态与列表状态容易表现不一致。

## 方案

1. 为素材 Store 增加一次性恢复门；`addAssetOnce` 必须等待恢复结束后再读取、去重和写入素材。
2. 生图成功后等待素材归档结束；失败时保留已生成图片，同时向用户提示“同步到我的素材失败”。
3. 下载图片、视频和音频时优先读取 `storageKey` 对应的 Blob，缺少本地文件时再使用现有 URL；下载动作不修改素材 Store。
4. 增加定向回归测试，验证恢复门在释放前阻止写入、释放后继续且重复释放安全。

## 边界

- 不修改素材、文件夹或画布的数据结构。
- 不改变素材去重规则。
- 不引入后端表、云同步或数据迁移。
- 不调整导入、删除和素材清理流程。

## 验收

- 素材 Store 恢复未完成时，画布归档等待而不是写入空状态。
- 生图流程结束时，归档已经成功或已显示明确错误。
- 下载使用持久化文件且下载前后素材 ID 集合不变。
