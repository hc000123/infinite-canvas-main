# 全系统共享 Skill 设计

## 背景

当前 Skill 分为 System Skill 和项目 Skill。项目 Skill 同时绑定创建者与项目 ID，只有同一账号进入原项目时才会出现在剧本优化、工作流节点等 Skill 选择入口。后台虽然可以查看全部 Skill，但这种“后台可见、其他项目不可用”的行为不直观，也会让同一能力在多个项目之间重复创建和维护。

## 目标

- 取消项目专属 Skill，所有可运行 Skill 均为全系统共享的 System Skill。
- 所有账号、所有项目使用同一套已启用、已发布且契约匹配的 Skill。
- Skill 的创建、导入、编辑、评测、发布、推荐和停用只允许管理员操作。
- 将现有项目 Skill 直接整理为 System Skill，使已有有效能力继续可用。
- 保留现有 Skill 版本、Manifest、Artifact 契约、评测、审计和执行机制。

## 产品与权限边界

- 管理后台“Skill 中心”是唯一 Skill 管理入口。
- 管理员可以创建、导入、编辑、评测、发布、推荐、归档和停用 System Skill。
- 普通用户不能创建、导入、复制或修改 Skill，只能在项目业务入口选择并运行可用 Skill。
- 项目详情不再提供独立的 Skill 管理入口，也不展示“项目 Skill”或“专属 Skill”概念。
- 后台 Skill 列表、筛选、卡片和编辑表单只使用“系统”这一种归属语义。

## 可见性与运行数据流

1. 项目业务入口携带 Capability、输入 Artifact 类型和输出 Artifact 类型请求 Skill 候选。
2. 后端要求调用者已登录，但不再使用项目 ID 或创建者 ID限制 Skill 可见范围。
3. 后端仅保留已启用 Skill 的已发布版本，并按 Manifest Capability 与 Artifact 契约过滤。
4. 前端继续按现有规则展示版本名称、推荐状态并保存所选精确版本 ID。
5. Skill 的执行、重试、审阅、回写和工作流绑定继续使用现有版本 ID，不改变运行时协议。

`projectId` 可以暂时保留在候选接口参数中以减少调用方改动，但不得参与 Skill 可见性判断；后续清理接口时再单独删除。

## 创建与管理入口

- 后台创建与文件夹导入固定创建 System Skill，不再提供归属类型或目标项目选项。
- 删除项目 Skill 创建、文件夹导入、复制为项目 Skill等前端入口。
- 后端停止注册或明确拒绝项目 Skill 创建、导入、复制相关接口，防止绕过前端继续产生专属数据。
- 项目 Skill 管理路由不再承担管理功能；从仍可能存在的旧链接进入时，返回项目页面或明确提示“请由管理员前往 Skill 中心管理”，不暴露编辑能力。

## 现有数据整理

- 将现有 `owner_type = project` 的 Skill 统一改为 `owner_type = system`。
- 同时清空 `owner_user_id` 与 `owner_project_id`，避免保留无效的专属归属信息。
- Skill ID、版本 ID、版本状态、推荐版本、内容哈希、评测、审计记录和工作流引用保持不变。
- 当前“全家穿越-剧本优化”整理后立即成为全系统候选；其已发布推荐版本可在任意项目的剧本优化选择框中出现。
- 项目尚未上线，本次直接按新设计整理当前数据，不增加旧项目归属的兼容分支或长期迁移兜底。

## 错误处理与安全

- 未登录用户请求 Skill 候选时继续返回未登录错误。
- 普通用户访问 Skill 管理写接口时返回权限不足，不允许以项目所有者身份绕过管理员权限。
- 无推荐版本不影响已发布精确版本作为候选；候选规则继续沿用当前实现。
- 禁用 Skill、草稿版本、已归档版本和契约不匹配版本不得出现在业务选择入口。
- 数据整理前后保留 Skill 与版本主键，避免已有运行记录和引用失效。

## 验收

- “全家穿越-剧本优化”在不同项目的剧本优化 Skill 选择框中均可见。
- 任意已登录账号在相同输入、输出与 Capability 条件下获得相同的系统 Skill 候选。
- 创建或导入 Skill 时不再出现“项目”归属选项。
- 项目页面不再提供 Skill 创建、导入、编辑或复制入口。
- 普通用户直接调用原项目 Skill 管理接口时无法创建或修改 Skill。
- 管理员仍能在后台完成 System Skill 的完整版本管理流程。
- 已有 Skill 版本 ID、推荐版本、评测和执行引用在数据整理后保持有效。

## 验证范围

- Repository / Service：系统 Skill 全局可见，项目与用户归属不再参与候选筛选。
- Handler / 权限：管理写操作仅管理员可用，项目 Skill 写入口不可用。
- 前端：后台只展示系统归属；项目内管理入口消失；剧本优化候选能展示整理后的 Skill。
- 数据：不存在仍带项目归属的可运行 Skill，现有版本与引用未变化。

## 非目标

- 不增加团队、组织、角色组或按项目授权的 Skill 权限模型。
- 不改变 Skill Manifest、Artifact 契约、评测标准或执行协议。
- 不调整工作流绑定的全局/项目作用域；本次只取消 Skill 定义本身的项目专属归属。
- 不删除历史审计记录中的原始项目范围信息。
