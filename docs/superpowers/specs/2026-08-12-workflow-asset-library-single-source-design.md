# 工作流资产与资产库单一数据源设计

> 路由部分已被 `2026-08-12-asset-only-image-generation-entry-design.md` 的最新决定覆盖：独立 `/image` 工作台已取消，仅保留到资产主体工作台的兼容转发；本文其余单一数据源设计继续有效。

## 背景

资产生产阶段会把提取结果写入浏览器本地资产 store，并为每条结果建立工作流资产记录。但资产库当前主要按 `AssetSubject` 与 `AssetVariant` 展示，主体卡没有读取工作流资产中的提示词与描述；工作流同步也没有稳定写入 `variantId`、形态提示词和当前图片。因此，同一条资产虽然已经进入资产库，两个入口显示的信息并不一致。

浏览器反馈中的 `/image` 再次显示分镜属于运行态旧包：当前源码已将 `/image` 固定为生图、`/storyboard` 固定为分镜并提供两个导航入口，但反馈时本机 3000 端口没有 Next.js 进程，页面仍停留在旧前端包。

## 目标

- 资产生产提取完成后，自动在资产库建立对应主体、形态和资产记录，不需要再次导入或建立卡片。
- 资产生产与资产库通过同一个稳定资产 ID 查看和修改提示词、描述、预览图、版本与绑定关系。
- 资产库主体卡紧凑显示当前预览与提示词摘要；主体详情展示可编辑的完整提示词。
- 工作流生成、上传或绑定图片后，图片自动成为对应形态的当前预览。
- 保持 `/image` 为生图工作台、`/storyboard` 为分镜制作台，并通过重新启动当前源码服务消除旧包。
- 不自动触发任何真实图片生成。

## 方案选择

### 方案 A：复制工作流内容到资产库卡片

实现最直接，但会形成两份提示词与预览状态，编辑后容易再次分叉。

### 方案 B：维护两套数据并做双向同步

可以保留现有模型，却需要持续处理覆盖顺序、冲突和循环更新，复杂度高且难以验证。

### 方案 C：稳定资产 ID 作为单一数据源（采用）

工作流提取记录继续使用现有 `Asset` 作为规范数据，主体与形态只负责分类、入口和当前版本指针。两个页面都读取并更新同一资产对象，避免复制业务内容。

## 数据流

### 提取物化

对每条通过质量门的工作流资产：

1. 按项目、类别和逻辑资产编号确保唯一主体存在。
2. 按主体和形态名称确保唯一形态存在；基础角色使用“基础形象”，其他基础资产使用“基础状态”，服装、发型等变化使用工作流提供的形态名。
3. 把最终提示词同步到形态的 `prompt`，并把形态 ID 写入资产的 `assetBinding.variantId`。
4. 继续以现有 `originalWorkflow` 元数据保存逻辑编号、剧本证据、描述、提示词和来源集数。
5. 已存在的资产也执行同样的对齐，不只处理首次创建，确保旧的已物化记录在刷新工作流时自动补齐关系。

人工在工作流卡片改过提示词时，继续尊重 `manuallyEdited`，不被同一 Artifact 的原始值覆盖。

### 图片回写

- 工作流后台生图成功后，更新原资产 ID 的图片数据和版本历史，并把该资产设为绑定形态的 `currentAssetId`。
- 从本地上传或资产库绑定图片后执行同样的当前预览更新。
- 不创建仅用于展示的第二份图片资产。

### 编辑一致性

- 工作流资产卡编辑描述或提示词时，同时更新规范资产元数据与对应形态提示词。
- 资产主体详情从绑定的工作流资产读取提示词；修改时同时更新规范资产元数据与形态提示词。
- 没有工作流来源的普通资产继续使用原有形态提示词逻辑。

## 展示

### 资产库主体卡

- 保持当前紧凑网格和操作按钮，不恢复大型详情卡。
- 图片区域优先显示形态当前图片；没有显式当前图片时，使用该主体最新的正式图片作为安全预览。
- 正文增加最多两行的提示词摘要；没有工作流提示词时显示现有形态提示词或“待补充提示词”。
- 卡片继续显示形态数、版本数和待选结果数量。

### 资产主体详情

- 左侧“画面描述”展示当前形态对应工作流资产的完整提示词。
- 修改后两个页面立即读取同一结果。
- 右侧版本区自动选择工作流生成或导入的当前图片。

## 路由运行态

- 不重新引入按查询参数切换页面的逻辑。
- `/image` 继续只渲染 `AssetImageWorkbench`；`/storyboard` 继续只渲染 `StoryboardImageWorkbench`。
- 完成代码后启动当前工作区的 Next.js 开发服务，并分别读取两个地址确认页面标题与导航入口匹配。

## 错误处理

- 主体或形态物化失败时保留现有工作流卡片并显示同步失败，可重试；不丢失 Artifact。
- 找不到绑定形态时不猜测其他主体，只保留资产记录并等待下一次物化对齐。
- 图片回写成功但形态指针更新失败时，图片仍保留在资产记录中，资产库可通过最新正式图片兜底显示。

## 验证

- 单元测试覆盖工作流条目到主体/形态绑定计划、提示词同步和当前图片选择。
- 资产库汇总测试覆盖工作流提示词摘要与无显式 current ID 时的最新图片兜底。
- wiring 测试覆盖物化、编辑、生图和导入路径均更新对应形态。
- 既有 `/image`、`/storyboard` 与导航测试继续通过。
- 启动本地服务后只做页面读取与导航验证，不点击任何真实生成按钮。
