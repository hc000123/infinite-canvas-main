# 画布视频素材顺序防漂移设计

## 目标

确保视频节点或视频生成配置节点连接多张图片后，提示词中的结构化 `@` 引用、界面显示的“图片 N”、Seedance 输入顺序以及首帧/尾帧角色始终指向同一个画布节点，避免素材 A、B 在提交时互换。

## 已确认根因

1. 没有 `inputOrder` 时，上游素材顺序直接依赖 `connections` 数组顺序；批量连接、断开后重连或替换节点会改变隐式顺序。
2. 结构化提示词保存节点 ID，但序列化后的 `prompt` 字符串只在编辑器内容变化时更新。连接顺序变化后，界面会按最新顺序显示标签，提交仍可能使用旧的“图片 N”字符串。
3. 未明确绑定角色时，首帧和尾帧按图片数组下标推断，因此同样受隐式顺序影响。

## 方案选择

采用“持久化输入顺序 + 提交时原子重建”的组合方案。

- 仅在提交时重建提示词可以解决旧编号问题，但不能阻止首尾帧和普通素材编号随连接数组变化。
- 按节点 ID 或坐标排序虽然稳定，但会改变用户已经建立的输入顺序，也无法表达用户主动调整顺序的意图。
- 持久化 `inputOrder` 保留用户当前顺序；提交时用同一份当前输入快照同时序列化提示词和构建媒体列表，可消除两个数据源分叉。

## 数据流

1. 创建单条或批量连接时，将目标节点当前有效输入顺序与新来源节点 ID 合并到 `metadata.inputOrder`，去重并保留已有顺序。
2. 构建生成输入时继续优先读取 `inputOrder`；历史节点没有该字段时沿用当前连接顺序。
3. 点击生成时，不再直接提交缓存的提示词字符串。若节点有结构化 `promptDocument`，使用当前生成输入构造 mention options，并即时序列化。
4. 生成上下文和视频 payload 使用同一批当前连接与 `inputOrder`，保证“图片 N”与第 N 张参考图一致。
5. 首帧/尾帧继续优先使用 `referenceRoles` 或专用连接端口；只有没有显式角色时才使用已持久化顺序推断。

## 兼容范围

- 不迁移旧数据；历史节点在下一次新增连接或调整输入顺序时自然写入 `inputOrder`。
- 不改变结构化引用格式，仍以真实画布节点 ID 持久化。
- 不改变 Seedance payload 协议和素材上传逻辑。
- 普通纯文本提示词保持原样，不尝试解析手写的“图片 1”。

## 测试

- 结构化引用在 A、B 顺序调整后，提交提示词从“图片 1”同步变为“图片 2”，同时仍绑定 A。
- 单条连接、批量连接和连接已有 `inputOrder` 的目标时，顺序追加、去重且不覆盖已有用户顺序。
- `first_last_frame` 模式在连接数组顺序变化但 `inputOrder` 固定时，A/B 的首尾帧角色保持不变。
