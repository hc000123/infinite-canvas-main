# 项目分集资产管理设计

## 目标

把“我的素材”从按媒体类型展示的文件列表升级为项目内的前期资产管理中心，并把项目、标准分集、工作流、主画布和子画布收口为一条明确主线。

用户先创建项目和标准分集，再选择进入视频工作流或画布。角色、场景和道具作为稳定资产主体，每个主体下管理基础图、马甲或不同状态；具体图片可以标记为全剧通用，或绑定多个已有分集。画布按分集筛选并批量导入本集可用图片。

## 已确认的产品规则

1. 项目是所有分集、工作流、画布和资产的上级上下文。
2. 分集必须使用标准编号，格式为 `EP` 加至少两位数字，例如 `EP01`、`EP108`；同一项目内编号唯一。
3. 分集标题可自由填写；标题不能代替分集编号，也不能用于建立绑定关系。
4. 素材只绑定到分集，不增加分场绑定。
5. 每集拥有一个主画布；主画布可以创建多个单层子画布，子画布不能继续嵌套。
6. 工作流、主画布和子画布自动继承项目、分集和剧本上下文，不能自由输入或改绑项目与分集名称。
7. 图片资产必须具有角色、场景、道具或其他分类；工作流自动提供分类，其他导入入口必须在确认框中补齐。
8. 角色、场景和道具是资产主体。角色的基础形象、服装、妆发和状态为马甲；场景的日夜、天气和布置，道具的完好、损坏和形态也使用同一套“图片形态”模型。
9. 图片形态与文件版本是两个概念。马甲/状态是可同时存在的不同图片；对同一形态重新上传或修图才进入文件版本历史。
10. 每个图片形态可设为全剧通用，或绑定一个或多个已有分集。
11. 画布按分集筛选时，同时显示全剧通用图片和绑定该集的图片；批量导入前允许取消勾选。
12. 第一版资产主体只属于一个项目，不实现跨项目共享和分场级绑定。

## 数据模型

### 标准分集

`ScriptEpisode` 增加必填 `code`：

```ts
type ScriptEpisode = {
    id: string;
    projectId: string;
    code: string; // EP01
    order: number;
    title: string;
    // 现有剧本字段保持不变
};
```

输入时先转大写，再以 `^EP\d{2,}$` 校验。同一项目内不得出现重复 `code`。排序继续使用 `order`，展示统一使用 `${code} · ${title}`。

### 资产主体

素材 Store 增加独立的项目资产主体集合：

```ts
type AssetCategory = "character" | "scene" | "prop" | "other";

type AssetSubject = {
    id: string;
    projectId: string;
    category: AssetCategory;
    code: string; // CHAR-001 / SCENE-001 / PROP-001 / OTHER-001
    name: string;
    tags: string[];
    note?: string;
    createdAt: string;
    updatedAt: string;
};
```

主体编号在项目和分类内自动生成，不允许用户用自由文本覆盖。工作流已有 `logicalAssetId` 时优先复用稳定编号。

### 图片形态绑定

`AssetBase` 增加可选的结构化资产绑定；只有完成绑定的图片才进入项目资产主体视图：

```ts
type AssetBinding = {
    projectId: string;
    subjectId: string;
    category: AssetCategory;
    variantName: string; // 基础形象、校服、受伤、夜景、碎屏
    allEpisodes: boolean;
    episodeIds: string[];
};

type AssetBase<T extends AssetKind> = {
    // 现有字段
    assetBinding?: AssetBinding;
};
```

`allEpisodes=true` 时 `episodeIds` 固定为空；否则 `episodeIds` 必须至少包含一个属于同一项目的真实分集 ID。普通 `tags` 继续服务于夜景、雨天、青年、室内等描述，不再承担项目、集数和分类关系。

### 主画布与子画布

`CanvasProject` 增加：

```ts
type CanvasProject = {
    // 现有字段
    canvasRole: "episode_main" | "episode_child";
    parentCanvasId?: string;
};
```

每个 `episodeId` 只能有一个 `episode_main`。子画布必须引用同集主画布，继承其 `projectId`、`episodeId`、剧本快照和预设；只允许自定义标题。画布 Store 提供“确保主画布存在”和“创建子画布”动作，页面不再提供脱离分集的新建项目画布入口。

## 页面与交互

### 项目详情和分集入口

项目详情成为唯一制作入口：

1. 新建或导入分集时必填标准集号、自由标题和剧本。
2. 分集卡显示 `${code} · ${title}`。
3. 每张分集卡提供“进入工作流”和“进入画布”两个主动作。
4. “进入画布”自动确保主画布存在并打开；不再先独立建画布再绑定。
5. 原项目级“画布列表/绑定旧画布/新建独立画布”入口退场，改为在对应分集下展示主画布与子画布。

### 项目素材库

素材页先锁定项目，再展示：

- 集数筛选：全部、具体标准分集。
- 主分类：角色、场景、道具、其他。
- 搜索：主体名称、主体编号、形态名称和普通标签。
- 主体卡：主体编号、名称、标签，以及其下全部图片形态。
- 形态缩略图：形态名称、适用集数、当前文件版本和常用操作。

新增“批量导入图片”流程：

1. 必须选择已有项目。
2. 必须选择分类。
3. 必须绑定已有主体或创建新主体。
4. 必须填写形态名称；首次角色图默认为“基础形象”，场景和道具默认为“基础状态”。
5. 必须选择“全剧通用”或至少一个已有分集。
6. 批量导入可先应用公共设置，再逐张调整主体和形态。

单项编辑继续保留标题、标签、来源、备注和文件版本，同时增加结构化绑定区。批量移动文件夹和普通标签功能保持不变。

### 工作流归档

工作流的 `character / scene / prop / costume` 映射为统一主体：

- `character` 创建或复用角色主体，形态为“基础形象”。
- `costume` 通过 `parentLogicalAssetId` 绑定角色主体，`variantName` 作为马甲名。
- `scene` 创建或复用场景主体。
- `prop` 创建或复用道具主体。
- 工作流当前分集自动写入 `episodeIds`，不能由产物自由文本改写。

### 画布素材选择与批量导入

画布素材选择器读取画布已经锁定的 `projectId` 和 `episodeId`，不显示自由项目/集数输入：

1. 默认只显示全剧通用和当前分集适用的图片。
2. 支持角色、场景、道具、其他和关键词筛选。
3. 以资产主体卡展示各形态，可多选。
4. “导入本集素材”默认全选筛选结果，用户可取消部分图片。
5. 确认后按角色、场景、道具、其他分区排列节点，并保留 `sourceAssetId` 与文件版本引用。

画布本地上传或生成图片归档时弹出轻量确认框，项目和分集只读，用户补齐分类、主体与形态后才能写入项目资产库。普通临时节点允许存在于画布，但不会伪装成已完成分类的项目资产。

### 子画布

主画布工具栏提供“新建子画布”。弹窗只输入标题；创建后自动继承当前项目、分集、剧本和画布预设。子画布顶部显示返回主画布入口与同集子画布切换，不提供再次新建孙级画布的动作。

## 数据流与一致性

所有入口最终调用同一套纯函数和 Store 动作：

1. `normalizeEpisodeCode` 负责集号标准化与校验。
2. `ensureAssetSubject` 按项目、分类和稳定编号创建或复用主体。
3. `normalizeAssetBinding` 校验项目、主体、分类和分集关系。
4. `assetsForEpisode` 返回全剧通用与指定分集的图片。
5. `ensureEpisodeMainCanvas` 保证一集一个主画布。
6. `createEpisodeChildCanvas` 保证子画布只继承、不改绑、不嵌套。

去重写入命中已有图片时保留已有明确主体绑定；只有原记录未分类时才接收新绑定。文件版本切换不改变主体、形态和适用集数。

## 错误处理

- 集号格式错误：阻止保存并提示“请输入 EP01 这类标准集号”。
- 项目内集号重复：阻止保存并定位已有分集。
- 未选项目、分类、主体/新主体名称、形态或适用集数：阻止项目素材归档。
- 绑定了其他项目的主体或分集：视为无效数据并阻止保存。
- 已删除分集：从图片的 `episodeIds` 中移除；若结果为空且不是全剧通用，标记为“未标集数”，要求重新处理。
- 已删除主体：所属图片移除结构化绑定，文件本身保留在普通素材中，避免丢失本地媒体。
- 批量导入画布时单张图片读取失败：继续导入其他图片，并汇总失败项。

## 验收边界

1. 创建项目后导入 `EP01`，集号格式和项目内唯一性生效，标题可自由编辑。
2. 从 `EP01` 分集卡分别进入工作流和主画布，两者共享同一项目、分集和剧本。
3. 主画布创建两个子画布，子画布继承上下文且不能继续嵌套或跨集改绑。
4. 批量导入角色、场景和道具图片，未完成分类和集数选择时不能进入项目资产主体视图。
5. 一个角色主体可同时显示基础形象、校服和受伤马甲；每个形态拥有独立文件版本历史。
6. 同一场景图片绑定 `EP19`、`EP47`、`EP48` 后，在三集画布中均可找到，在其他集不可见。
7. `EP47` 画布筛选结果同时包含全剧通用图片和 `EP47` 专用图片，一键导入后按分类分区排列。
8. 工作流角色、服装、场景和道具产物自动进入正确主体与当前分集，不依赖产物中的自由项目名或集数名。
9. 画布上传、画布生成、本地批量导入和工作流归档使用同一分类与集数查询结果。
10. `docs/todo.md` 与 `docs/pending-test.md` 按实际实现结果更新。

## 非目标

- 跨项目共享同一个资产主体。
- 云端多人素材同步。
- 分场级素材绑定。
- 多层子画布。
- 使用文件名或 AI 猜测自动建立项目、分集或主体关系。
