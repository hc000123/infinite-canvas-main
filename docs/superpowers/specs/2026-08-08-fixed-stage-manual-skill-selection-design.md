# 固定生产阶段与手动 Skill 选择设计

## 背景

项目当前同时向制作人员展示 Workflow 中心、Skill 管理和固定分集生产流程，容易让人误以为需要先设计 Workflow，再配置 Skill。实际产品目标更简单：生产阶段由系统固定，管理员或项目成员维护各阶段可用 Skill，制作人员运行阶段前手动选择具体 Skill 版本。

本次收口移除制作人员可见的自由 Workflow 编排入口，但保留后端 Workflow、Invocation 和 Artifact Runtime，用于固定阶段顺序、任务状态、审核、恢复和产物传递。

## 目标

- 项目界面只呈现固定生产流程和 Skill 管理，不要求制作人员设计节点或路由。
- System Skill 和 Project Skill 继续使用同一套 Skill Registry 与运行时。
- 项目 Skill 页面按生产阶段折叠，复用后台 Skill 中心的分组规则。
- 每个固定阶段在执行前由制作人员手动选择兼容的 Skill 和精确版本。
- 明确全局缓存与项目缓存入口的关系。
- 在独立试跑提交前识别默认模型缺失，避免产生无意义的失败评测。

## 非目标

- 不删除后端 Workflow、Invocation、Artifact、审批、恢复或版本冻结能力。
- 不新增自由拖拽编排、自动路由、标签决策或 Agent 自动选 Skill。
- 不改变现有固定阶段的输入输出 Artifact 契约。
- 不合并 System Skill 与 Project Skill 的所有权和权限。
- 不新增第二套缓存数据或项目专属缓存页面。

## 产品概念

### 固定生产流程

固定生产流程负责阶段顺序和运行状态。阶段由系统定义，例如剧本与内容分析、资产提取、资产设计 / Brief、资产成图、分镜、镜头提示词 / 视频和成片交付。

制作人员不能新增、删除或连线阶段，也不需要理解 DAG、条件节点或路由策略。

### Skill Registry

后台 `/admin/skills` 是全局 System Skill 管理入口。项目 `/projects/:id/skills` 使用同一套 Registry 数据：

- System Skill 对项目只读，可复制为独立 Project Skill。
- Project Skill 只属于当前项目，可导入、试跑、发布、推荐、停用或删除。
- 两种 Skill 都按同一生产阶段规则归类。
- Workflow、画布、图片和 API 调用的是同一个冻结 Skill 版本。

### 运行时选择

每个固定阶段只列出满足 capability、输入 Artifact 和输出 Artifact 契约的已发布 Skill 版本。制作人员执行前明确选择一个版本，系统将该精确版本冻结到本次运行记录。

系统不得根据题材标签、历史推荐或其他隐式规则自动替换选择。已保存的阶段选择可以作为下次默认显示值，但仍由制作人员确认后执行。

## 项目导航

项目详情顶部保留以下生产入口：

- 分集
- 项目画布
- Skill 管理
- 查看项目缓存

原“Workflow 中心”按钮改为“Skill 管理”，进入 `/projects/:id/skills`。

旧 `/projects/:id/workflows` 页面不再作为制作人员入口。直接访问该地址时重定向到 `/projects/:id/skills`，避免旧书签进入已退场的自由编排界面。后端已有 Workflow 定义和运行记录不删除。

“管理缓存”改名为“查看项目缓存”，继续进入 `/cache?projectId=:id`。顶部全局“缓存”进入同一个 `/cache` 页面但不预设项目筛选，两者使用相同数据和操作。

## 项目 Skill 页面

项目 Skill 注册表复用后台 Skill 中心的阶段定义、分类回退、固定排序和计数逻辑，不复制第二份规则。

阶段顺序为：

1. 剧本与内容分析
2. 资产提取
3. 资产设计 / Brief
4. 资产成图
5. 分镜
6. 镜头提示词 / 视频
7. 成片交付
8. 其他

页面行为：

- 只渲染存在当前可见 Skill 的阶段。
- 默认展开当前选中 Skill 所在阶段；没有选中项时展开第一个非空阶段。
- 搜索或所有者筛选生效时，展开全部匹配阶段。
- 阶段标题显示总数、System 数量和 Project 数量。
- Skill 卡片、版本轨道、导入、复制、试跑和生命周期操作保持现状。

共享分组逻辑从后台页面私有目录移动到通用 Skill 组件或工具目录，由后台和项目页面共同引用。

## 独立试跑与默认模型

当前运行配置已经公开 `gpt-5.6-sol`，但 `defaultTextModel` 和兼容字段 `defaultModel` 都为空，因此文本 Skill 独立试跑在调用模型前返回“缺少文本模型”。该错误发生在执行目标解析阶段，不是 Skill 内容、输出 Schema 或固定转换问题。

本次处理分为两层：

1. 将当前本地公开配置的默认文本模型明确设置为 `gpt-5.6-sol`。
2. 独立试跑弹窗打开时读取公开模型配置。文本 Skill 没有默认文本模型、图片 Skill 没有默认图片模型时，禁用运行按钮并显示可操作提示；管理员可进入后台模型设置，普通用户只看到“请联系管理员配置默认模型”。

前端预检查只改善反馈，后端执行目标校验继续保留，防止过期页面或直接 API 绕过配置要求。系统不静默选择可用模型列表中的第一个模型。

## 数据流

1. 管理员在后台维护 System Skill 和默认模型。
2. 项目成员在项目 Skill 管理中查看 System Skill、复制或导入 Project Skill。
3. Skill 通过独立试跑和质量门后发布。
4. 制作人员进入固定生产阶段，从兼容版本列表中手动选择 Skill。
5. 后端冻结 Skill 版本、模型执行目标和输入 Artifact 快照。
6. Runtime 执行、审核并将产物传给下一个固定阶段。

## 错误处理

- 没有兼容 Skill：阶段显示“当前没有满足输入输出契约的已发布 Skill”，不能执行。
- 没有默认模型：独立试跑在提交前禁用，并给出模型类型和设置入口提示。
- 已选择 Skill 后被停用：执行前重新校验并要求用户选择其他版本，不自动替换。
- 旧 Workflow 中心 URL：服务端或页面级重定向到项目 Skill 管理。
- 未分类 Skill：进入“其他”，不得从注册表消失。

## 测试与验收

自动测试覆盖：

- 项目导航显示“Skill 管理”和“查看项目缓存”，不再显示“Workflow 中心”。
- `/projects/:id/workflows` 重定向到 `/projects/:id/skills`。
- 后台和项目页面共用同一阶段分组函数。
- 项目 Skill 分组顺序、计数、选中项展开、筛选展开和未分类兜底。
- 独立试跑在对应默认模型为空时禁用并显示明确原因。
- 后端在缺少执行目标时仍拒绝调用。

人工验收覆盖：

- 从项目详情直接进入 Skill 管理，确认 System 与 Project Skill 均按阶段折叠。
- 从顶部缓存和“查看项目缓存”分别进入同一页面，确认后者自动筛选当前项目。
- 在固定阶段选择不同 Skill 版本，确认运行记录冻结用户所选版本且不会自动替换。
- 使用 `gpt-5.6-sol` 完成一次文本 Skill 独立试跑；临时清空默认文本模型后，确认弹窗提交前即阻止运行并显示设置提示。
