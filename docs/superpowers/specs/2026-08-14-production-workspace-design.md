# 2026 AI 原生制作工作台设计说明

## 状态

- 方案已确认。
- 推荐组合：A「自适应生产台」作为全站骨架，B「编辑流」作为项目首页，C「空间工作室」的关系表达渐进进入画布。
- 原「电影制片编辑部」方案作废，不再作为实现依据。

## 目标

把产品从传统的“顶栏 + 卡片仪表盘 + 独立 AI 页面”重组为以项目对象、当前制作阶段和可追踪 AI 任务为中心的专业工作台，同时保持现有业务数据、生成逻辑、API、store 和画布节点操作不变。

成功标准：

1. 用户在项目、分集、镜头和画布之间移动时，始终知道自己所在的制作上下文。
2. 首页优先回答“现在该推进什么”，不再只展示项目卡片墙。
3. AI 的运行范围、状态、产物和等待确认点可见；AI 结果回到可编辑工作面。
4. 主内容获得最大视觉权重，导航、筛选和低频操作退到边缘。
5. 深浅主题、中文排版、键盘与触控反馈保持完整。
6. 不修改已有生成、存储、费用、超分、插帧、字幕擦除和节点创建逻辑。

## 研究依据

- [Figma Design Agent，2026-05-20](https://www.figma.com/blog/the-figma-agent-is-here/)：Agent 位于画布与对象上下文中，用户可在 Agent 运行时继续编辑。
- [Figma Weave，2026-04-09](https://www.figma.com/blog/five-figma-weave-workflows/)：生成链路可分支、批量运行、并排比较并保留谱系。
- [Config 2026，2026-06-24](https://www.figma.com/blog/config-2026-recap/)：图像、视频、动效、生成式能力和代码层成为同一画布中的材料。
- [Runway Aleph 2.0 / Edit Studio，2026-05-21](https://runway.com/news/introducing-aleph-2-and-edit-studio)：正式付费生成前先低成本预演修改范围。
- [Linear 设计更新，2026-03-12](https://linear.app/blog/behind-the-latest-design-refresh)：降低导航、边框和非激活元素的视觉重量。
- [Linear Agent，2026-03-24](https://linear.app/changelog/2026-03-24-introducing-linear-agent)：Agent 全局可达但默认不抢画面，在任务发生处提供可编辑草稿。
- [DaVinci Resolve 21](https://www.blackmagicdesign.com/products/davinciresolve/whatsnew)：同一项目对象在不同制作阶段切换专用工作空间。

这些来源支持的是结构原则，不是某一种统一的“2026 流行皮肤”。全页玻璃拟态、Bento 卡片墙、紫色渐变 AI 按钮和营销站式滚动特效不进入生产工作台。

## 产品结构

### 第一层：全局应用脊柱

桌面端使用 52–58px 的左侧应用脊柱，提供项目、画布、分镜、素材、提示词和缓存等全局入口。它替代当前常驻横向顶栏，未激活入口保持低对比；主题、用户与设置放到底部。

约束：

- 路由和项目上下文参数沿用 `navigationTools`、`contextualToolHref` 与 `workspaceProjectId`。
- 画布详情页继续使用自己的沉浸式壳层，不叠加全局脊柱。
- 中屏折叠为 48px 图标栏，小屏改为底部/抽屉导航，不把桌面布局等比压缩。

### 第二层：项目上下文树

进入项目后，在全局脊柱右侧出现项目上下文树：项目总览、资产设定、分集列表，以及当前分集的剧本、分镜、画布和审片入口。

上下文树只负责定位，不复制创建、导入、生成等业务动作。低频项目管理进入“更多”。

### 第三层：连续工作面

中央工作面随制作阶段改变：

- 项目首页：编辑式工作流，按最近活动和待确认事项组织。
- 项目详情：分集轨道 + 当前分集内容，不再用多层卡片包装。
- 生产总控：任务行/阶段轨道，突出 queued、running、needs-review、done、failed。
- 画布：保持无限画布，工具退到边缘，节点和生成结果为主角。

### 第四层：AI 执行轨迹

AI 分为三层：

1. 项目总控员工：跨分集、素材和任务协调。
2. 阶段员工：只处理剧本、分镜、生成、精修或交付阶段。
3. 对象级动作：作用于当前镜头、素材或节点。

右侧区域显示执行轨迹而不是单纯聊天瀑布：当前动作、作用对象、输入来源、状态、产物和等待确认点。默认可折叠；在没有运行任务时不永久占据大面积工作区。

## 关键页面

### 工作首页 `/projects`

结构：

- 顶部只保留“今天”、当前项目数量、待确认数量和“新建项目”。
- 主区按更新时间展示项目工作事件，而不是统一尺寸的项目卡片。
- 右侧“今日焦点”从现有项目状态、分集状态和运行记录投影；第一阶段没有跨源运行数据时，只展示可由本地 store 确定的项目动作，不伪造任务。
- 搜索与状态筛选收进一条低视觉重量工具行；列表/网格切换取消。
- 重命名、归档、恢复、删除仍调用原有动作。

### 项目详情 `/projects/[id]`

结构：

- 左侧项目上下文树。
- 中央为项目标题、阶段轨道和分集连续列表。
- 选中分集后在当前工作面展示剧本、优化版本与画布入口。
- 右侧执行轨迹只投影现有 `optimizingEpisodeIds`、`scriptOptimizeErrors` 和可获得的 Invocation 状态。
- 新建分集、编辑项目、剧本 Skill、画布绑定等逻辑原样复用。

### 生产总控 `/agent`

结构：

- 跨项目视图由项目卡片改为任务/注意力工作流。
- 项目视图按分集展开阶段状态，保留现有筛选与 URL 路由。
- 进入具体分集仍装配现有 `EpisodeWorkflowWorkbench`，不修改工作流状态机。
- Agent 建议必须是草稿或待确认动作，不得直接推进生产状态。

### 画布 `/canvas/[id]`

结构：

- 保留已确认的顶部常驻动作与左侧创建栏。
- 画布助手从“大聊天面板”逐步重排为可折叠执行轨迹；历史对话和写入逻辑不变。
- 节点选中后显示对象级 AI 动作；无选中时只保留全局召唤入口。
- 第二阶段再增加“创作模式 / 流程模式”：创作模式保持当前自由画布；流程模式显示生成分支和谱系。第一轮不改节点数据结构。
- 生成前预演复用现有费用预估和确认弹窗，不新增自动付费调用。

## 视觉系统

### 层级

- 应用背景、导航、工作面、浮层使用 3–4 个接近的中性色阶。
- 主内容最亮；导航、说明、非激活状态逐级降低对比。
- 以对齐、留白和细分隔线组织连续内容，避免容器套容器。
- 卡片只保留给可移动对象、媒体资产和真正独立的可点击集合。

### 强调色

- 每个主题只使用一个主要动作色。
- 主要动作色只用于当前阶段、主操作、运行状态和选择态。
- 成功、警告、错误继续使用语义色，不与品牌动作色混用。
- AI 标识用于说明来源与责任，不把星芒或渐变当装饰。

### 控件

- 主工具栏无阴影、无大胶囊背景、少边框。
- hover 反馈 75–160ms，状态变化 120–220ms。
- 不使用持续漂浮、缩放卡片、滚动劫持或全屏模糊。
- 核心导航始终可找到，不能只依赖 hover。

## 响应式

- ≥ 1280px：应用脊柱 + 上下文树 + 工作面 + 可选执行轨迹。
- 900–1279px：应用脊柱 + 可折叠上下文树 + 工作面；执行轨迹为抽屉。
- < 900px：任务、内容、预览分段呈现；项目树和执行轨迹进入抽屉。
- 画布在小屏仍保持沉浸式，不显示桌面四栏结构。

## 业务逻辑冻结线

本轮不得修改：

- API 请求契约与后端接口。
- Zustand store 数据结构与 localforage 持久化格式。
- 项目、分集、画布、素材绑定关系。
- 节点创建、拖拽、缩放、连线、生成、重试和归档动作。
- 图片/视频超分、插帧、字幕擦除的任务提交和费用逻辑。
- Invocation / Workflow 状态机和人工确认规则。
- 当前未提交的 `canvas-create-rail.tsx`、`canvas-tool-button.tsx` 与相关测试改动。

允许新增的仅是纯展示投影、布局状态和可折叠 UI 状态。

## 渐进落地

1. 基础：视觉 Token、应用脊柱、低视觉重量控件。
2. 首页：项目卡片墙改为编辑式工作流。
3. 项目：上下文树、阶段轨道、连续分集工作面。
4. 总控：任务状态与注意力流。
5. 画布：统一边缘控件与可折叠执行轨迹。
6. 后续：在不改旧节点数据的前提下评估生成谱系视图。

每一阶段都必须可独立使用和回滚，不要求一次性重写全站。

## 验收标准

- 用户从工作首页进入项目、分集、总控和画布最多需要两次明确点击。
- 桌面端主工作面宽度不被重复顶栏和卡片外框浪费。
- 导入、素材、整理画布、保存各只有一个主入口。
- AI 运行中的对象、状态和等待确认点可见。
- 所有付费生成仍需用户明确确认。
- 深浅主题下文本、选中态、错误和禁用态均可辨识。
- 不引入新的业务 store、API 字段或数据迁移。
- 不覆盖工作区中用户现有未提交改动。

## 不在本轮范围

- 重做生成模型、工作流引擎或后端任务系统。
- 云端同步本地项目和素材。
- 新增自动执行付费任务。
- 全量实现 Weave 式节点工作流。
- 品牌营销首页、3D/WebGL、全页 Liquid Glass。
