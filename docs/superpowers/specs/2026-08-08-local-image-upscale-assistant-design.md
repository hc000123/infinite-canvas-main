# 网页版画布本地图片超分助手设计

## 目标

为网页版画布增加使用本机算力执行图片超分的能力。首版面向 Apple Silicon Mac 与 Chrome，处理通用 AI 人物、场景和道具图片，提供 2×、4× 两种倍率。网页负责交互和画布数据，本地助手负责模型管理与推理；输入和输出图片不经过云端后端。

超分结果不得覆盖源图片节点。任务开始后在源节点右侧创建关联的图片子节点并连线，成功结果写入现有本地图片存储并自动归档到“资产”。节点与资产保留本地任务、引擎、模型、倍率、尺寸和耗时等追溯信息。

## 已确认范围

首版包含：

- 网页版画布调用独立安装的本地超分助手。
- macOS Apple Silicon ARM64 与 Chrome 首发支持。
- 通用 AI 图片的 2×、4× 超分，默认选择 2×。
- 助手连接检测、一次性配对、令牌鉴权和解除配对。
- 模型首次使用时按需下载，显示下载进度并校验文件完整性。
- 单任务串行队列、阶段进度、取消、错误显示和失败重试。
- 刷新页面后根据本地任务 ID 恢复仍存在的任务状态。
- 结果创建子图片节点、连接源节点并自动归档到“资产”。
- 结果节点保存完整本地处理元数据。

首版不包含 Safari、Intel Mac、Windows、局域网远程机器、多设备调度、云端任务中继、批量节点超分、人脸专用增强、动漫专用模型或自动付费调用。后续增加平台或模型时继续沿用相同助手协议，不改变画布业务入口。

## 方案选择

### 采用：浏览器直连回环地址上的本地助手

网页通过固定地址 `http://127.0.0.1:47821` 访问本地助手。助手只监听 IPv4 回环地址，接收图片 Blob、执行本地推理，并把结果 Blob 返回当前浏览器。Chrome 把回环地址视为本机可信目标；首次访问仍可能要求用户授予本地网络访问权限，界面必须说明权限用途并提供重新检测动作。

选择该方案的原因：

- 图片不需要上传项目后端，符合本地算力和隐私预期。
- 不引入云端设备队列、长连接和结果中继。
- 助手和推理引擎可以独立升级，未来可增加 Windows 引擎。
- 网页只依赖版本化 HTTP 协议，不依赖 Electron preload 或浏览器扩展。

### 未采用：浏览器 WebGPU 直接推理

WebGPU 不需要安装助手，但模型加载、显存控制、大图分块、页面生命周期和浏览器兼容性不够稳定。关闭或刷新页面也会直接中断任务，因此不作为首版主路径。

### 未采用：云端中继与本地助手主动领取任务

该方案可以避开浏览器访问本机的限制，但需要设备登录、云端队列、长连接、任务所有权和结果中继。实现与运维成本高，且图片可能经过服务器，不符合首版本地处理优先的目标。

## 总体架构

系统分为三个独立边界：

1. **画布集成层**：读取源图片、创建子节点、显示状态、持久化结果并归档资产。
2. **本地助手协议层**：负责检测、配对、模型状态、任务创建、进度订阅、取消和结果读取。
3. **本地推理层**：管理模型文件、临时输入输出、串行队列与原生超分进程。

网页不通过现有 Go 云端后端转发本地助手请求，云端数据库也不新增本地任务表。助手不读取画布、项目、用户或资产数据；它只处理单次请求携带的图片、倍率和任务标识。

## 本地助手

### 进程与存储

助手新增为独立 Go 命令 `cmd/upscale-assistant`，核心逻辑放在聚焦的 `localupscale` 包中。安装产物为 macOS ARM64 应用，启动后运行后台服务并可打开本地状态页。助手使用以下本机目录：

- `~/Library/Application Support/眨眼之间超分助手/config`：实例密钥、配对授权和版本信息。
- `~/Library/Application Support/眨眼之间超分助手/models`：已下载的版本化模型。
- `~/Library/Caches/眨眼之间超分助手/jobs`：任务临时输入、输出和日志。

配置文件权限限制为当前用户。任务成功、失败或取消后删除输入临时文件；输出保留到网页成功领取，最长保留 24 小时，之后由助手清理。助手不记录图片内容日志。

### 推理引擎

首版引擎固定为 MIT 许可证的 `realesrgan-ncnn-vulkan`，为 Apple Silicon 构建 ARM64 可执行文件并随助手安装。模型权重按需下载，推理通过独立进程适配器调用，便于未来替换为 Core ML 或增加 Windows 引擎而不改变 HTTP 协议。

首版模型 ID 固定为 `realesrgan-x4plus`。2× 与 4× 都由该模型能力提供，输出统一为 PNG。引擎启用自动 tile，避免直接把整张大图一次性放入显存。任务开始前校验输入类型、尺寸、输出像素上限和可用磁盘空间；超限时明确拒绝，不静默降级倍率。

模型清单随助手版本发布，包含模型 ID、版本、下载地址、文件大小和 SHA-256。下载写入临时文件，校验成功后原子移动到模型目录；中断下载保留可恢复信息。校验失败的文件不会进入可用状态。

### 队列与生命周期

第一版全局只执行一个推理任务，其他任务进入 FIFO 队列。任务状态为：

- `queued`
- `preparing`
- `downloading_model`
- `processing`
- `saving`
- `succeeded`
- `failed`
- `cancelled`

模型下载提供字节级百分比。原生引擎不能稳定报告精确 tile 百分比时，`processing` 使用不确定进度和已耗时，不伪造百分比。取消排队任务立即生效；取消执行中任务会终止子进程并清理临时文件。

任务快照持久化在任务目录中。助手重启后不伪装恢复正在执行的原生进程，而是扫描未结束快照并统一标记为 `failed`，错误代码为 `assistant_restarted`；网页可以从失败子节点重新提交。

## 本地协议与安全

### 固定端点

协议前缀为 `/v1`：

- `GET /v1/health`：助手版本、协议版本、平台、引擎状态。
- `POST /v1/pair`：使用一次性配对码换取访问令牌。
- `DELETE /v1/pairing`：撤销当前令牌。
- `GET /v1/models`：模型安装状态和下载状态。
- `POST /v1/models/{modelId}/download`：显式开始模型下载。
- `POST /v1/jobs`：以 `multipart/form-data` 提交图片、倍率和客户端任务 ID。
- `GET /v1/jobs/{jobId}`：查询任务快照。
- `GET /v1/jobs/{jobId}/events`：通过 SSE 接收状态和进度。
- `DELETE /v1/jobs/{jobId}`：取消任务。
- `GET /v1/jobs/{jobId}/result`：成功后读取结果图片。
- `POST /v1/jobs/{jobId}/result/ack`：网页确认结果已写入本地图片存储，助手随后删除输出临时文件。

除健康检查和配对外，接口都要求 `Authorization: Bearer <token>`。进度使用基于 `fetch` 响应流的 SSE 客户端，以便携带 Authorization 请求头，不把令牌放进 URL。错误响应使用稳定的 `code` 与中文 `message`，网页按错误代码决定重新配对、重试或展示原始原因。

`POST /v1/jobs` 以绑定 Origin 的 `clientTaskId` 保证幂等；相同客户端任务 ID 的网络重试返回原 `jobId`，不得重复排队。结果读取允许重复执行，只有收到 `result/ack` 或超过 24 小时后才删除输出，因此网页写入图片存储失败时可以重新领取。

### 配对

助手状态页展示短时有效、单次使用的配对码。用户在画布超分弹窗中输入配对码后，助手生成至少 256 bit 的随机令牌，并将令牌绑定到请求的精确 `Origin`。网页使用 user-scoped `localforage` 保存令牌，不使用 `localStorage`。

配对码有过期时间和失败次数限制。配对成功、过期或达到失败上限后立即失效。用户可从助手状态页撤销单个网站或全部网站授权。

### 网络边界

- 服务只绑定 `127.0.0.1`，不绑定 `0.0.0.0`、局域网地址或 IPv6 通配地址。
- `Host` 只接受固定回环主机与端口，拒绝其他 Host，降低 DNS rebinding 风险。
- 拒绝缺失 Origin、`Origin: null` 和非 HTTP(S) Origin。
- CORS 只回显已配对令牌绑定的精确 Origin；配对端点可以回显发起配对的精确 Origin，但仍要求有效一次性配对码。
- Chrome Private Network Access 预检仅对允许的端点返回所需响应，不开放通配凭据。
- 请求体、输入像素、输出像素和并发数都有硬限制。
- 固定端口被其他进程占用时助手启动失败并显示明确诊断，不切换到网页无法发现的随机端口。

生产站点需要在 CSP `connect-src` 中加入 `http://127.0.0.1:47821`。开发环境允许当前本地前端 Origin 通过同一配对流程，不设置开发专用免鉴权后门。

## 画布交互

### 入口与弹窗

已有内容的图片节点在悬浮工具栏和侧边检查器增加“本地超分”。现有空图片节点中的“图片高清”仍是云端图片预设入口，两者名称和行为保持明确区分，避免用户误以为本地超分会消耗云端算力。

本地超分弹窗沿用画布主题和现有 Modal 风格，显示：

- 本地助手：未检测、未配对、已连接、版本过低。
- 模型：未下载、下载中、可用、校验失败。
- 倍率：2×、4×，默认 2×。
- 原始尺寸与预计输出尺寸。
- 当前队列和本次任务进度。
- 安装助手、重新检测、输入配对码、下载模型、开始、取消和重试动作。

若助手未安装或未运行，弹窗提供 macOS ARM64 下载入口与重新检测，不自动跳转、不反复弹系统权限。

### 提交流程

1. 从 `storageKey` 读取现有图片 Blob；没有本地 Blob 时再读取节点可访问的 `content`。无法读取源图时停止并显示错误。
2. 冻结源节点 ID、源资产 ID、倍率、模型、输入尺寸和开始时间。
3. 创建一个位于源节点右侧的加载中图片子节点，并创建源节点到子节点的连接。
4. 把子节点 ID 作为客户端任务 ID 提交本地助手，随后把助手 `jobId` 写入子节点元数据。
5. 基于 `fetch` 流的 SSE 更新子节点的阶段、下载进度、队列位置和已耗时。
6. 成功后读取结果 Blob，通过现有 `uploadImage` 保存到 user-scoped 图片存储；保存成功后确认结果已领取。
7. 使用现有等比节点尺寸逻辑完成子节点，原始图片比例不变。
8. 调用现有资产写入链路自动归档结果，并把返回的资产 ID 写回子节点引用。

源节点在整个流程中保持不变。用户重复对同一源图超分时，每次都创建独立子节点和独立资产，不覆盖旧结果。

### 刷新恢复

画布节点自身持久化 `jobId` 和任务状态，不另建全局业务列表。页面 hydrate 后扫描未结束的本地超分节点：助手可用时查询任务并继续订阅；助手暂时不可用时保留节点并显示“等待本地助手”，用户可以重新检测。助手已丢失任务时将节点置为失败，并允许重试。

## 节点与资产元数据

`CanvasNodeMetadata` 增加独立的 `localUpscale` 快照：

```ts
type CanvasLocalUpscaleMetadata = {
  sourceNodeId: string;
  sourceAssetId?: string;
  clientTaskId: string;
  jobId?: string;
  status: "queued" | "preparing" | "downloading_model" | "processing" | "saving" | "succeeded" | "failed" | "cancelled";
  progress?: number;
  modelId: string;
  modelVersion?: string;
  engine: string;
  engineVersion?: string;
  assistantVersion?: string;
  scale: 2 | 4;
  inputWidth: number;
  inputHeight: number;
  outputWidth?: number;
  outputHeight?: number;
  startedAt: string;
  completedAt?: string;
  durationMs?: number;
  errorCode?: string;
};
```

结果节点同时沿用现有 `canvasSource`：`sourceNodeId` 指向源图，`sourceAssetId` 记录源资产，`originalImage` 保存源节点和本地存储引用，`generationParams` 保存本地超分快照。节点 `sourceType` 继续使用现有 `manual`，不把本地处理伪装为云端 AI 生成任务。

资产通过现有 `addCanvasNodeToAssets` 归档到当前项目资产文件夹。资产数据复用结果节点的 `storageKey`，不复制 Blob；`canvasSource` 保留本地超分的完整来源与参数。归档成功后回写结果节点 `sourceAssetId`。归档失败不删除已经完成的结果节点，并提示“图片已完成，本次未能归档到资产”，提供再次归档入口。

## 代码边界

### 本地助手

- `cmd/upscale-assistant/`：进程启动、信号和本机目录初始化。
- `localupscale/server.go`：HTTP 路由、CORS 和请求限制。
- `localupscale/pairing.go`：配对码、令牌、Origin 绑定与撤销。
- `localupscale/models.go`：模型清单、下载、断点和校验。
- `localupscale/jobs.go`：串行队列、状态、保留与清理。
- `localupscale/engine.go`：推理引擎接口与子进程适配器。
- `localupscale/status_page.go`：本机状态、配对和授权管理页面。

本地助手不复用项目主后端的数据库、登录和业务 service，也不把路由塞入现有 `router/`。它与主后端只共享必要的通用 Go 依赖。

### 网页画布

- `web/src/services/local-upscale/`：协议类型、令牌存储、HTTP/SSE 客户端和错误映射。
- `web/src/app/(user)/canvas/hooks/use-canvas-local-upscale-actions.ts`：源图读取、任务创建、进度恢复、结果落盘和资产归档。
- `web/src/app/(user)/canvas/utils/canvas-local-upscale.ts`：子节点、连接、状态和完成结果的纯转换。
- `web/src/app/(user)/canvas/components/canvas-local-upscale-modal.tsx`：连接、配对、模型和倍率界面。

`canvas-client-page.tsx` 继续作为装配层，只接入 hook、Modal 状态和工具栏动作。本地超分不得并入云端图片生成 API，也不扩张现有生成配置节点语义。

## 错误与边界处理

- **助手未安装或未启动**：不创建任务节点，展示下载与重新检测。
- **Chrome 拒绝本地网络权限**：说明如何在站点权限中重新开启，不把它报告为模型错误。
- **未配对或令牌撤销**：要求重新配对，不自动循环重试。
- **协议版本不兼容**：提示升级助手，禁止提交任务。
- **模型下载失败**：保留可恢复下载状态，展示网络或校验错误。
- **输入图片无法读取**：不创建子节点；源节点不变。
- **输入或预计输出超限**：在提交前阻止，并显示具体尺寸限制。
- **任务提交后断线**：保留子节点和 `jobId`，恢复连接后继续查询。
- **推理失败或内存不足**：子节点进入失败态，保留错误代码和重试入口。
- **用户取消**：终止本地任务，子节点保留取消状态；重试创建新任务并复用该节点位置。
- **结果下载或本地保存失败**：助手暂存输出，网页允许重新领取，不重复执行推理。
- **资产归档失败**：结果节点仍成功，归档状态单独提示并可重试。

## 测试与验收

### 本地助手单元与协议测试

- 服务只监听回环地址，非法 Host、Origin 和无令牌请求被拒绝。
- 配对码单次有效、会过期、有失败次数限制，令牌严格绑定 Origin。
- CORS 与 Private Network Access 预检只对允许场景返回正确头。
- 模型下载支持进度、恢复、SHA-256 校验和原子落盘。
- 假推理引擎覆盖排队、成功、失败、取消、重启失败和结果领取。
- 输入类型、请求体、像素、输出尺寸和磁盘空间限制有效。
- 任务结束及过期后临时文件按规则清理。

### 网页纯函数与交互测试

- 只对有内容的图片节点显示“本地超分”。
- 2×、4× 预计尺寸与元数据正确。
- 提交后创建一个子节点和一条源到子的连接，源节点不变。
- 进度事件只更新对应任务节点，切换选中节点不会串任务。
- 成功 Blob 通过 `uploadImage` 落盘，节点保持原图比例。
- 成功后调用资产归档并回写资产 ID；归档失败不回滚图片节点。
- 页面刷新可按 `jobId` 恢复，任务丢失进入可重试失败态。
- 取消、推理失败、结果领取失败和令牌失效分别显示准确状态。

### 人工验收

1. 在 Apple Silicon Mac 安装并启动助手，从 Chrome 网页版画布完成本地网络授权和配对。
2. 首次执行时确认模型按需下载、进度可见、下载文件通过校验且再次使用不重复下载。
3. 分别对本地上传图和已有生成图执行 2×、4×，输出像素尺寸准确。
4. 确认源节点未被修改，右侧生成子节点和连接，结果刷新后仍可显示。
5. 在“资产”中确认结果已归档到当前项目，并可追溯源节点、源资产、模型、倍率、尺寸和耗时。
6. 使用浏览器网络面板确认图片请求只访问 `127.0.0.1`，不上传项目后端。
7. 覆盖助手未启动、拒绝权限、模型下载中断、助手重启、内存不足、取消、结果领取失败和资产归档失败。
8. 浅色与深色画布主题下确认弹窗、工具栏、进度和错误信息可读。
