# 画布规模稳定性一期设计

## 背景与结论

当前画布没有节点硬上限，已有验证覆盖 300 个轻量节点，但复杂媒体、历史版本、配置节点和密集连线会显著放大成本。第一期不阻止用户继续创建节点，而是建立可见容量指标，并消除最明显的全量计算、全量连线渲染和节点重叠风险。

## 方案选择

### 方案 A：只增加节点硬上限

实现最简单，但节点数量不能代表真实压力：100 个多版本视频可能比 300 个文本节点更重，并且无法解决已经存在的卡顿和重叠。

### 方案 B：渐进式加固（采用）

先增加容量观测和软预警，再优化连线裁剪、生成输入索引和节点放置。改动不改变画布数据结构，可独立回滚，适合当前仍在持续开发的本地画布。

### 方案 C：立即拆分存储并重写画布状态

长期收益最大，但会同时影响持久化、媒体恢复、历史版本和素材库引用，第一期实施风险过高。

## 一期范围

### 1. 容量指标与软预警

新增纯计算容量快照，统计：

- 节点数；
- 连线数；
- 生成配置节点数；
- 图片、视频、音频节点数；
- 媒体历史版本数；
- 按唯一 `storageKey` 去重后的本画布媒体字节数；
- 浏览器当前 origin 的总存储用量与配额（支持 `navigator.storage.estimate()` 时）。

顶部工具栏以低视觉重量展示“节点 N · 连线 M”。达到软阈值时显示黄色或红色状态，点击后打开容量详情。详情明确区分“本画布媒体估算”和“浏览器全部本地缓存”，不把浏览器总用量误写成当前画布用量。

软阈值：

- 节点：200 警告，300 严重；
- 连线：400 警告，800 严重；
- 历史媒体版本：200 警告，400 严重；
- 浏览器配额使用率：70% 警告，90% 严重。

阈值只提示，不阻断新建、粘贴、导入或生成。

### 2. 节点与连线视口裁剪

抽出统一的世界坐标视口边界计算。节点继续使用 280 世界单位预加载边距；连线使用更大的 600 世界单位边距，并按起点、终点形成的包围盒与视口相交关系裁剪。

以下连线始终保留：

- 当前选中的连线；
- 当前高亮关联连线；
- 正在拖拽创建的临时连线。

隐藏批次子节点的判断改用既有 `nodeById`，避免每条连线再次扫描全部节点。

### 3. 生成输入拓扑索引

新增画布生成输入索引：一次遍历节点建立 `nodeById`，一次遍历连线建立 `incomingConnectionsByTarget`。所有配置节点从同一个索引构建上游输入，不再为每个配置节点重复扫描全部节点和连线。

索引只改变计算路径，不改变：

- `inputOrder` 顺序；
- `referenceRoles` 和首尾帧角色；
- 文本、图片、视频、音频识别；
- 提交 payload。

现有单节点 API 保留，由它内部创建一次索引，以免扩大调用方改动。

### 4. 节点放置可靠性

自动避让搜索结束后不得返回未经重叠检查的位置。通用环形放置继续使用现有 24 圈搜索；向右派生放置最多检查“已有节点数 + 25”个候选位置。

如果固定搜索仍未找到空位，两条路径统一返回全部节点最右边界加间距的位置。该位置在横向上必定与现有节点分离，不再使用可能已占用的固定兜底点。

## 数据流

1. 页面节点或连线变化时计算容量快照和生成输入索引。
2. 视口变化时只重新计算可见节点、可见连线，不修改持久化数据。
3. 顶部容量入口读取快照；浏览器存储估算异步刷新，失败时只隐藏配额信息。
4. 节点创建、粘贴或派生结果继续使用现有动作，放置工具负责保证最终位置不重叠。

## 错误与降级

- 浏览器不支持存储估算或调用失败：仍显示节点、连线、版本和本画布媒体估算。
- 节点引用缺失：连线按现有行为不渲染，不影响其他连线。
- 容量达到严重级别：仅提示拆分画布或清理版本，不自动删除数据。
- 可见连线判断异常时，选中和关联连线仍强制渲染，保证用户可以取消选择或删除。

## 测试

- 容量统计：去重媒体字节、阈值边界、配额降级。
- 视口裁剪：视口内、视口外、跨越视口、选中和关联连线。
- 生成输入索引：与旧 API 输出完全一致，覆盖混合媒体顺序与首尾帧。
- 节点放置：超过原 24 次向右候选后仍不重叠，极端密度返回边界外安全位置。
- 接线测试：顶部容量入口和连接层使用新的纯工具。
- 完成后运行前端全量测试、TypeScript 检查和 `git diff --check`。

## 二期边界

以下内容不在一期修改：

- 媒体历史版本按需恢复；
- Blob URL 生命周期统一释放；
- 每个画布独立持久化；
- 撤销历史改为操作补丁。

这些改动需要独立的数据恢复设计。第一期上线后的容量数据将用于决定二期顺序和验收规模。
