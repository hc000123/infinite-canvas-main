# 缓存视频长期收藏设计

## 目标

在现有缓存管理页中，让素材名称始终可见，并允许用户长期收藏生成视频，随后通过“只看收藏视频”快速筛选、批量选择和下载结果。

本次只增强缓存文件的展示、收藏和筛选，不改变媒体生成、缓存归档、预览、项目打包或下载协议。

## 已确认交互

- 保留卡片左上角的批量选择框，继续服务于“全选当前结果”和“下载所选”。
- 仅视频卡片右上角显示收藏星标；图片和音频不显示收藏入口。
- 收藏状态长期保存在服务端，刷新页面、重启服务或换浏览器登录后仍然存在。
- 素材名称固定显示在缩略图下方，最多展示两行；超长名称保留完整 `title` 提示。
- 筛选区增加“只看收藏视频”。开启后只显示状态正常且已收藏的视频，并继续与关键词、分集、分类和类型筛选组合。
- 用户在收藏结果中继续使用现有“全选当前结果 → 下载所选”，不新增重复下载入口。

## 数据模型

`ProjectCacheFile` 增加：

```text
favorite: boolean
```

收藏状态与缓存文件记录存放在同一项目缓存清单中，不新增数据库表或独立收藏文件。未包含该字段的清单按布尔零值处理为未收藏。

未归属缓存移动到项目时需要把原文件的收藏状态传入归档流程，确保移动后仍为收藏。删除缓存文件时，其收藏状态随文件记录一起移除。项目缓存打包清单自然包含该字段，但媒体内容和打包格式保持不变。

## 服务端接口

新增登录鉴权接口：

```text
POST /api/v1/project-cache/files/:id/favorite
```

请求体：

```json
{ "favorite": true }
```

接口只允许修改当前登录用户拥有的缓存文件。服务层复用现有缓存路径约束、用户隔离和清单写入方式，更新成功后返回最新的 `ProjectCacheFile`。

收藏接口不接受文件名、路径或用户 ID，不允许收藏其他用户的文件。文件不存在或清单不可写时返回项目统一的安全错误结构。

## 前端结构

### 缓存页

`cache/page.tsx` 增加收藏筛选状态和收藏更新动作：

- 收藏请求成功后，用服务端返回记录更新当前 `manifest.files`。
- 请求期间只禁用正在处理的星标，其他卡片保持可操作。
- 请求失败时不提前改变本地收藏状态，并显示错误提示。
- 切换项目时重置“只看收藏视频”，避免用户进入另一个项目后误以为缓存为空。

### 视图模型

`filterProjectCacheFiles` 增加收藏筛选条件。收藏筛选必须与现有分集、分类、类型和关键词条件同时生效，并隐式限定 `kind === "video"` 与 `status === "ready"`。

### 卡片

`CacheFileGrid` 接收收藏回调和正在更新的文件 ID：

- 左上角复选框仍代表临时批量选择。
- 右上角星标代表长期收藏，使用不同图形、提示文案和无障碍标签，避免与复选框混淆。
- 星标点击不触发卡片预览。
- 状态正常的视频可以收藏；缺失视频若已有收藏则显示收藏状态但禁用星标操作。
- 素材名称使用固定的两行标题区域，卡片高度保持一致。

## 状态与错误处理

- 收藏以服务端响应为准，不使用乐观更新，避免请求失败后出现假收藏。
- 重复提交同一收藏状态按幂等更新处理。
- 缺失文件不进入收藏筛选结果；如果历史清单中缺失文件已被收藏，状态仍保留，便于文件恢复后重新出现。
- 文件移动时保留收藏，删除后不保留孤立收藏记录。
- 收藏失败不影响预览、选择、下载和其他筛选。

## 测试

服务端测试覆盖：

- 收藏与取消收藏写入清单并可重新读取。
- 重复设置相同状态保持幂等。
- 用户不能修改其他用户的缓存文件。
- 未归属文件移动后保留收藏状态。
- 路由与响应结构符合现有 API 约定。

前端测试覆盖：

- 收藏筛选只返回状态正常的收藏视频。
- 收藏筛选与关键词、分集、分类和类型组合生效。
- 视频卡片显示星标，图片和音频不显示。
- 素材名称使用常驻两行区域。
- 现有批量选择、全选当前结果和单个/批量下载接线保持不变。

## 非目标

- 不在资产库或画布节点同步收藏状态。
- 不新增收藏分组、排序、备注或批量收藏。
- 不为图片或音频开放收藏。
- 不修改生成任务、媒体文件内容和项目缓存目录结构。
