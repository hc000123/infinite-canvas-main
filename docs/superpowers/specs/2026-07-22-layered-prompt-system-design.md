# 分层提示词系统设计

## 目标

将当前以搜索、复制和收藏为主的提示词库，升级为直接参与图片与视频生产的“提示词配方台”。系统需要同时承载：

- 公司统一标准：品牌、质量、合规和模型约束，由管理员维护。
- 项目风格：当前项目的画风、色彩、镜头、光线、材质与一致性要求。
- 个人习惯：个人常用的表达、质量增强词和负面约束，仅保存在当前浏览器用户空间。
- 任务内容：本次需要生成的角色、场景、画面或视频镜头描述。

成功标准不是“提示词数量更多”，而是用户在生图、画布和视频创作时，能用较少输入稳定得到符合公司和项目要求的最终提示词，并能看清每一段内容来自哪里。

## 当前问题

当前提示词库已经具备模板变量、图片/视频分组、用途、场景、标签、常用筛选和插入能力，但本质仍是一个扁平卡片列表：

- 提示词只有“找到并整段插入”，无法与项目风格和个人习惯组合。
- “常用”是管理员写入模板元数据的全局布尔值，不是每位用户自己的使用习惯。
- 普通用户不能沉淀自己的可复用提示词，只能复制或加入“我的素材”。
- 提示词与项目没有绑定关系，切换项目后仍需手动寻找并追加相同风格词。
- 公司标准、项目风格、普通灵感模板混在一个列表里，缺少继承和锁定关系。
- 视频结构化提示词有严格字段约束，不能简单在最终文本末尾追加任意风格句。

## 方案比较

### 方案 A：强化现有资料库

继续增加文件夹、标签、收藏、最近使用和推荐排序。

优点是改动小；缺点是用户仍需反复检索、复制和拼接，公司标准也不能自动生效。它只能让资料更好找，不能让生产更稳定。

### 方案 B：分层风格包与提示词合成器（采用）

保留现有模板库，同时增加公司、项目、个人三层配置。生成或插入时由合成器组合任务内容和各层生效规则，并展示来源。

优点是能直接复用现有 Prompt 数据和本地项目存储，增量实现；结果可解释，用户仍能编辑。缺点是需要定义层级、作用范围和视频应用规则。

### 方案 C：自动学习个人习惯的提示词 Agent

从历史生成、编辑和最终采用结果中学习偏好，再自动改写提示词。

长期价值高，但第一版需要行为采集、隐私边界、反馈闭环和质量评估，且自动改写难以解释。适合作为分层系统稳定后的增强，不作为当前实现基础。

## 核心模型

### 1. 公司提示词

继续由后端 `prompts` 表和管理员页面维护。现有普通记录默认仍是“模板”，不自动应用。`metadata` 增加以下可选字段：

| 字段 | 值 | 作用 |
| --- | --- | --- |
| `kind` | `template`、`standard` | 区分可选模板和公司规则 |
| `policy` | `required`、`recommended`、`optional` | 必选、默认推荐或手动使用 |
| `slot` | `style`、`camera`、`lighting`、`quality`、`negative`、`format`、`constraint` | 标明内容在配方中的用途 |
| `enabled` | boolean | 是否参与生产 |

图片或视频范围继续使用现有 `nodeGroup`，不再增加重复的媒体字段。旧数据没有新增字段时按 `kind=template`、`policy=optional` 处理，不会突然自动插入。

### 2. 项目风格包与个人习惯包

新增浏览器本地 `PromptProfile`：

```ts
type PromptProfile = {
    id: string;
    name: string;
    scope: "project" | "personal";
    projectId?: string;
    nodeGroup: "image" | "video";
    blocks: Array<{
        id: string;
        title: string;
        slot: "style" | "camera" | "lighting" | "quality" | "negative" | "format" | "constraint";
        content: string;
        enabled: boolean;
    }>;
    createdAt: string;
    updatedAt: string;
};
```

同一项目可保存多个图片或视频风格包，但每种媒体最多启用一个。个人层同样每种媒体最多启用一个习惯包。数据使用 `localforage` 并按当前登录用户隔离，与项目和“我的素材”的本地存储边界保持一致。

### 3. 合成结果

合成器输入本次任务文本、可选模板、匹配的公司规则、当前项目风格包和当前个人习惯包，输出：

- `text`：可直接插入编辑器的最终文本。
- `sections`：每段的来源、用途、是否锁定和原始内容，用于界面解释。
- `warnings`：变量未填写、项目未选择、公司必选规则读取失败等提示。

合成器只做纯文本规划和去重，不读取 store、不弹消息、不发请求。

## 层级与冲突规则

正向内容按以下语义组合：

1. 本次任务内容：描述要生成什么。
2. 项目风格：约束这部作品整体长什么样。
3. 个人习惯：补充个人偏好，但不能替换公司锁定项。
4. 公司规则：质量、合规、品牌和输出要求；`required` 项不可关闭。

完全相同的段落只保留一次。系统不尝试理解并自动解决语义冲突；当不同层同时出现明显相反词时保留来源标记，让用户在预览中处理。第一版不做 AI 改写，避免不可解释的内容变化。

公司 `recommended` 规则默认开启但可在当次合成中关闭；`optional` 规则只在用户明确选择时加入。个人和项目 block 均可逐项启停。

## 图片与视频的不同应用方式

### 图片

图片提示词可直接合成。生图工作台、画布图片节点和图片 Brief 入口在用户选择模板后展示“本次将应用”的公司、项目、个人层，确认后把完整文本写入当前提示词输入框。生图工作台若来自项目资产或 Brief，应自动带入 `projectId`；独立生图时只应用公司与个人层。

### 视频

普通视频节点或空白视频提示词可以直接使用合成结果。已有严格结构的 Seedance / Copy-only 提示词不能在末尾机械追加风格段落：

- 在生成结构化视频提示词之前，将公司标准、项目视频风格和个人视频习惯作为“风格上下文”提供给上游提示词生成步骤。
- 最终视频提示词继续遵守既有字段、时长、引用图和连续性校验。
- 对已经生成的结构化提示词，界面只允许“重新按当前风格生成”或把片段插入对应字段，不提供无脑自动追加。

第一阶段先打通提示词中心、选择弹窗、生图与画布节点；视频工作流只建立可读取的项目视频风格上下文和预览，不修改已确认生产包。第二阶段再接入视频提示词生成服务。

## 页面与交互

### 提示词中心

默认入口从“灵感检索”改为“当前生效”：

- 未指定项目时，显示公司标准与我的习惯。
- 指定项目时，显示公司标准、项目图片风格、项目视频风格和我的习惯。
- 每层显示启用数量、锁定状态和最终合成预览。
- “全部模板”保留现有搜索、筛选和卡片列表，作为次级入口。

普通用户可以新建、编辑和删除自己的习惯包；项目成员可以编辑本地项目风格包。公司标准和公共模板仍只有管理员可修改。

### 选择弹窗

弹窗顶部增加当前上下文条，例如“公司 2 项锁定 · 项目《重逢》图片风格已启用 · 我的习惯 3 项”。选中模板后先进入合成预览，再执行“应用完整配方”；同时保留“仅插入模板”以支持临时试验。

### 管理后台

现有提示词表单增加“记录类型、执行策略、内容位置、是否启用”。只有 `kind=standard` 时展示执行策略；模板仍沿用现有变量、场景和模型字段。

## 数据流

1. 页面根据媒体类型和可选 `projectId` 读取当前上下文。
2. 前端从 `/api/prompts` 读取匹配媒体的公司规则和公共模板。
3. 本地 profile store 读取当前项目风格包与个人习惯包。
4. 用户输入本次任务或选择模板并填写变量。
5. 纯函数合成器输出带来源的 sections、最终文本和 warnings。
6. 用户应用后，调用现有 `onSelect` 或写入对应提示词编辑器，不改变生成 API 协议。

## 错误处理

- 公司规则读取失败时，禁止把结果标成“符合公司标准”，并显示可重试警告；仍允许用户只使用本地项目和个人内容进行草稿编辑。
- 本地 profile 尚未完成 hydration 时不提前合成，避免短暂漏掉个人或项目规则。
- 项目不存在或已删除时忽略对应项目风格包，不自动转成个人习惯。
- 必填模板变量未填写时保留变量标记并阻止“应用完整配方”，但允许复制草稿。
- 空 block、重复 block 和只有空白的 profile 在保存时清理。

## 实施边界

第一阶段包含：

- 扩展提示词元数据和管理员编辑字段。
- 新增本地 profile store、标准化函数和纯合成器。
- 提示词中心增加当前生效视图和图片/视频风格包编辑。
- 提示词选择弹窗增加来源预览、完整配方与仅模板两种应用方式。
- 生图工作台传入来源项目；画布沿用现有 `projectId`。
- 提供视频风格上下文读取接口，但不直接改写已确认视频生产包。

第一阶段不包含：

- 云同步个人习惯和本地项目风格。
- 根据生成历史自动学习或自动改写提示词。
- 多人协同编辑项目风格。
- 复杂权限、审批流、灰度发布和旧字段迁移。
- 对已确认结构化视频提示词做文本尾部注入。

## 验收要点

- 没有新增元数据的旧提示词仍按普通模板展示，且不会自动应用。
- 管理员能创建图片或视频公司标准，并设置必选、推荐或可选。
- 普通用户不登录管理员账号也能创建个人习惯包和项目风格包。
- 同一项目的图片与视频可以选择不同风格包，切换项目后生效配置随之变化。
- 图片模板变量填写后，合成预览明确标出任务、项目、个人和公司四层来源。
- 公司必选规则不能在普通用户界面关闭。
- “仅插入模板”保持当前行为；“应用完整配方”插入去重后的组合文本。
- 公司规则接口失败时出现明确警告，不误报为符合公司标准。
- 结构化视频生产包不会被自动追加文本，也不会因此破坏现有校验。
