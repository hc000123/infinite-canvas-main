# 模型渠道配置界面适配设计

## 状态与替代关系

本设计替代 `2026-07-30-model-configuration-management-design.md` 作为后续模型配置优化的实现依据。`codex/model-configuration-management` 分支中的 Provider Connection、Model Deployment、部署 ID 路由和公开模型目录方案保持隔离，不合并、不 cherry-pick，也不作为本设计的增量基础。

## 背景

当前主线已经稳定支持 OpenAI 兼容、Volcengine Ark、Jimeng CLI 和 Xinglian Cloud。它们在鉴权、模型标识、任务提交、状态查询、用户登录和预检方面存在真实差异。主线以 `ModelChannel` 保存这些差异，并通过 `SelectModelChannel`、`PreflightModelChannel` 和协议专用执行器完成调用。

此前方案把运行时改成统一部署 ID 和适配器，破坏了同模型同协议渠道的权重与 fallback、火山模型到 EP 的映射、即梦用户登录态以及各视频协议专用任务流程。本轮只优化管理员配置和普通用户模型选择，不改变已经正常运行的渠道结构与调用链。

## 目标

- 用分步向导降低管理员新增和编辑模型渠道的复杂度。
- 让普通用户按文本、图片、视频筛选模型，并看清模型所属渠道和算力点。
- 保留主线现有设置结构、公开配置、节点请求参数、渠道选择和协议执行器。
- 视频渠道只执行现有连接或环境预检，不通过真实视频生成验证配置。

## 非目标

- 不新增 Provider Connection、Model Deployment、部署 ID、发布状态或模型目录数据结构。
- 不新增 `/api/model-catalog`，不修改 `/api/v1` 模型代理协议。
- 不修改 Agent Run、Invocation、Workflow、画布、图片或视频的运行时路由。
- 不取消现有渠道权重、显式渠道绑定或 fallback。
- 不把不同协议下的同名模型强行统一为一个运行时模型。
- 不建设新的测试、计费、任务或日志体系。

## 稳定性边界

下列主线能力是兼容边界，实施时保持现有语义：

- `model.ModelChannel` 和 `PublicModelChannelSetting` 继续作为配置真相。
- `/api/admin/settings` 继续读写完整管理员设置，API Key 掩码与留空保留规则不变。
- `/api/settings` 继续向普通用户输出可用模型、默认模型、协议、能力、来源和文本接口类型。
- `SelectModelChannel` 与 `SelectModelChannelWithOptions` 继续按模型、渠道 ID、能力、权重和 fallback 选择渠道。
- `BuildModelChannelURL`、`handler/ai.go`、Agent Run 和 Invocation 继续使用当前调用路径。
- Volcengine Ark、Jimeng CLI、Xinglian Cloud 和 OpenAI 兼容执行器继续独立处理提交、查询、下载与错误。

实施阶段不得修改上述运行时文件来适配新界面；界面必须适配现有接口，而不是让运行时适配界面。

## 管理员配置界面

### 信息架构

系统设置继续区分公开配置和私有渠道，但私有渠道的新增与编辑改为四步向导：

1. **选择渠道类型**：OpenAI 兼容、Volcengine Ark、Jimeng CLI、Xinglian Cloud。
2. **填写连接信息**：只显示该协议真实需要的字段。
3. **配置模型**：读取厂商模型列表或使用协议内置候选；管理员选择需要保存的模型。
4. **确认使用范围**：设置渠道能力、公开模型、文本接口类型和默认模型。

向导编辑的是现有 `AdminModelChannel` 草稿。完成时仍通过现有管理员设置保存接口写入 `private.channels` 和 `public.modelChannel`，不引入第二份配置真相。

### 协议专属字段与检测

- **OpenAI 兼容**：配置名称、Base URL、API Key、模型、能力和权重；文本模型保留 Chat Completions / Responses 选择，图片模型保留当前请求入口。管理员主动执行文本或图片模型测试时，继续使用现有测试接口。
- **Volcengine Ark**：配置 Base URL、API Key，以及每个可见模型对应的 EP。检测只调用现有企业 API 鉴权预检，不创建视频任务。
- **Jimeng CLI**：配置 CLI 路径、工作目录、输出目录和模型。管理员只检测 CLI 安装、版本和模型支持，不要求管理员登录，也不生成视频；普通用户继续通过现有配置弹窗完成个人登录。
- **Xinglian Cloud**：配置 Base URL、API Key 和模型。检测继续使用现有余额或服务预检，不创建视频任务。

渠道保存成功不等于自动公开。第四步必须明确选择要加入 `availableModels` 的模型，并分别设置文本、图片、视频默认模型；未公开的私有渠道模型不出现在普通用户选择器中。

### 编辑与密钥保护

- 编辑已有渠道时读取并提交原渠道 ID，避免创建重复渠道。
- 已保存 API Key 继续只显示掩码；留空或提交掩码时保留原密钥。
- 修改渠道名称、备注、环境、权重等非连接字段不触发模型调用。
- 删除、启停和保存仍使用现有整份设置校验，保留同名模型跨协议冲突等主线规则。

## 普通用户模型选择

前端继续从 `/api/settings` 读取 `availableModels`、`modelProtocols`、`modelCapabilities`、`modelSources`、`modelTextEndpoints` 和三类默认模型，不读取私有渠道或密钥。

模型选择器按文本、图片、视频能力展示，并使用现有模型名称作为选中值和节点请求参数。选项显示：

- 模型名称。
- 渠道名称；同模型有多个同协议来源时显示来源数量或来源摘要，不把渠道 ID 替换成模型值。
- 算力点及文本按次、图片按张、视频按秒的单位。

选择模型后，前端继续通过现有协议元数据确定 UI 参数；真正请求到达后端后，仍由现有渠道选择逻辑决定具体渠道。已选模型不再公开时，沿用当前同类型默认模型回退规则。

## 数据流

```text
管理员向导
  -> 现有 /api/admin/settings
  -> private.channels + public.modelChannel
  -> 现有 /api/settings 派生公开元数据
  -> 普通用户模型选择器
  -> 节点继续提交原模型名称
  -> SelectModelChannel / 显式渠道绑定 / fallback
  -> 各协议原有专用执行器
```

界面层不生成部署 ID，不重写模型名称，不保存运行时适配器，也不绕过现有渠道选择。

## 错误处理

- 连接信息无效时停留在向导第二步，显示现有脱敏错误。
- 厂商不支持模型列表时允许手动填写模型，但明确标记为手动配置。
- 火山模型缺少 EP 时阻止完成配置。
- 视频预检失败只说明连接、鉴权、CLI 环境或余额问题，不执行付费生成来进一步判断。
- 同一模型被配置到不同协议时继续使用主线冲突校验并阻止保存；同协议多渠道保持可用。
- 公开模型没有可用私有渠道、默认模型不在公开列表等情况继续使用现有设置校验和页面警告。

## 实施顺序

1. 只重组管理员渠道新增与编辑 UI，保存载荷与现有接口保持一致。
2. 优化公开模型选择器的分类、渠道名称和算力点展示。
3. 回归现有渠道、节点和工作流，不修改运行时来修补界面问题。

每一步单独提交并可独立回退。不得从 `codex/model-configuration-management` 复制运行时代码。

## 验证范围

### 自动验证

- 向导对四种协议生成的最终设置载荷与当前 `AdminSettings` 契约一致。
- 编辑渠道保留 ID、密钥掩码语义、EP 映射、能力、权重和环境。
- 视频渠道检测只命中既有预检函数，不命中视频任务创建路径。
- 模型选择器按能力过滤，展示渠道来源和算力点，但提交值仍为原模型名称。
- 现有 `SelectModelChannel`、fallback、火山 EP、即梦用户登录、星链云和节点调用测试不修改断言并继续通过。

### 人工验证

1. 使用当前已正常运行的四类渠道配置打开和保存向导，确认保存前后私有渠道关键字段不变。
2. 新增一个 OpenAI 兼容渠道，配置文本与图片模型，确认原节点可调用。
3. 打开火山渠道，确认模型与 EP 一一对应；执行预检后直接保存，不生成视频。
4. 打开即梦 CLI 渠道，确认管理员检测不要求登录；普通用户仍能使用原网页登录流程。
5. 打开星链云渠道，确认只执行原预检，视频提交与查询仍走原专用路径。
6. 为同一模型配置两个同协议渠道，确认权重、显式渠道和 fallback 行为保持不变。
7. 在画布、图片页、视频页、Workflow 和 Skill 中分别调用原有模型，确认请求参数与改造前一致。
