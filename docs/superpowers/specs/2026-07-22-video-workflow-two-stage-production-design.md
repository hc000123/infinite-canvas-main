# 视频工作流两阶段生产台设计

## 目标

将当前分散的“导演与美术、资产准备、分镜提示词、视频生成”重新组织为两个用户可理解的业务阶段：

1. **资产设计**：从确认稿提取资产描述，分配稳定资产编号，生成或匹配资产图片，并把图片版本绑定到资产编号。
2. **镜头生产**：展示生产包对应的原剧本，拆分并编辑具体分镜，在人工确认后结合剧本、资产图片与连续性参考生成提示词，最后调用视频模型生成视频。

剧本确认和审核交付继续保留，因此用户侧主流程为：

`剧本确认 → 资产设计 → 镜头生产 → 审核交付`

本设计不修改画布，也不新增或复制后台模型设置。

## 设计原则

- 页面阶段按创作任务组织，后台任务按可追踪、可重试、可替换 Skill 的边界组织。
- 资产描述、资产图片、分镜、提示词和视频必须逐级确认，后一步不能绕过前一步。
- 图片理解是提示词生成的正式输入，不允许仅用资产名称或文字描述代替可用图片。
- 上一镜尾帧是下一镜的剧情连续性参考，不是下一镜的强制首帧。
- 任何会触发图片或视频模型费用的动作都需要明确确认。
- 本地开发可以显式使用 Codex CLI 完成文本和图片理解验证；生产环境必须固定使用企业 API。

## 用户侧信息架构

### 主阶段

| 阶段 | 目的 | 完成条件 |
| --- | --- | --- |
| 剧本确认 | 锁定本集生产稿 | 存在不可变剧本快照 |
| 资产设计 | 得到可追踪且有正式图片的角色、场景、道具、服装资产 | 必需资产均已确认图片版本 |
| 镜头生产 | 完成分镜、提示词、视频和连续性参考 | 必需镜头均有已确认提示词和成功视频 |
| 审核交付 | 检查阻断项并导出 | 所有交付门禁通过 |

### 资产设计页面

页面使用“筛选栏 + 资产卡片工作区 + 任务/详情区”的结构。

- 筛选栏展示角色、场景、道具、服装分类及完成数量。
- 资产卡展示：稳定资产编号、名称、类型、原剧本证据、资产描述、生图提示词、绑定图片、图片版本、确认状态。
- 单卡动作包括：选择已有图片、单独生图、进入图片工作台精修、替换图片、确认资产。
- 用户可勾选多个待生图资产，统一确认模型与费用后批量生成。
- 图片生成或匹配结果回写原资产记录，不创建无法追踪的平行资产。
- 图片工作台通过 `libraryAssetId` 和逻辑资产编号回写，并保留 `returnTo` 返回路径。

### 镜头生产页面

桌面端使用三栏结构，分镜队列只存在于本页面。

#### 左栏：分镜队列

- 显示镜头编号、场次、原剧本摘要、当前状态、连续性关系。
- 支持搜索、状态筛选、键盘切换和长列表窗口化。
- 状态至少区分：待拆分、待修改、待确认分镜、待生成提示词、待确认提示词、可生成视频、生成中、已完成、阻断。

#### 中栏：镜头编辑链

按固定顺序展示：

1. 当前生产包对应的原剧本片段，只读并保留来源位置。
2. 可编辑具体分镜，包括景别、机位、镜头运动、主体动作、人物表演、对白/声音、时长和衔接方式。
3. 分镜确认动作。
4. 多模态提示词生成动作。
5. 可编辑最终提示词和确认动作。

未确认分镜不能生成提示词；分镜或参考版本发生变化后，既有提示词立即标记为过期。

#### 右栏：参考与视频结果

- 正式资产参考图，按角色、场景、道具、服装分组。
- 上一镜尾帧连续性参考及来源视频版本。
- 视频模型、时长、分辨率、画幅等本镜头实际参数。
- 通道预检、费用确认、生成、停止/同步、当前视频和历史版本。
- 每个成功视频展示其尾帧资产及下一镜引用状态。

窄屏时左栏和右栏变为抽屉，中间编辑链保持完整。

## 后台任务与 Skill 边界

用户只看到两个业务阶段，但后台保留独立子任务：

1. `asset-extraction`：从确认稿提取资产、剧本证据和稳定逻辑编号。
2. `asset-image-prompt`：把已确认资产描述转换为图片模型提示词。
3. `shot-breakdown`：把原剧本拆成可编辑镜头草案，不生成最终视频提示词。
4. `shot-prompt`：读取确认分镜、原剧本、资产图片理解和连续性参考，生成最终视频提示词。

每个子任务都绑定独立 Skill，支持后台发布、灰度、回滚、审计和任务级快照冻结。视频生成始终调用正式视频通道，不用文本 Skill 模拟成功。

用户侧阶段状态由子任务聚合：

- 资产设计：提取中、待补图、待确认、已完成。
- 镜头生产：拆镜中、待改分镜、提示词生成中、待确认提示词、视频生成中、部分完成、已完成。

## 资产数据模型

逻辑资产和素材库记录分开表示：

- `logicalAssetId`：稳定创作编号，例如 `CHAR-001`、`SCENE-003`、`PROP-008`，跨图片版本保持不变。
- `libraryAssetId`：浏览器素材库中的资产记录 ID。
- `assetVersion`：当前冻结的图片版本与内容哈希。
- `kind`、`name`、`scriptEvidence`、`description`、`imagePrompt`。
- `status`：草稿、待生图、待绑定、待确认、已确认、失败。

图片工作台使用 `libraryAssetId` 更新同一记录；生产包通过 `libraryAssetId + assetVersion` 冻结具体图片，同时保留 `logicalAssetId` 用于人类识别和追踪。

## 镜头生产包数据模型

每个生产包至少包含：

- `shotId`、`sceneKey`、`order`。
- `sourceScript`：对应原剧本片段和来源位置。
- `shotDraft`：结构化分镜字段。
- `shotStatus`：草稿、已修改、已确认。
- `prompt`、`promptStatus`、`promptInputHash`。
- `referenceBindings`：资产编号、素材记录 ID、冻结版本、用途和图片理解摘要。
- `continuityReference`：上一镜编号、尾帧资产 ID、冻结版本、来源视频版本、更新状态。
- `config`：本镜头实际视频参数。
- `generation` 与 `generationVersions`：任务、视频、费用、失败原因和历史版本。
- `lastFrameAssetId` 与 `lastFrameVersion`。

修改已确认分镜、参考资产版本或连续性参考后，重新计算 `promptInputHash`；若与生成提示词时的哈希不同，提示词状态变为“需重新生成/确认”。

## 提示词生成输入

`shot-prompt` 任务必须同时冻结：

- 当前镜头原剧本片段；
- 用户确认的结构化分镜；
- 正式资产图片及其逻辑资产编号和冻结版本；
- 对每张输入图片的可见事实与应用位置；
- 可选的上一镜尾帧连续性参考；
- 当前 Skill 版本与内容哈希。

当存在连续性参考时，任务自动加入语义约束：

> 以上一镜尾帧作为剧情连续性参考，本镜从该画面之后继续发展；保持场景、角色身份、服装、光线、材质与画风一致，不要求第一帧复刻参考图，不重新诠释视觉设定。

连续性参考在应用内部使用 `continuity_reference` 角色；提交当前视频协议时映射为普通参考图，不映射为 `first_frame`。

## 视频与尾帧流程

1. 只有提示词已确认且必需资产完整时才能生成视频。
2. 视频请求携带最终提示词、正式资产图片和可用的连续性参考图。
3. 支持尾帧返回的通道默认请求 `return_last_frame=true`。
4. 若上游返回尾帧地址，下载并归档该图片。
5. 若上游没有返回尾帧，则从已经下载的视频文件中定位到结尾并本地截取 PNG 作为兜底。
6. 尾帧作为独立图片资产保存，元数据记录项目、分集、镜头、视频资产、视频版本、来源方式和生成时间。
7. 同一场景且标记为连续动作的下一镜自动建议绑定该尾帧；绑定后仍由用户确认。
8. 跨场景、时间跳切、闪回等镜头不自动建议承接。
9. 上一镜重新生成后，不静默替换下一镜已冻结的连续性参考；显示“存在新版本”并要求确认更新。

尾帧归档失败不改变视频成功状态，但需要连续性的下一镜会显示阻断原因，并提供重新提取、上传图片或选择已有图片入口。

## 费用与执行边界

- 资产提取、资产提示词、拆镜和镜头提示词在本地开发可由 Codex CLI 验证，算力点为 0。
- 实际资产图片由图片工作台当前图片通道生成；批量生图前统一展示模型、数量和费用确认。
- 视频生成只调用正式企业视频通道，每次单条或批量提交前明确确认真实参数与费用。
- 生产环境拒绝 Codex CLI，工作流文本/多模态任务统一走企业 API。
- 不在本任务中修改画布、画布节点结构或后台模型配置页面。

## 失败与恢复

- 单张资产生图失败只影响该资产卡，批次内其他资产继续执行。
- 子任务保存输入快照、Skill 版本和失败原因，可单独重试。
- 分镜切换前保存；保存失败时停留在当前镜头。
- 图片、分镜或连续性参考更新后阻止旧提示词直接生成视频。
- 视频网络中断时保留企业任务 ID，可恢复同步。
- 视频成功但尾帧缺失时保留成功视频，并单独重试尾帧归档。
- 已审核产物不能被新任务静默覆盖，新版本必须重新确认。

## 测试与验收

### 自动测试

- 四阶段路由、状态聚合和继续下一项。
- 稳定资产编号、图片版本绑定和图片工作台回写。
- 原剧本到镜头草案的映射、分镜保存与确认门禁。
- 分镜或参考变化导致提示词过期。
- 图片理解证据完整性和提示词输入快照。
- 连续性参考映射为普通参考图而不是首帧。
- 上游尾帧返回归档、本地视频截帧兜底和失败恢复。
- 下一镜连续性建议、跨场景不建议、上游版本更新不静默替换。
- 视频生成参数、费用确认、任务同步、历史版本和交付阻断。

### 真实页面闭环

按顺序完成：

`剧本确认 → 资产提取 → 批量/单独生图 → 绑定并确认资产 → 拆分镜头 → 修改并确认分镜 → 多模态生成提示词 → 修改并确认提示词 → 最小视频生成 → 尾帧归档 → 下一镜连续性参考`

本地文本和图片理解使用 Codex CLI；图片生成使用现有图片通道；视频仅使用已授权的最小企业 API 测试。每轮按“体验 → 记录问题 → 最小修复 → 自动检查 → 重新体验”循环，直到无 P0/P1，主路径无阻断，预估满足度达到 95%。

## 非目标

- 不修改画布及其节点交互。
- 不重做后台模型渠道、模型选择和费用设置。
- 不引入自动无确认扣费的图片或视频批量生成。
- 不把上一镜尾帧当作下一镜强制首帧。
- 不在本轮实现云端素材同步；素材、版本和生产包继续沿用当前浏览器本地持久化边界。
