# 资产方形图库设计

## 目标

将资产总览从多层整行面板和横向长卡片收口为紧凑的方形图库。人设、场景、道具、站位主体与图片、视频、音频使用一致的卡片密度；资产页不再展示、创建或导入文本资产。

本次以 `/assets` 总览页的方形图库为主，同时补齐资产卡与现有生图工作台之间的入口和版本回写。资产 Store 的主体、形态与媒体模型继续沿用；历史文本数据和视频工作流保持不变。

## 已确认边界

- 人设、场景、道具、站位主体全部使用方形卡片。
- 普通图片、视频、音频使用相同尺寸的方形媒体区域。
- 文本资产从资产页筛选、新建、导入和结果列表中移除。
- 已有文本资产只隐藏，不删除、不迁移，避免破坏历史引用、视频工作流和回写链路。
- “所有项目”继续按项目分段；具体项目内部不再按资产类型套整行折叠面板。
- 项目设定摘要不是媒体资产，继续保留在项目资产图库上方，不纳入本次统一卡片。
- 主体可以先手动新建，再从主体卡进入对应形态的生图流程。
- 已有图片可以带着当前图片和生成配置重新进入生图；保存结果创建新版本，不覆盖原图。

## 页面结构

### 顶部工具栏

保留项目选择、媒体类型筛选、模糊搜索、排序、批量导入和新建入口，并降低工具栏高度。类型筛选只包含“全部资产、图片、视频、音频”；新建菜单只保留文件夹、人设、场景、道具、站位、视频和音频。

### 项目分段

“所有项目”视图继续显示项目标题和资产数量，避免不同项目混在一起。选择具体项目时只显示当前项目内容。项目分段内部使用一个扁平图库，不再渲染人设整行面板、资产类型整行面板或嵌套的长条资产行。

集数、来源、收藏、文件夹和版本状态仍由现有筛选器负责，不通过额外的视觉分组重复表达。

### 方形图库

图库使用自适应固定密度：桌面卡片媒体区域约 200–220px，按可用宽度自动换行；390px 窄屏保持两列。所有卡片顶部均为 `aspect-square` 媒体区域，标题与少量元信息放在媒体区域下方，整体视觉参考用户提供的资产图库截图。

卡片操作在桌面悬停或键盘聚焦时出现，触屏设备保持可见。选择、收藏、编辑、下载、加白和删除继续沿用现有动作与确认逻辑。

## 卡片类型

### 资产主体卡

每个人设、场景、道具或站位主体只在总览中占一张卡，不把每个形态再拆成整行子面板。

- 封面优先使用形态当前正式资产，其次使用该主体最近的正式图片。
- 没有正式图片时显示清晰的“待生产”占位和类型图标。
- 媒体区角标显示人设 / 场景 / 道具 / 站位。
- 卡片下方显示主体名称、主体编号、形态数和正式图片数。
- 点击卡片进入 `/assets/[subjectId]` 主体生产工作台。
- 卡片提供“去生图”快捷动作：打开主体生产工作台并定位到当前形态；刚手动创建的主体使用自动建立的默认形态。
- 主体卡不参与普通媒体资产的批量选择，避免把主体 ID 与资产 ID 混用。

### 普通媒体卡

图片、视频、音频共用统一卡片边界：

- 图片显示裁切封面。
- 视频显示封面或静音首帧预览，并保留视频类型标识。
- 音频显示音频图标和简洁的媒体占位，不伪造图片封面。
- 卡片下方只保留标题、媒体信息和必要来源；长 metadata 继续在详情抽屉查看。
- 图片卡提供“进入生图修改”动作；视频和音频不显示该动作。

## 生图联动与版本回写

### 手动主体卡进入生图

顶部“新建”菜单继续允许手动建立人设、场景、道具和站位主体。创建时同步建立该类别的默认形态，随后资产总览立即出现一张“待生产”主体卡。用户可以点击主体卡进入主体生产工作台，也可以使用卡片上的“去生图”快捷动作直接定位到默认或当前形态。

主体名称、类型、标签、形态提示词和项目范围继续保存在现有主体与形态数据中；开始生成不要求先有正式图片。生成候选并转为正式资产后，图库中的同一张主体卡更新封面，不额外产生第二张主体卡。

### 已有图片进入生图修改

图片卡的“进入生图修改”动作打开现有 `/image` 工作台，并携带来源资产 ID、项目、集数和返回地址。工作台初始化时：

- 将来源图片自动放入第 1 个参考图槽，用户仍可删除或补充其他参考图。
- 优先恢复来源图片记录中的生成提示词、模型、质量和尺寸；缺失时使用当前生图默认配置。
- 保留来源图片的主体、形态和项目坐标，供保存结果时回写。

工作台生成过程不会改动来源图片。用户点击“保存到资产”后：

- 来源图片绑定了主体与形态时，创建一张继承相同 `assetBinding` 的新正式图片，并将该形态的 `currentAssetId` 指向新图片；旧图片继续保留在形态版本列表中。
- 来源图片没有主体绑定时，创建一张新的独立图片资产，并在生成 metadata 中记录来源资产 ID，保留修改链路。
- 新图片记录本次实际使用的提示词、模型、质量、尺寸和能力追踪信息，后续仍可再次进入生图修改。
- 保存失败时不更新形态当前版本，并保留本次生成结果供用户重试保存。

原有视频工作流文本素材卡通过 `libraryAssetId` 原地回写图片的行为维持现状；只有从正式图片资产发起的修改使用上述“新建版本”规则，避免改变现有工作流契约。

## 文本资产处理

资产总览的数据查询在分页和数量计算之前排除 `kind === "text"`，保证列表、空状态、项目计数和分页不会出现文本资产。

- 顶部类型筛选移除“文本”。
- 新建菜单移除“文本”。
- 普通文件导入和资产包导入只接收图片、视频、音频；遇到文本条目时跳过并提示数量。
- 如果一次导入只有文本条目，显示“没有可导入的媒体资产”，不创建任何新资产。
- 底层 `AssetKind`、文本资产 Store、历史记录和其他工作流消费代码不删除。

## 数据与组件边界

- `page.tsx` 继续负责 Store、筛选、分页和动作接线，不承载卡片视觉细节。
- `AssetResultsSection` 负责项目分段、设定摘要和扁平图库装配。
- 新增或收口统一媒体卡组件，使图片、视频、音频共享布局；主体卡保持独立组件，因为它的身份、点击目标和批量动作与媒体资产不同。
- 现有删除、下载、收藏、加白、详情抽屉和主体工作台接口保持原契约。
- 复用现有 `AssetVariant.currentAssetId` 表达形态当前版本；普通图片的来源链写入已有 metadata，不新增持久化模型，不迁移或删除已有数据。

## 异常与空状态

- 主体没有封面时显示待生产占位，卡片仍可进入工作台。
- 视频没有可用封面时显示视频占位；音频始终使用音频占位。
- 文本被过滤后，如果没有其他资产或主体，显示现有资产空状态。
- 导入中部分媒体失败时继续保留成功项，并汇总成功、跳过文本和失败数量。

## 验收

- 桌面端资产不再以整行长条或每主体一整行面板展示，而是从左到右自动换行的方形图库。
- 人设、场景、道具、站位无论是否已有正式图片，都只占一张主体卡并可进入工作台。
- 手动新建主体后立即出现待生产卡，并可从卡片进入默认形态开始生图。
- 图片、视频、音频卡片具有相同宽度和方形媒体区域，原操作仍可用。
- 已有图片进入生图时自动成为第 1 张参考图；保存结果不会覆盖来源图片。
- 主体图片的修改结果继承原主体与形态绑定并成为当前版本，旧版本仍可查看和重新设为当前版本。
- 无主体绑定图片的修改结果作为独立新资产保存，并可追溯到来源图片。
- 资产页所有筛选、新建菜单、列表、项目计数和分页均不出现文本资产。
- 导入包含文本的资产包时只跳过文本，不删除已有文本数据。
- “所有项目”和单项目视图均正确；浅色、深色和 390px 窄屏无横向溢出。
- 验收不触发任何真实图片或视频生成。
