# 单页视频工作流设计

## 1. 决策摘要

视频工作流采用“阶段轨道 + 分镜队列 + 当前工作区 + 结果控制台”的单页结构。

项目分集页继续负责新建项目、导入剧本、AI 优化和确认本集生产稿。用户确认剧本后，从项目分集页进入当前集的统一工作流页面：

`/projects/:projectId/episodes/:episodeId/workflow`

统一页面承接导演分析、资产准备、分镜与视频提示词、视频生成、版本审核和交付检查。现有 `/original-workflow` 与 `/video` 不再作为两套并行主流程；带有项目和分集上下文的旧入口统一跳转到当前集工作流。

本设计同时实现可上线的云端 Worker 和统一视频工作流前端。门禁不通过删除提示解除，而是在后端具备持久化队列、任务租约、失败恢复、日志、停止、重试、人工审核、映射预览和算力点结算后开放。画布页面和后台模型设置界面保持不变；Worker 只读取后台已经发布的文本模型与渠道，不恢复本地 Codex CLI，也不读取用户本机目录。

## 2. 目标与成功标准

### 2.1 产品目标

- 用户始终知道当前处理的是哪个项目、哪一集、哪个阶段、哪条分镜。
- 用户可以在一个页面内完成从确认稿到视频版本审核的连续操作。
- 每条分镜同时呈现剧情、参考资产、提示词、生成设置、任务状态和结果，避免跨页面对照。
- 批量动作只处理已确认且满足门禁的条目，不用全局设置覆盖单条分镜配置。
- 任务失败、页面刷新或应用重启后，用户可以继续同步和修复，不被迫重新创建任务。
- 画布只保留为结果完成后的次要承接出口，不成为视频工作流前置条件。
- 阶段启动后立即返回持久化任务，页面刷新、进程重启或短暂断网不会丢失执行状态。
- 未审核的 Agent 草案不能写入正式资产、分镜和视频生产包。
- 同一个启动请求不会因双击、重试或网络超时重复扣费或创建重复任务。

### 2.2 “95% 满足需求”的可验收定义

本轮以核心用户旅程覆盖率和阻塞问题清零作为判断依据：

- 30 个核心交互与服务场景至少 29 个一次通过，且剩余问题不阻断主流程。
- 空状态、未配置、运行中、待审核、已通过、已过期、失败、可恢复、已完成九类状态均有明确下一步。
- 在 1440×900 与 1920×1080 桌面视口下，主操作不需要页面级横向滚动。
- 连续处理 30 条分镜时，切换分镜、保存提示词和查看结果不发生明显卡顿或布局跳动。
- 1000 条以上分镜队列使用虚拟化渲染或等价的稳定方案，搜索和筛选不会一次渲染全部复杂卡片。
- 页面刷新后能恢复项目、分集、阶段、当前分镜和已保存的单条配置。
- 主流程体验期间无未处理的应用错误、控制台错误、永久 loading 或不可关闭遮罩。
- Worker 进程重启后，未完成任务能按租约规则继续、重排或明确失败，不永久停在 `running`。
- 并发提交、重复提交、取消与超时都能维持一次扣费/一次退款边界。
- 所有扣费或远程生成动作都经过明确确认；自动化验收使用本地假上游，不产生真实费用。上线前真实渠道冒烟测试需再次取得明确授权。

## 3. 范围边界

### 3.1 本轮包含

- 项目分集到统一工作流的入口与返回路径。
- 单页阶段导航和阶段状态汇总。
- 已确认剧本的只读摘要与来源状态。
- 导演/美术/分镜阶段的产物摘要、任务状态、质量门和人工确认入口。
- 资产准备状态、缺图定位、项目素材引用和当前分镜资产槽。
- 分镜队列、提示词编辑、单条配置、单条生成、批量生成、任务同步和失败恢复。
- 视频主预览、历史版本、结果详情和保存到素材状态。
- 全集完成度、问题筛选和交付前检查。
- 统一页面的空态、错误态、响应式和键盘可达性。
- 云端 workflow run、stage run、artifact、quality gate、event 的后端持久化。
- DB 持久化 Worker 队列、任务租约、心跳、超时回收、取消和有限重试。
- 按登录用户隔离的 workflow API、事件流和审核 API。
- 服务端版本化阶段模板、输入快照、输出结构化、确定性质量门和映射预览。
- Worker 调用现有文本模型渠道、预扣算力点、失败退款和任务审计。
- 单容器内嵌 Worker 的默认部署方式，以及后续拆成独立 Worker 进程的边界。
- 真实浏览器体验、问题记录、修复、回归和再次体验。

### 3.2 本轮不包含

- 画布布局、节点行为、画布工具栏和画布数据模型调整。
- 后台模型设置、渠道配置、EP 绑定、模型目录和费用规则调整。
- 恢复本地 Runner、Codex CLI 或本机工作流目录执行。
- 依赖用户本机文件、`.workflow-cache`、Python 工作流脚本或 Codex CLI 的执行方式。
- 新建剪辑器、PR/剪映深度集成、字幕或音频后期系统。
- 云端多人协作和跨设备同步。
- 本轮不把浏览器本地项目、画布和素材整体迁移为云端项目系统；服务端 workflow 通过 `userId + projectId + episodeId` 隔离运行，审核后的正式写入仍由登录前端应用到现有本地 store，并把写入回执提交服务端审计。

## 4. 页面信息架构

### 4.1 顶部上下文栏

顶部只保留生产所需信息：

- 返回项目。
- 项目名称 / 分集名称。
- 本集总体进度与阻塞数量。
- 当前默认视频模型的只读摘要；点击“查看配置”只打开现有全局配置入口，不在工作流内复制配置表单。
- “继续下一项”主动作，根据当前状态定位下一条待处理分镜或下一项阶段审核。
- 更多菜单放刷新状态、查看运行记录和返回分集，不放画布主操作。

顶部不提供会覆盖全部分镜的隐式模型下拉。需要批量套用参数时，必须通过显式“批量套用”弹窗展示影响条目和覆盖字段。

### 4.2 最左阶段轨道

阶段轨道固定宽度，负责显示流程而非承载长内容：

1. 剧本确认
2. 导演与美术
3. 资产准备
4. 分镜提示词
5. 视频生成
6. 审核交付

每个阶段显示图标、短名称和状态：未开始、进行中、待审核、已通过、需处理、被阻断。状态不能只靠颜色表达，同时显示图标和文字提示。

点击阶段只切换当前工作区，不跳转路由。阶段状态来源于现有剧本、Agent workflow、质量门、资产和视频生产包数据，不维护第二套重复进度。

### 4.3 左侧上下文队列

队列内容随阶段切换：

- 剧本确认：显示确认稿来源、字数和更新时间。
- 导演与美术：显示阶段产物、审核项和运行记录。
- 资产准备：按角色、场景、道具筛选资产卡，突出缺图和需确认项。
- 分镜提示词、视频生成、审核交付：显示分镜/P 编号队列。

分镜队列提供搜索、状态筛选、场次分组、问题计数和虚拟滚动。每一项只展示编号、短剧情、关键状态和结果缩略图，不在队列内堆完整提示词。

当前分镜由 URL 查询参数恢复：`?stage=video&shot=P01`。无参数时按以下优先级定位：阻断项、待审核项、生成中项、第一条未完成项、第一条。

### 4.4 中间当前工作区

中间区域只处理当前阶段或当前分镜。

视频相关阶段按固定阅读顺序展示：

1. 剧情原文摘要，可展开查看完整段落。
2. 当前分镜参考资产槽。
3. 视频提示词编辑器。
4. 风险、质量门和保存状态。
5. 上一条 / 下一条与保存后继续。

资产槽与提示词中的 `@图N` 对应。资产状态分为未生成、已匹配、需确认、审核中、可用；缺失时仍保留占位，不删除提示词引用。

提示词编辑采用显式保存状态：未修改、未保存、保存中、已保存、保存失败。切换分镜前若存在未保存修改，自动保存；保存失败时停留当前分镜并提供重试，不静默丢失。

### 4.5 右侧结果控制台

右侧保持固定，随当前分镜更新：

- 当前视频主预览。
- 历史生成版本缩略图和版本编号。
- 当前版本状态、生成时间和是否已入素材。
- 单条视频设置摘要：实际模型、时长、画幅、清晰度、生成方式、参考图模式、音频和水印。
- 预检、生成、同步任务、重新生成和打开详情。
- 失败原因与推荐修复动作。

设置默认以摘要展示，点击后使用现有视频设置组件打开弹层；不把完整后台渠道设置搬入右栏。

右栏在 1440px 以上固定显示；较窄桌面收为可保持打开的抽屉。分镜队列在更窄宽度收为抽屉，中心编辑区始终优先保留。

## 5. 阶段逻辑

| 阶段 | 主要输入 | 主要工作 | 正式输出 | 进入下一阶段条件 |
| --- | --- | --- | --- | --- |
| 剧本确认 | 项目分集确认稿 | 查看来源、版本和生产就绪状态 | 本集生产稿快照 | 已确认且内容非空 |
| 导演与美术 | 生产稿 | 查看/启动阶段任务、阅读摘要、审核 | 导演判断和美术设定产物 | 质量门通过并人工确认 |
| 资产准备 | 美术设定、项目素材 | 补图、匹配、确认角色/场景/道具 | 可引用的项目资产 | 阻断资产已解决或用户明确接受文本生成风险 |
| 分镜提示词 | 生产稿、导演判断、资产 | 按场次生成和审核 P 条目 | 视频生产包 | 提示词质量门通过并确认同步 |
| 视频生成 | 视频生产包 | 逐条检查、配置、生成、同步和版本管理 | 视频素材版本 | 需要交付的条目已有选定版本 |
| 审核交付 | 视频素材版本 | 检查缺失、失败、未确认和过期引用 | 可交付清单/现有导出动作 | 无阻断项 |

页面只有在后端健康检查返回 Worker 可领取任务、数据库可写且存在可用文本模型时才开放阶段启动。Worker 临时不可用时，只阻断新的远程启动动作；已有产物、已有生产包、资产补图、视频生成和历史审核仍可继续查看或操作，不把整个页面替换成单一禁用页。

## 6. 单条分镜状态模型

一条分镜同时拥有五组状态，页面按严重程度合并成一个主状态：

- 提示词：待审核、需修改、已确认。
- 资产：缺失、需确认、可用。
- 配置：未配置、可生成、预检失败。
- 任务：空闲、检查中、创建中、排队、生成中、成功、失败、取消。
- 版本：无结果、有结果、已选主版本、已入素材。

主状态优先级：生成中 > 创建/排队 > 阻断 > 失败 > 待审核 > 可生成 > 已完成。

批量生成仅包含“提示词已确认、配置可用、没有阻断风险、当前没有运行任务”的条目。确认弹窗列出包含数、排除数、排除原因和会使用的单条配置，不允许用一个全局配置静默覆盖全部条目。

## 7. 云端 Worker 设计

### 7.1 总体结构

第一版使用“API 进程 + 同库持久化队列 + 内嵌 Worker”结构，适配当前单容器部署：

```text
统一工作流页面
  -> Gin Workflow API
  -> workflow_runs / workflow_stage_runs / agent_runs
  -> DB 任务队列
  -> 内嵌 Cloud Worker
  -> 现有文本模型渠道
  -> 结构化草案 + Artifact + Quality Gate
  -> 用户审核
  -> 前端写入本地资产 / 分镜 / 视频生产包
  -> 服务端记录 applied 回执
```

Worker 与 API 通过数据库任务状态协作，不依赖进程内队列。以后需要独立扩容时，可以关闭 API 进程中的内嵌 Worker，并用同一代码启动独立 Worker 进程，不改变页面 API 和数据库合同。

### 7.2 持久化模型

新增并同步记录到 `docs/backend-database.md`：

- `workflow_runs`：用户、项目、分集、workflow 版本、当前阶段、整体状态和输入剧本快照摘要。
- `workflow_stage_runs`：阶段、状态、尝试次数、依赖阶段、质量门摘要、审核时间和应用时间。
- `workflow_artifacts`：阶段产物类型、版本、原始文本、结构化 JSON、内容哈希和来源任务。
- `workflow_quality_gate_results`：规则版本、通过/失败、问题列表、输入 artifact 哈希和执行时间。
- `workflow_events`：状态变化、进度、重试、取消、审核、写入回执和安全化日志。

扩展现有 `agent_runs` 作为可领取任务：

- 新增 `queued`、`cancel_requested`、`cancelled` 状态。
- 新增 `attempt`、`max_attempts`、`available_at`。
- 新增 `lease_owner`、`lease_expires_at`、`heartbeat_at`。
- 新增 `idempotency_key`，并对 `user_id + idempotency_key` 建唯一约束。
- 新增 `credits_reserved`、`credits_refunded` 和最终结算状态。

任务领取必须使用“条件更新 queued -> running”保证只有一个 Worker 获得租约。过期租约由回收器重新排队；超过最大尝试次数后进入 failed 并结算退款。项目未上线，不保留旧 `created -> 同步执行` 行为的兼容分支。

### 7.3 版本化工作流合同

服务端维护内置、可版本化的三阶段定义，不读取绝对路径或用户本机 Skill：

1. `script-adaptation`：接收项目分集页已确认的生产稿，保存不可变输入快照并运行确定性就绪检查；不再次自动改稿。
2. `art-design`：读取生产稿和指定 workflow 版本，生成导演讲戏摘要、角色、场景、道具结构化草案。
3. `seedance-storyboard`：读取已批准的美术 artifact，按场次/子场次排队生成分镜提示词和视频生产包草案。

每次 stage run 固定记录 workflow 版本、模板版本、输入 artifact ID、模型、实际渠道和内容哈希。后续模板更新不改变正在运行或已经审核的任务。

阶段输出先经过 JSON schema/字段检查、引用检查、台词预算、资产唯一性和提示词基础规则等确定性质量门。模型自评只作为补充证据，不能替代确定性校验。

### 7.4 API 合同

新增用户态接口，全部经过登录鉴权和所有权检查：

- `POST /api/v1/workflow-runs`：按项目、分集和剧本哈希确保一个 workflow run；支持幂等键。
- `GET /api/v1/workflow-runs/:id`：返回阶段、artifact、质量门和最新任务摘要。
- `POST /api/v1/workflow-runs/:id/stages/:stageId/start`：校验依赖、预估费用、幂等入队并立即返回。
- `POST /api/v1/workflow-stage-runs/:id/cancel`：请求取消排队中或运行中任务。
- `POST /api/v1/workflow-stage-runs/:id/retry`：只对可重试失败创建下一次任务，不复用旧扣费记录。
- `POST /api/v1/workflow-stage-runs/:id/review`：批准或驳回当前 artifact；内容哈希不一致时拒绝审核。
- `POST /api/v1/workflow-stage-runs/:id/apply`：记录前端已写入的目标、数量、版本和错误回执。
- `GET /api/v1/workflow-runs/:id/events`：按游标增量读取事件；前端使用 2 秒轮询并在后台标签页退避，避免第一版引入不必要的长连接复杂度。
- `GET /api/v1/workflow-worker/health`：返回 Worker 开关、最后心跳、可用文本通道和积压数量，不返回密钥。

现有 `/api/v1/agent-runs` 改为底层任务查询和兼容服务，不再在 HTTP 请求内同步调用上游模型。Next `/api/original-workflow` 门禁路由退出主流程，旧链接只负责解析上下文并跳转到统一页面。

### 7.5 调度、取消与重试

- 默认全局 Worker 并发 2、单用户并发 1；配置来自部署环境，不进入后台模型设置页面。
- 阶段三按场次拆成子任务，父 stage run 汇总进度；同一场次失败不抹掉已成功场次。
- Worker 每 10 秒续租，租约默认 60 秒；进程失联后由其他 Worker 回收。
- 取消请求写入数据库；Worker 在上游调用前、批次之间和写 artifact 前检查取消状态。
- 网络超时、上游 429 和 5xx 最多自动重试 2 次并指数退避；输入错误、余额不足、质量门失败不自动重试。
- 重试任务保留上一次错误、模型、渠道、费用和 artifact 关系，页面能说明是第几次尝试。

### 7.6 算力点与幂等

- 创建 stage run 时只计算预估费用，不扣费。
- Worker 成功领取具体 Agent 子任务后按现有模型费用预扣，并写关联 run ID 的算力点日志。
- 上游未返回可用结果、任务被系统取消或重试前失败时按现有退款服务返还；产生可审核 artifact 后不自动退款。
- 每个创建动作由前端生成幂等键；网络重试返回同一 run，而不是新建任务。
- 审核、应用和取消接口同样使用状态条件更新，重复请求返回当前结果。

### 7.7 权限与安全

- 所有 workflow、stage、artifact、event 查询都附带 `user_id` 条件；只使用用户自己的项目/分集上下文。
- 客户端不能提交 API Key、渠道密钥或任意上游 URL；服务端通过现有模型目录解析实际文本通道。
- 限制剧本、提示词、artifact 和事件日志大小；拒绝超限输入。
- 事件日志只保存安全化元数据，不记录 API Key、Authorization、完整请求头或后台密钥。
- Worker 写入采用临时对象后事务提交；质量门和审核引用 artifact 内容哈希，防止审核后内容被替换。
- 服务启动使用可取消 context；收到退出信号后停止领取新任务、等待当前任务安全退出或释放租约，再关闭 HTTP 服务。

### 7.8 上线门禁

只有以下条件全部满足才把 `/original-workflow` 的禁用状态替换成可运行入口：

- Worker 健康检查通过并持续心跳。
- 队列领取、租约续期、进程重启恢复和取消测试通过。
- 用户隔离、幂等提交、费用预扣/退款和审核哈希测试通过。
- 假上游环境跑通三阶段、质量门、审核、应用回执的完整集成测试。
- 浏览器真实走通统一页面主路径。
- 真实文本渠道冒烟测试经用户授权后成功，并能在后台 AI 任务/算力点记录中追溯。

## 8. 数据与组件边界

### 8.1 数据来源

统一页面直接组合现有数据：

- `useCreativeProjectStore`：项目与画布归属信息。
- `useScriptStore`：项目分集和确认稿。
- Workflow API：服务端 workflow run、阶段任务、artifact、质量门、事件和审核状态，作为远程阶段的事实来源。
- `useAgentRunnerStore`：实施期间只保留页面需要的本地显示缓存和既有 Agent 中心数据，不再作为统一工作流远程阶段的唯一事实来源。
- `useAssetStore`：项目素材、引用图片和生成结果。
- `useVideoPackageStore`：视频生产包、单条配置、任务状态和版本。
- 现有视频服务：预检、创建任务、同步任务和读取结果。

不新增只为页面重复保存这些数据的大型全局 store。页面选择、筛选、面板显隐和草稿状态放在当前页面私有 hook；需要刷新恢复的阶段和分镜写入 URL。远程轮询结果通过页面 hook 合并，不复制成另一套持久化 workflow 状态。

`ProductionPackage` 在实施时补齐稳定的 `projectId`、`episodeId` 和排序/场次字段，更新与查找必须使用项目、分集和条目 ID 组合，避免不同项目的同名 `P01` 相互覆盖。项目尚未上线，不为旧结构增加复杂兼容层。

### 8.2 前端文件职责

- `workflow/page.tsx`：只负责装配 stores、hooks 和主要区域。
- `workflow/hooks/`：阶段选择、当前分镜、自动保存、批量动作和视频任务操作。
- `workflow/components/`：顶部栏、阶段轨道、上下文队列、分镜编辑器、结果控制台、阶段状态面板和审核面板。
- `workflow/utils/`：纯状态汇总、默认定位、筛选、批量资格和 URL 参数转换。
- 现有视频设置、任务请求、资产匹配和详情组件优先复用；只在职责不适合新布局时做小范围拆分。

### 8.3 后端文件职责

- `handler/`：解析 workflow HTTP 请求、读取登录用户、调用 service、返回统一响应。
- `service/`：workflow 状态机、阶段依赖、幂等、Worker 调度、质量门、审核、算力点和模型调用。
- `repository/`：任务领取、租约、事件分页、artifact 和 workflow 数据库查询。
- `model/`：workflow、stage、artifact、gate 和 event 数据结构及状态枚举。
- `main.go`：创建可取消服务 context，启动/停止内嵌 Worker 和 HTTP 服务。

## 9. 错误、恢复与安全

- 项目或分集不存在：显示可返回项目列表的明确空态。
- 剧本未确认：阻断后续阶段，并提供返回分集页的主按钮。
- Worker 不可用：只阻断新远程任务，显示最后心跳和恢复建议，不遮蔽已有产物。
- Worker 重启：租约过期任务自动恢复；页面显示“正在恢复”而不是永久运行中。
- 重复提交：返回同一任务并显示当前状态，不重复扣费。
- 余额不足：任务不入队，明确显示预估和当前余额。
- 质量门失败：保留 artifact 和问题列表，进入待修复状态，不自动写入下游。
- 审核冲突：artifact 哈希变化时要求重新审阅，旧确认不能应用到新内容。
- 资产缺失：指出具体槽位；允许上传、去项目素材选择或接受文本生成风险。
- 保存失败：保留当前草稿，提供重试，不允许切换后丢失。
- 预检失败：展示实际模型、失败原因和“查看现有配置”入口，不在工作流内编辑后台渠道。
- 任务创建失败：保留提示词和配置，可修改后重试。
- 已有任务 ID 但结果未返回：显示“同步任务结果”，不新建重复扣费任务。
- 页面刷新：从持久化 store 和 URL 恢复当前上下文。
- 所有图标按钮都有可访问名称，错误使用文字和图标共同表达，键盘顺序与视觉顺序一致。

## 10. 体验与优化循环

实施后采用同一条闭环，不以“页面能打开”作为完成标准：

1. 先用假文本上游完成 Worker 集成测试，覆盖排队、成功、失败、429、超时、取消、重试、重启恢复、幂等和费用结算。
2. 准备一个至少包含 30 条分镜、完整/缺失资产、待审核/已确认提示词、成功/失败/运行中任务和多个版本的验收项目。
3. 用真实浏览器从项目分集页进入统一工作流，实际启动导演与美术、分镜提示词任务并完成审核和应用。
4. 依次体验阶段切换、队列搜索、定位阻断项、资产替换、提示词修改与保存、单条配置、预检、生成确认、任务同步、版本切换和交付检查。
5. 同时检查 1440×900、1920×1080 和 1024px 窄桌面。
6. 记录问题的复现路径、严重度、预期行为和实际行为。
7. 优先修复阻断、数据丢失、错误扣费风险、任务重复、上下文错乱和永久 loading；再处理信息密度、文案和视觉细节。
8. 每轮修复后重新从项目入口走完整主路径，并重跑受影响的 Worker 状态与费用测试，不只验证被修改的局部。
9. 直到核心场景至少 29/30 一次通过、无 P0/P1 问题、无控制台错误、无悬挂任务，并由最终视觉检查确认信息层级稳定。

自动化验收不使用真实付费渠道。所有服务与浏览器回归完成后，再单独请求一次真实文本渠道冒烟授权；视频生成仍沿用已有明确确认和预检流程。

## 11. 核心验收场景

1. 从项目分集页进入正确项目和分集的工作流。
2. 未确认剧本时不能误进入后续生产。
3. 刷新后恢复当前阶段和分镜。
4. Worker 健康时可幂等启动阶段，接口立即返回 queued。
5. 阶段状态与现有 workflow run 一致。
6. 资产缺失能定位到具体分镜和槽位。
7. 上传或替换参考图后当前分镜立即更新。
8. `@图N` 与资产槽顺序一致。
9. 提示词修改能显示未保存和已保存状态。
10. 保存失败不会丢失文本。
11. 单条视频设置不会影响其他分镜。
12. 批量套用参数必须显示影响范围。
13. 批量生成自动排除未确认、缺配置和运行中的条目。
14. 预检失败不创建真实视频任务。
15. 已有任务 ID 时优先同步而不是重复创建。
16. 失败任务能查看原因、修复并重试。
17. 成功结果能查看历史版本并选中主版本。
18. 保存到素材后显示归档状态和版本关系。
19. 1000 条队列搜索、筛选和滚动保持可用。
20. 审核交付阶段能列出所有缺失、失败、未确认和过期项。
21. 两次相同幂等请求只创建一个任务和一笔扣费记录。
22. 两个 Worker 竞争时只有一个成功领取任务。
23. Worker 进程中断后任务能在租约过期后恢复。
24. 取消排队任务不会调用上游，也不会扣费。
25. 上游超时和 5xx 按规则重试，超过次数后明确失败并正确退款。
26. 不同用户不能读取、审核、取消或应用对方任务。
27. 质量门未通过时审核/应用接口被阻断。
28. artifact 在审核后发生变化时旧审核失效。
29. 前端应用资产/分镜/生产包后，服务端保存可追溯写入回执。
30. Worker 健康检查失败时旧产物可查看，新任务不可启动且页面没有死锁。

## 12. 推荐实施顺序

设计批准后拆成三个连续交付面，但保持同一个最终闭环：

1. 云端 Worker 基础：数据库模型、异步 Agent Run、任务租约、恢复、事件、审核、费用和假上游集成测试。
2. 单页工作流：统一路由、阶段轨道、远程阶段、资产、分镜提示词、视频生成和审核交付。
3. 上线验收循环：服务回归、真实浏览器体验、问题修复、重测、性能与安全检查，最后在获得授权后做真实文本渠道冒烟。

实施计划必须先完成 Worker 安全与幂等底座，再开放启动按钮；不能先删除门禁、让同步 Agent Run 暂时上线后再补队列。
