# 模型配置管理优化设计

## 背景

当前后台把厂商凭证、渠道能力、模型列表、请求协议、文本接口类型、默认模型和公开模型目录集中在同一组设置中。同一个模型的类型和请求方式分散在渠道能力、公开模型映射和前端名称推断中，容易出现“图片模型发到 Chat Completions”或“Responses 模型发到 Chat Completions”等矛盾配置。

本设计将“怎么连接厂商”与“怎么调用某个模型”拆分，并把模型类型和请求适配器收口为单一服务端配置。

## 目标

- 管理员通过四步向导完成厂商连接、模型发现、模型选择和分类确认。
- 默认界面只显示必要字段；协议、适配器、超时、并发和厂商特殊参数收入高级配置。
- 发现的模型默认全部不选，只有管理员明确勾选的模型才进入系统。
- 模型类型和请求适配器在保存时明确固化；运行时不再根据模型名临时猜测路由。
- 新模型先测试、后发布；普通用户只能选择管理员已发布的模型。
- 保留现有算力点计算和管理范围，不在本次引入厂商价格同步或自动换算。

## 非目标

- 不开放普通用户维护 Base URL、API Key、协议、适配器或计费规则。
- 不建设通用厂商插件市场，只保留内置预设与通用 OpenAI 兼容入口。
- 不自动发布新发现的模型，不在没有管理员确认时触发付费测试。
- 不兼容旧渠道配置字段，不增加旧数据迁移或回退分支。

## 核心概念

### 厂商连接 Provider Connection

厂商连接只负责“如何连接上游”，不再同时承担模型类型和公开目录职责。主要字段为：

- 稳定 ID、配置名称、厂商预设类型。
- 协议类型：OpenAI 兼容、Volcengine Ark、Jimeng CLI、Xinglian Cloud。
- Base URL、在服务端私有设置中保存且对管理响应脱敏的 API Key、启用状态。
- CLI 路径、工作目录、输出目录等厂商特殊选项。
- 凭证修订号和最后一次连接检查结果。

同一个厂商连接可以供多个模型部署复用，API Key 只保存一次。

### 模型部署 Model Deployment

模型部署表示某个厂商连接下的一个可调用模型。主要字段为：

- 稳定部署 ID、厂商连接 ID、上游模型 ID、可选显示名称。
- 模型类型：`text`、`image`、`video`。
- 请求适配器：例如 `chat_completions`、`responses`、`images_generations`、`gemini_chat_image`、`volcengine_ark_video`、`jimeng_cli_video`、`xinglian_cloud_video`。
- 厂商端点 ID、并发上限、超时等部署级高级选项。
- 测试状态、最后测试时间、安全错误摘要、已测配置指纹。
- 发布状态。每个类型的默认部署 ID 单独保存，不在多条记录中分散保存 `isDefault`。

模型部署 ID 是系统内的稳定路由身份。普通用户选择和 Workflow / Invocation 冻结记录使用该 ID；后端在调用上游前把请求中的模型重写为已固化的上游模型 ID。这允许不同厂商提供同名模型，也避免运行时再按模型名选渠道。

### 公开模型目录 Published Model Catalog

公开目录由已发布的模型部署派生，不另存一份可与私有配置失配的模型列表。普通用户可读字段仅包含：

- 部署 ID、显示名称、上游模型名称、厂商显示名称。
- 模型类型和前端需要的请求模式。
- 是否为该类型默认模型。
- 现有算力点配置和必要的生成约束。

公开目录不返回 Base URL、API Key、内部协议参数、未发布模型、测试错误或凭证状态。

### 算力点关联

现有文本按次、图片按张、视频按秒的算力点计算、预扣、失败返还和管理界面保持不变。关联键从可重复的上游模型名改为稳定模型部署 ID，使不同厂商的同名模型可以配置不同算力点。本次不增加厂商价格表或自动换算逻辑。

## 配置存储与服务边界

厂商连接和模型部署继续存储在系统设置的私有配置中，不新增数据表。原有 `private.channels`、公开模型列表、模型来源、协议、能力和文本接口类型字段直接替换为新结构。项目未上线，实现不增加旧字段兼容或数据迁移。

模型管理不再依赖一次提交整份系统设置。后端新增专用管理服务，分别承担：

- 厂商连接的创建、编辑、删除、连接测试和模型发现。
- 候选模型选择、分类确认和模型部署创建。
- 模型部署的编辑、测试、发布、取消发布、设为默认和删除。
- 公开模型目录的派生和安全输出。

`handler/` 只解析请求、调用上述 service 并返回 `{ code, data, msg }`；私有设置的更新、ID、分类、指纹、状态门禁和默认值都在 `service/` 完成。

## 管理员界面

### 信息架构

系统设置中的模型配置改为独立管理区，主视图按“文本 / 图片 / 视频”分栏。每个分栏显示已选模型部署，并按厂商连接分组。模型行直接显示：

- 模型名称、厂商名称、请求适配器。
- 未测试、测试通过、测试失败状态。
- 未发布、已发布和默认状态。
- 测试、发布 / 取消发布、设为默认、编辑和删除操作。

页面不默认展开 Base URL、API Key、协议与厂商特殊字段。这些字段收入厂商连接抽屉，模型的适配器和端点映射收入模型部署的高级配置。

### 四步添加向导

1. **选择厂商**：从内置预设或“通用 OpenAI 兼容”中选择。预设可填充 Base URL、协议和已知模型分类规则，但不自动发布模型。
2. **连接并发现**：填写配置名称、Base URL 和 API Key，先完成安全连接检查，再读取厂商模型列表。不支持列表接口的厂商使用内置候选列表。
3. **选择模型**：展示可搜索、可按推测类型筛选的候选列表。默认 0 个已选，不提供默认全选。列表没有的模型可从高级入口手动添加上游模型 ID。
4. **确认配置**：仅展示已选模型。高置信度结果直接展示类型和适配器；无法识别的条目必须由管理员选择类型和兼容适配器后才能保存。

保存后创建厂商连接和选中模型部署，所有新模型的初始状态固定为“未测试 + 未发布”。

## 模型发现与分类

模型发现结果是短期候选数据，不因为“被厂商列出”就写入系统。分类优先级为：

1. 厂商预设中的精确模型规则。
2. 上游模型元数据或可靠的类型字段。
3. 项目统一的已知模型名称规则。
4. 无法判定时标记为待确认，不用宽泛渠道能力自动填充。

自动分类只用于帮助管理员创建显式配置。模型部署保存后，所有请求都读取已存储的类型和适配器，不再执行名称推断。

## 测试、发布与默认模型

### 连接测试

连接测试只检查厂商地址、凭证和可用的模型发现 / 预检能力。它不替代单模型调用测试，不自动发布模型。

### 模型测试

模型测试必须通过模型部署的显式适配器构造请求：

- `chat_completions` 使用 `/chat/completions`。
- `responses` 使用 `/responses`。
- `images_generations` 使用 `/images/generations`。
- `gemini_chat_image` 使用图片请求适配后的 `/chat/completions`。
- 视频和 CLI 适配器继续使用各自的鉴权预检或最低测试路径。

图片和视频模型发起可能产生厂商费用的真实请求前，必须显示确认弹窗，说明测试类型和可能费用。本次不把厂商价格表纳入系统真相。

测试通过时保存配置指纹和测试时间；失败时保存脱敏错误摘要，不保存完整凭证或大型媒体响应。

### 发布门禁

- 只有“最后测试通过”且“当前配置指纹与已测指纹一致”的模型可以发布。
- 修改 Base URL、上游模型 ID、模型类型、请求适配器或端点映射后，测试状态立即失效；已发布模型自动取消发布。
- API Key 轮换先通过连接检查再保存。凭证轮换不改变模型路由指纹，不自动取消已发布模型；连接检查失败时不覆盖原凭证。
- 一个模型部署取消发布后立即从普通用户目录移除，但历史 Workflow / Invocation 记录继续保留冻结快照。

### 默认模型

- `text`、`image`、`video` 每类最多一个默认模型部署。
- 默认模型必须处于已发布状态。
- 取消发布、禁用或删除当前默认模型前，必须先指定同类型的新默认模型。

## 普通用户权限和使用流程

- 普通用户可在全部已发布的文本、图片和视频模型中自由选择。
- 用户首次进入或已选模型不再发布时，回退到该类型的系统默认模型。
- 用户可见选项显示模型名称、厂商显示名称、模型类型和必要的算力点信息。
- 用户不能读取或修改 Base URL、API Key、内部请求适配器、测试结果、未发布模型或厂商高级参数。
- 前端请求携带模型部署 ID；后端验证该部署仍已发布，并根据固化适配器选择请求路径。

## 请求路由

所有前端和后端 Runtime 消费者改为使用模型部署 ID，不再仅使用上游模型名选择渠道。请求处理步骤为：

1. 读取已发布模型部署。管理员测试使用私有部署读取路径，不要求已发布。
2. 验证请求入口、模型类型和固化适配器匹配。例如 `images_generations` 部署不能经由文本 Chat 入口调用。
3. 读取关联厂商连接和凭证。
4. 把客户端模型部署 ID 重写为上游模型 ID，按适配器构造或转换请求。
5. 按现有 AI 任务、算力点、失败返还和审计路径记录模型部署 ID、上游模型 ID 和厂商连接 ID。

上游失败不会自动切换到另一个同名模型部署。不同厂商的部署是不同用户选项，避免在计费、质量和请求适配器不同时静默切换。

## 错误处理

- 连接失败时停留在向导第二步，显示脱敏错误，不进入模型选择。
- 模型列表接口不可用但厂商连接通过时，允许使用预设候选或高级手动模型 ID，并明确标记“未从厂商列表验证”。
- 已选模型存在未确定类型或适配器时阻止保存；未选模型不参与校验。
- 模型测试失败时保持未发布，可在原记录上修改高级适配器并重测。
- 厂商连接禁用或删除前，检查关联已发布和默认模型；存在时阻止操作并列出需要先处理的模型。
- 所有管理接口继续使用管理员鉴权，错误响应保持 `{ code, data, msg }`，不返回完整凭证。

## 删除与历史

- 未发布、未被默认值、Workflow、Invocation 或 AI 任务引用的模型部署可以物理删除。
- 已有历史引用的模型部署只能取消发布和停用，不物理删除。
- 没有任何模型部署、历史引用和默认关系的厂商连接可以物理删除。
- Workflow / Invocation 继续保存模型部署 ID、厂商和上游模型快照，不因后续取消发布而改写历史。

## 验证范围

### 后端

- 厂商连接创建、脱敏读取、凭证保留、连接测试和删除门禁。
- 模型发现不持久化未选模型，默认选择为空。
- 预设、上游元数据、已知规则和待确认四级分类优先级。
- 各请求适配器的路径和最小测试请求，特别覆盖 Responses、GPT Image 和 Gemini 图片适配。
- 测试指纹、发布门禁、关键配置修改后自动取消发布、默认模型唯一性。
- 公开目录只返回已发布模型，不包含凭证和私有路由字段。
- 请求根据部署 ID 解析、验证入口并重写上游模型 ID；同名不同厂商部署不会静默切换。
- 管理员鉴权、严格请求解码、请求体上限和 `{ code, data, msg }` 响应。

### 前端

- 四步向导的步骤门禁，连接失败不能进入模型选择。
- 发现列表默认全部不选，支持搜索、类型筛选和高级手动模型 ID。
- 仅校验已选模型，待确认分类会阻止保存。
- 文本 / 图片 / 视频分栏、厂商分组、测试与发布状态、单类型默认模型。
- 图片和视频测试的费用风险确认。
- 普通用户只能看到已发布模型，已选模型失效时回退到同类型默认模型。

### 人工验收

1. 通过厂商预设创建一个连接，确认默认不勾选任何候选模型。
2. 搜索并选择一个 Responses 文本模型、一个 GPT Image 模型和一个视频模型，确认分类与适配器正确。
3. 保存后确认三个模型均为未测试、未发布，普通用户不可见。
4. 分别测试并发布，确认请求命中固化适配器，普通用户可以选择。
5. 修改 GPT Image 模型适配器，确认系统自动取消发布并要求重测。
6. 设置三类默认模型，确认普通用户可自由切换，且不能读取私有配置。

## 文档影响

实现时同步更新：

- `docs/api-response.md`：新增管理员模型配置和公开模型目录响应。
- `docs/features.md` 或 `docs/pending-test.md`：按项目验收流程记录已实现事项。
- `CHANGELOG.md`：在 `Unreleased` 中保留一条版本级归纳。

Provider Connection 和 Model Deployment 继续使用设置 JSON，因此不更新 `docs/backend-database.md`。
