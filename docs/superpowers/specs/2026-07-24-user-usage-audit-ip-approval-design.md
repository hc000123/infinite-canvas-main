# 用户用量、操作审计与异地 IP 登录审批设计

## 背景

管理后台当前将 AI 任务和算力点流水中的 `user_id` 直接显示为“用户”，列表接口也没有带出用户名，因此管理员需要手动对照用户列表，容易误以为用户名与用户 ID 不同步。

现有数据库只读核对结果表明，当前 AI 任务和算力点流水均能通过 `user_id` 关联到现有用户，根因在查询和展示层，不是底层 ID 写错。用户希望进一步从用户管理进入单个用户详情，查看该用户的操作、AI 用量和算力点流水，并识别在非工作 IP 登录后实际使用工具的账号，降低账号外借风险。

## 目标

- AI 任务日志和算力点日志始终同时展示当前用户名与稳定用户 ID。
- 管理员可以从用户列表进入独立用户详情页，查看资料、用量汇总、操作记录、AI 任务和算力点流水。
- 记录低频、可审计的业务事件，不记录拖拽、缩放、输入过程和自动保存等高频 UI 行为。
- 普通用户可按账号配置允许的 IP 或 CIDR 网段；非白名单 IP 登录需要管理员批准。
- 管理员可以仅批准本次登录、批准并加入白名单，或拒绝申请。
- 管理员账号始终不受 IP 限制，也不进入异地登录审批。
- 后台可以筛选“非白名单 IP 登录且执行过 AI 操作”的普通用户。

## 非目标

- 不记录键盘输入内容、完整 AI 请求正文、密码、登录 Token、AI API Key 等敏感信息。
- 不采集鼠标移动、画布拖拽、缩放、节点选择、输入过程、自动保存等高频行为。
- 不在本轮引入短信、邮件或第三方即时通信审批通知。
- 不使用 IP 地理位置作为自动封禁依据；本轮只依据管理员维护的 IP 白名单和审批结果。
- 不改变 AI 任务或算力点流水的记账规则，操作审计不参与余额计算。

## 核心规则

### 用户身份关联

- AI 任务、算力点流水和操作审计只保存稳定的 `user_id`。
- 管理后台查询时关联 `users` 表，返回当前 `username` 和 `display_name`。
- 用户修改用户名后，历史记录自动显示最新用户名，不复制或维护冗余用户名快照。
- 用户详情中的所有子查询必须同时带 `user_id` 条件。

### IP 限制对象

- 只有 `role=user` 的普通用户支持 IP 限制。
- `role=admin` 的管理员账号无条件跳过 IP 白名单和登录审批校验。
- 普通用户默认关闭 IP 限制，管理员完成白名单配置后再为该用户开启。
- 白名单支持单个 IPv4、单个 IPv6、IPv4 CIDR 和 IPv6 CIDR，使用 Go 标准库 `net/netip` 解析和匹配。

### 真实 IP

- 未配置受信任代理时，以连接对端地址为准，不直接相信客户端提交的 `X-Forwarded-For`。
- 部署在 Nginx、网关或 CDN 后时，只从配置的受信任代理链解析转发头。
- IP 统一规范化后再保存和匹配，避免 IPv4 映射地址等格式差异造成误判。

## 用户体验

### 用户列表

- 用户列继续展示头像、昵称和用户名，并新增“查看详情”入口。
- 点击用户主体或“查看详情”进入 `/admin/users/[id]`。
- 编辑、删除等原有操作保留，不把详情塞进拥挤的抽屉。

### 用户详情页

顶部身份卡展示头像、昵称、用户名、可复制用户 ID、角色、状态和编辑入口。

汇总卡展示：

- 当前算力点；
- 累计 AI 消耗；
- AI 任务总数；
- 最近登录时间。

详情区使用三个标签页：

1. **操作记录**：按时间倒序展示事件、结果、对象、IP、设备和风险状态，可按类型、时间和关键词筛选。
2. **AI 任务**：复用现有 AI 任务字段与详情能力，只查询当前用户。
3. **算力点流水**：复用现有流水字段，只查询当前用户。

安全设置区域展示“异地 IP 登录审批”开关和允许的 IP 列表。管理员可以输入 IP/CIDR、填写备注、从历史登录 IP 一键加入或移除规则。

### 独立日志列表

- `/admin/ai-tasks` 与 `/admin/credit-logs` 的用户列统一显示用户名或昵称，下一行显示可复制用户 ID。
- AI 任务的“用户”筛选同时匹配用户名、昵称和用户 ID。
- 算力点日志关键词同时匹配用户名、昵称、用户 ID、类型、备注和关联 ID。
- 用户已删除时保留原始用户 ID，并显示“用户已删除”，避免整条历史记录不可读。

### 登录等待页

普通用户在非白名单 IP 提交正确凭据后不立即获得正式登录 Token。登录页进入等待状态，展示申请时间、当前 IP、剩余有效时间，并轮询审批状态。

状态及文案：

- `pending`：等待管理员批准；
- `approved`：批准成功，换取正式会话后进入原目标页面；
- `rejected`：管理员已拒绝；
- `expired`：申请已过期，请重新登录；
- `consumed`：申请已用于创建会话，不能再次使用。

### 管理员审批页

后台菜单新增“登录审批”，未处理数量以徽标提示。页面默认展示待审批项，字段包括用户名、用户 ID、IP、设备、申请时间、该 IP 历史出现次数和最近一次操作。

操作包括：

- **拒绝**：申请进入 `rejected`；
- **仅批准本次**：允许当前 IP 获得一个绑定该 IP 的会话，不修改白名单；
- **批准并加入白名单**：先把当前单个 IP 加入该用户白名单，再批准申请。

历史页可按用户、IP、状态和时间筛选。

## 登录与审批状态流

1. 登录接口校验用户名和密码，或完成 Linux.do 身份确认。
2. 凭据错误时记录失败登录；响应继续使用统一的安全错误文案，不向外泄露账号是否存在。
3. 账号被禁用时记录拒绝原因并停止登录。
4. 管理员账号直接创建会话，不执行 IP 规则。
5. 普通用户未启用 IP 限制，或当前 IP 命中白名单时，记录成功登录并创建会话。
6. 普通用户已启用 IP 限制且当前 IP 未命中白名单时，创建有效期 10 分钟的 `pending` 申请，只向当前客户端返回一次性审批凭证。
7. 管理员作出决定后，等待页使用审批凭证查询状态；获批后通过独立交换接口创建正式会话。
8. 审批凭证只保存哈希，原文只返回发起登录的客户端；审批页和数据库查询均不能取得原文。
9. 申请只能从 `pending` 原子地进入 `approved`、`rejected` 或 `expired`。获批申请只能原子地交换一次，随后进入 `consumed`。
10. “仅批准本次”的会话在 Token 中带审批 ID 和获批 IP，后续鉴权请求必须来自同一规范化 IP；IP 改变后要求重新登录审批。
11. 白名单会话的后续鉴权请求必须继续命中该用户当前白名单。管理员移除规则或关闭账号后，后续请求立即失效。
12. 重复审批、审批过期、用户被禁用或删除、审批后 IP 改变时都不能签发或继续使用会话。

## 操作审计范围

### 记录的事件

- 账号：登录成功、登录失败、退出、资料修改、密码修改、账号禁用。
- 登录审批：创建、仅本次批准、加入白名单并批准、拒绝、过期、会话交换失败。
- 项目与画布：创建、重命名、删除。
- 素材：上传、创建、重命名、删除。
- AI：任务提交、成功、失败、取消，引用现有 AI 任务 ID。
- 数据流转：关键导入完成、导出完成、下载完成。
- 算力点：消费、返还、后台调整只引用现有流水或任务，不在审计表重复记账。

### 不记录的事件

- 鼠标移动、拖拽节点、画布缩放和平移；
- 节点或素材选择；
- 输入过程和表单逐字段变化；
- 自动保存、本地持久化和常规轮询；
- AI 请求正文、响应正文或媒体 base64。

### 前端上报

项目、画布和素材主要保存在浏览器本地，后端无法自动观察这些行为。前端只在目标动作成功后调用审计上报接口，并提交受控的事件类型、对象类型、对象 ID、对象名称和简短摘要。

后端从鉴权上下文确定用户 ID，从 HTTP 请求确定 IP 和设备信息；前端不能提交或覆盖这些字段。每次前端上报携带用户作用域内唯一的 `clientEventId`，后端幂等保存，避免重试产生重复记录。

AI 代理、算力点和登录等后端已经掌握结果的事件由对应 service 直接记录，不由前端重复上报。

## 数据模型

### `users` 新增字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ip_approval_enabled` | bool | 普通用户是否启用异地 IP 登录审批；管理员角色始终忽略 |

### `user_allowed_ips`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键 |
| `user_id` | string | 普通用户 ID，索引 |
| `cidr` | string | 规范化后的单个 IP 或 CIDR |
| `label` | string | 管理员备注 |
| `created_by` | string | 添加规则的管理员 ID |
| `created_at` | string | 创建时间 |

`user_id + cidr` 唯一。单个 IP 保存为对应的 `/32` 或 `/128`，匹配逻辑统一走前缀判断。

### `login_approvals`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 主键 |

| `user_agent` | string | 截断后的原始 User-Agent |
| `device_summary` | string | 浏览器、系统和设备摘要 |
| `token_hash` | string | 一次性审批凭证哈希 |
| `status` | string | `pending`、`approved`、`rejected`、`expired`、`consumed` |
| `approval_scope` | string | `once` 或 `whitelist` |
| `decided_by` | string | 审批管理员 ID |
| `decided_at` | string | 审批时间 |
| `expires_at` | string | 申请过期时间 |
| `session_id` | string | 获批交换后写入 Token 的会话 ID |
| `session_issued_at` | string | 固定会话签发时间，用于保证交换幂等边界 |
| `session_expires_at` | string | 会话过期时间 |
| `consumed_at` | string | 完成会话交换时间 |
| `created_at` | string | 申请时间 |

状态更新使用带旧状态条件的数据库更新，确保并发审批和交换只有一个请求成功。

| 字段 | 类型 | 说明 |
| --- | --- | --- |

| `action` | string | 受控动作枚举，索引 |
| `result` | string | `success`、`failed`、`rejected` |

| `target_id` | string | 操作对象 ID，索引 |
| `target_name` | string | 截断后的对象名称 |
| `summary` | string | 不含敏感正文的简短摘要 |

| `session_id` | string | 当前登录会话 ID，索引 |
| `login_approval_id` | string | 关联异地登录审批 ID |
| `user_agent` | string | 截断后的 User-Agent |

| `metadata` | string | 经过字段白名单过滤的 JSON |
| `created_at` | string | 发生时间，索引 |

失败登录到不存在的用户名时 `user_id` 为空，只在 `metadata` 中保存截断后的尝试用户名，不进入任何用户详情页。

## API 设计

所有接口继续使用 `{ code, data, msg }` 响应结构。

### 登录相关

- `POST /api/auth/login`：现有登录入口；成功时返回会话，需审批时返回申请 ID、一次性审批凭证、状态和过期时间。
- `POST /api/auth/login-approvals/:id/status`：使用一次性审批凭证查询状态，不把凭证放进 URL。
- `POST /api/auth/login-approvals/:id/exchange`：获批后使用一次性审批凭证换取正式会话。
- Linux.do 回调在建立普通用户会话前复用同一 IP 审批服务；管理员角色仍跳过。

### 用户操作上报

- `POST /api/v1/activity-logs`：普通用户上报允许的低频本地业务事件。handler 只解析入参并调用 service；事件白名单、长度限制、幂等和敏感字段过滤放在 service。

### 管理后台

- `GET /api/admin/users/:id`：用户资料和汇总。
- `GET /api/admin/users/:id/activity-logs`：单用户操作记录。
- `GET /api/admin/users/:id/ai-tasks`：单用户 AI 任务。
- `GET /api/admin/users/:id/credit-logs`：单用户算力点流水。
- `GET /api/admin/users/:id/allowed-ips`：用户 IP 白名单。
- `POST /api/admin/users/:id/allowed-ips`：添加 IP/CIDR。
- `DELETE /api/admin/users/:id/allowed-ips/:ruleId`：移除规则。
- `POST /api/admin/users/:id/ip-approval`：启用或关闭普通用户 IP 审批；管理员用户拒绝开启。
- `GET /api/admin/login-approvals`：审批列表，支持用户、IP、状态和时间筛选。
- `POST /api/admin/login-approvals/:id/approve-once`：仅批准本次。
- `POST /api/admin/login-approvals/:id/approve-and-allow`：批准并加入单个 IP 白名单。
- `POST /api/admin/login-approvals/:id/reject`：拒绝申请。
- 现有 `GET /api/admin/ai-tasks` 和 `GET /api/admin/credit-logs` 增加当前用户摘要与用户名查询能力。

## 后端分层

- `handler/`：解析 HTTP 入参、路径参数和查询参数，调用 service，返回 `OK` / `Fail`。
- `service/`：登录审批状态机、IP 匹配、管理员免限制、活动事件白名单、敏感信息过滤、汇总和权限校验。
- `repository/`：用户、白名单、审批、活动日志和分页查询；状态流转使用条件更新或事务。
- `model/`：新表结构、状态枚举、查询结构和简单模型方法。

用户名关联采用批量用户查询或数据库关联，避免列表逐条查询造成 N+1。

## 前端结构

- 新增 `web/src/app/(admin)/admin/users/[id]/page.tsx`，页面只有一个主业务组件，直接在 `page.tsx` 装配。
- 用户详情私有 hook 和组件放在 `users/[id]/` 当前目录，不提升到全局共享目录。
- 新增 `web/src/app/(admin)/admin/login-approvals/page.tsx` 和同目录私有 hook。
- API 请求统一扩展 `web/src/services/api/admin.ts` 与认证 API 文件。
- 登录等待状态保留原始跳转目标，审批成功后回到原页面。
- 复用 Ant Design、现有管理后台主题 token、ProTable、Descriptions、Tabs 和 Tag，不新增主题分支或全局页面样式。
- 审批列表按固定间隔低频刷新待处理数量，不引入 WebSocket。

## 风险查询

后台需要支持以下筛选：

- 非白名单 IP 登录；
- 非白名单 IP 登录且出现 AI 任务提交、成功、失败或取消事件；
- 指定用户、IP、时间范围；
- 登录失败次数；
- 待审批、已批准、已拒绝和已过期。

“非白名单 IP 登录且使用工具”以操作发生时保存的 `ip_allowed=false` 和 AI 类活动事件为依据，不根据后来修改后的白名单回写历史结果。

## 安全与隐私

- 登录错误继续使用统一文案，避免用户名枚举。
- 一次性审批凭证使用密码学安全随机数，只保存哈希，并设置 10 分钟有效期。
- 审批和交换使用原子状态更新，防止重复签发。
- 管理员决定由服务端鉴权上下文记录，前端不能提交 `decided_by`。
- 活动上报只接受固定事件类型和字段；字符串统一截断，metadata 按事件类型过滤。
- IP 和设备信息只在管理员后台可见。
- 不记录 Authorization、Cookie、密码、API Key、完整提示词、AI 请求/响应正文或媒体内容。
- 受限普通用户的后续请求重新读取当前用户状态与 IP 规则；禁用账号和越界 IP 立即失效。

## 异常处理

- 申请过期：状态查询或定期清理时原子更新为 `expired`，前端提示重新登录。
- 管理员重复操作：仅第一个 `pending` 状态更新成功，后续返回“申请已处理”。
- 审批后用户被禁用或删除：交换接口拒绝签发并记录安全事件。
- 批准并加入白名单失败：不批准申请，保证白名单写入和审批在同一事务中。
- 审批后 IP 改变：交换或后续鉴权拒绝，要求重新申请。
- 前端操作上报失败：不阻断已经成功的本地业务动作；在当前页面生命周期内有限重试，依赖 `clientEventId` 去重。
- 用户已删除：日志列表保留用户 ID 并显示“用户已删除”。

## 测试与验收

### 后端测试

- 当前用户名通过用户 ID 正确补充到 AI 任务和算力点列表。
- 用户名修改后历史记录显示新用户名，用户 ID 不变。
- 普通用户白名单 IP 登录直接成功。
- 普通用户非白名单 IP 登录进入待审批，不提前签发 Token。
- 管理员账号从任意 IP 登录和调用接口都不受限制。
- 仅批准本次后，只允许获批 IP 使用该会话。
- 批准并加入白名单后，新规则保存且当前申请可交换会话。
- 拒绝、过期、重复审批、重复交换、用户禁用或删除都不能签发新会话。
- 受信任代理和非受信任转发头分别得到正确客户端 IP。
- 前端审计事件白名单、字段截断、敏感字段过滤和幂等生效。
- 用户详情各分页接口严格按 `user_id` 隔离。
- 风险查询能返回非白名单 IP 下发生 AI 操作的用户。

### 前端测试

- 用户列表可进入正确用户详情。
- AI 任务和算力点列表同时展示用户名与用户 ID，并支持两者查询。
- 登录页正确处理等待、批准、拒绝和过期状态，并保留原跳转目标。
- 用户详情三个标签页、分页和筛选互不串用户。
- 管理员不能为管理员账号开启 IP 审批。
- 审批按钮重复点击不会发出并发重复请求。
- 高频 UI 行为不会触发操作上报，受控业务动作成功后只上报一次。
