# 项目级缓存管理设计

## 目标

在不引入云对象存储、不改变浏览器本地项目与素材主存储方式的前提下，把生成成功的图片、视频和音频自动复制到运行后端的本地磁盘，并按项目生产语义分类。用户可以从全局缓存中心统一查看占用、定位文件、清理缓存和生成完整项目包，也可以从项目详情直接进入当前项目的筛选视图。

本功能优先保证生成结果不因上游临时地址过期而丢失，以及磁盘目录可以脱离应用直接理解、复制和备份。

## 已确认边界

- 保持本地优先，不接云存储，不做跨设备同步。
- 图片、视频和音频生成成功后立即尝试写入项目缓存，不等待加入“我的素材”或设为主版本。
- 缓存实际落在运行 Go 后端的电脑或服务器磁盘，而不是只存在浏览器 IndexedDB。
- 缓存按项目、项目共享/具体分集/自由创作、业务类别和媒体类型分类。
- 全局提供缓存管理中心，项目详情提供进入当前项目缓存的快捷入口。
- 一键打包生成完整项目包，包含项目结构、剧本、画布、分镜、素材清单和缓存媒体。
- 删除浏览器本地项目时不自动删除磁盘缓存；缓存标记为“项目已删除/待清理”，由用户显式处理。
- 第一版不做自动清理、云备份、多人共享、后台转码或媒体内容审核。

## 方案选择

采用“文件目录 + `manifest.json`”作为真实数据源，不新增缓存数据库表。

理由：

- 目录可直接复制和压缩，符合本地版与后续制作交付习惯。
- 不会出现数据库索引存在但磁盘文件缺失后仍被误认为可用的双重真相。
- 当前单机/小团队规模下，扫描项目清单的成本可控。
- 后续如果文件规模显著增大，可以在不改变目录格式的情况下增加可重建索引。

## 磁盘结构

新增可配置根目录 `PROJECT_CACHE_DIR`，默认值为 `data/project-cache`。缓存不放进公开静态资源目录，所有读取、下载、打包和删除均通过登录鉴权接口完成。

```text
data/project-cache/
└── users/
    └── user_<hash>/
        ├── projects/
        │   └── 东海人鱼国__<project-hash>/
        │       ├── manifest.json
        │       ├── metadata/
        │       │   ├── project.json
        │       │   ├── canvases.json
        │       │   ├── scripts.json
        │       │   ├── storyboards.json
        │       │   └── assets.json
        │       ├── shared/
        │       │   ├── character/images/
        │       │   ├── scene/images/
        │       │   ├── prop/images/
        │       │   └── other/{images,videos,audios}/
        │       ├── episodes/
        │       │   └── 第01集__<episode-hash>/
        │       │       └── {character,scene,prop,storyboard,other}/{images,videos,audios}/
        │       └── free-canvas/
        │           └── <canvas-name>__<canvas-hash>/{images,videos,audios}/
        └── unassigned/
            ├── manifest.json
            └── {images,videos,audios}/
```

目录展示项目、分集和画布名称，哈希后缀保证重名时仍稳定唯一。任何用户输入只作为清理后的显示段使用；真实定位使用服务端计算的稳定哈希，禁止直接拼接未经验证的路径。

业务类别固定为 `character / scene / prop / storyboard / other`。没有项目上下文的工具生成结果进入当前用户的 `unassigned`，后续可在缓存中心移动到某个项目；无法确定分类时进入 `other`，不猜测业务含义。

## 清单格式与一致性

每个项目使用一个 `manifest.json`，记录：

- 项目 ID、名称、状态、首次与最后缓存时间。
- 文件 ID、相对路径、原文件名、媒体类型、字节数和 SHA-256。
- 项目、分集、画布、节点、素材、生产包和版本引用。
- 业务类别、来源动作、模型、渠道、提示词摘要、生成时间。
- 缓存状态及最后一次错误；敏感配置与 API Key 永不写入。

后端按用户和项目加锁，先写临时清单再原子重命名，避免并发完成多个生成任务时损坏 JSON。媒体先写临时文件，完成校验后再重命名到最终位置；只有媒体落盘成功后才追加清单。SHA-256 相同且业务引用相同的重复请求复用已有文件，避免刷新或重试生成重复副本；不同版本即使内容相同也保留独立引用。

应用启动或缓存中心刷新时执行轻量一致性检查：清单引用但文件缺失的项标记为“文件缺失”，目录中没有清单记录的文件标记为“待恢复”，不自动删除任何文件。

## 自动缓存数据流

1. 图片、视频或音频生成成功，前端先按现有逻辑保存浏览器本地副本并完成画布/素材回写。
2. 前端从当前项目、分集、画布和生成动作收集缓存上下文，提交媒体 Blob 与结构化元数据到项目缓存接口。
3. 后端鉴权、验证媒体类型与大小、计算安全目录、以临时文件写入、计算 SHA-256、原子移动并更新清单。
4. 前端把返回的缓存文件 ID、相对路径和状态写入节点或素材 metadata。
5. 缓存失败不把 AI 生成任务改为失败；前端保存一条按账号隔离的本地重试任务，并在用户重新进入应用、有网络且登录有效时重试。
6. 达到有限重试次数后保持“待处理”状态，在缓存中心显示原因并提供手动重试。

未登录时继续只保存浏览器本地副本，并显示“登录后可写入项目磁盘缓存”。生成结果没有明确项目 ID 时进入 `unassigned`，保证结果仍能落盘。

旧的 `/canvas/media-cache` 平面缓存接口收口到新的项目缓存服务。已有节点上的 `cachePath/cacheUrl` 继续可读，但新写入统一使用结构化 `projectCache` metadata；项目尚未上线，不增加旧缓存文件自动迁移逻辑。

## 后端接口

新增登录用户接口，均从登录态确定用户目录，不接收可覆盖的用户 ID：

- `POST /api/v1/project-cache/files`：上传并归档一个媒体文件。
- `GET /api/v1/project-cache/projects`：列出项目缓存、未归属缓存、容量和一致性状态。
- `GET /api/v1/project-cache/projects/:id`：读取项目清单和分类统计。
- `GET /api/v1/project-cache/files/:id`：鉴权读取或下载文件。
- `POST /api/v1/project-cache/files/:id/move`：把未归属文件移动到项目分类。
- `POST /api/v1/project-cache/projects/:id/status`：标记项目活动或已删除，不删除文件。
- `POST /api/v1/project-cache/projects/:id/package`：接收当前浏览器项目快照并流式生成完整 ZIP。
- `DELETE /api/v1/project-cache/files/:id`：显式删除单个缓存文件。
- `DELETE /api/v1/project-cache/projects/:id`：二次确认后删除整个项目缓存。

列表与详情接口只读取清单和必要的文件统计，不把媒体内容编码进 JSON。ZIP 使用 Go 标准库流式写出，避免把完整项目包同时读入内存或长期重复保存在磁盘。

## 完整项目包

打包时前端从现有本地 Store 生成最新项目快照，后端校验项目归属后写入 ZIP：

```text
项目名__导出时间.zip
├── package-manifest.json
├── metadata/
│   ├── project.json
│   ├── canvases.json
│   ├── scripts.json
│   ├── storyboards.json
│   └── assets.json
├── shared/
├── episodes/
└── free-canvas/
```

`package-manifest.json` 包含应用版本、导出格式版本、导出时间、文件清单、校验值和缺失项警告。存在缺失文件时先返回打包预检结果，由前端明确展示；用户继续后，ZIP 保留缺失清单但不伪造文件。第一版只保证完整备份和可审计交付，不同时实现完整项目导入恢复。

## 缓存管理界面

新增 `/cache` 全局缓存中心，沿用当前工作台主题与极简扁平视觉：

- 顶部显示缓存根目录、总占用、项目数、文件数和待处理数。
- 左侧或窄栏显示全部项目、未归属、已删除项目；项目按最后缓存时间排序。
- 主区域显示共享/分集/自由创作分类树、媒体类型统计和文件列表。
- 支持项目、分集、类别、媒体类型、状态和关键词筛选。
- 文件行显示缩略信息、版本、来源、大小、时间、相对路径和一致性状态。
- 项目操作包括复制目录路径、生成完整项目包、重新检查、标记状态和清理缓存。
- 删除单个文件或整个项目必须二次确认，并明确提示不会删除浏览器本地项目；删除项目缓存属于不可恢复操作。

项目详情增加“管理缓存”按钮，跳转到 `/cache?projectId=<id>`。不在项目详情重复实现一套缓存列表。

## 项目删除与孤立缓存

前端删除项目成功后调用状态接口，把清单标记为 `deleted`，但不删除媒体。缓存中心同时把浏览器当前项目 ID 列表与磁盘清单比较；本地数据被清空、但磁盘仍存在的缓存显示为“本地项目不存在”。这两类缓存都归入“待清理”，仍可先打包。

项目恢复同一 ID 时可重新标记为活动。重名但 ID 不同的项目绝不自动合并。

## 错误与容量处理

- 磁盘空间不足、权限不足或文件写入失败时保留浏览器本地结果，并把缓存任务标记为失败。
- 上传接口限制媒体类型与单文件大小，拒绝空文件、路径穿越和伪造扩展名。
- 列表接口遇到单个损坏清单时返回该项目错误状态，不阻断其他项目展示。
- 删除失败时不提前改写清单；部分删除只标记实际结果并允许重试。
- 第一版不自动按容量删除旧文件，只显示占用和警告，所有删除均由用户确认。

## 测试与验收

后端测试覆盖：安全目录生成、重名项目隔离、媒体类型校验、原子清单更新、重复归档、并发写入、用户隔离、孤立文件识别、删除保护、缺失文件预检和流式 ZIP 内容。

前端纯函数测试覆盖：缓存上下文分类、项目快照、筛选统计、重试状态和项目删除后的状态同步。页面验收覆盖：生成成功自动落盘、失败不影响生成结果、全局与项目快捷入口、未归属移动、完整项目打包、缺失文件警告、显式清理和浅/深色主题。

按照项目约定，本任务只运行新增或直接相关的定向测试，不执行完整构建或全量测试。
