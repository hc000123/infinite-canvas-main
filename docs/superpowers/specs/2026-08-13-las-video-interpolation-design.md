# LAS 视频智能插帧接入设计

## 目标

在现有画布视频超分流程中接入火山引擎北京地域 LAS 视频插帧算子 `las_video_interpolation`。用户可选择保持原帧率、智能插帧 2× 或智能插帧至 60fps，并在创建付费任务前看到 LAS 超分、LAS 插帧及总费用预估。

本功能沿用现有画布入口、右侧单一派生节点、任务轮询、结果缓存和资产归档行为。选择插帧时固定按“视频超分 → 视频插帧”串联，不增加第二个画布节点，不使用 FFmpeg 补帧冒充 AI 插帧。

## 用户界面

现有“视频超分”弹窗继续提供目标清晰度、输出质量和音频选项，并启用帧率选择：

- 保持原帧率：只执行 LAS 视频超分。
- 智能插帧 2×：目标帧率为服务端识别的输入帧率乘以 2。
- 智能插帧至 60fps：输入帧率低于 60fps 时目标为 60fps；输入帧率达到或超过 60fps 时不可选。

选择智能插帧后显示插帧模式：

- 极速 `ultra-fast`：优先处理速度。
- 快速 `fast`：速度与质量均衡，作为界面默认值。
- 高质量 `medium`：优先效果，处理较慢且计费系数更高。

“保留原音频”同时作用于超分和插帧阶段。弹窗固定提示处理顺序为“LAS 超分 → 智能插帧”。

## 服务端参数校验

创建任务时先把输入保存到服务端，再用 `ffprobe` 获取宽、高、时长和可靠源帧率。任何 LAS 付费 Submit 发生前完成以下校验：

- 帧率模式只接受 `keep / double / to60`。
- 插帧模式只接受 `ultra-fast / fast / medium`；保持原帧率时忽略插帧模式。
- 插帧目标必须大于源帧率。
- 插帧目标必须小于或等于 `min(480, source_fps × 6)`。
- `to60` 在源帧率达到或超过 60fps 时拒绝。
- 无法可靠识别源帧率时，选择插帧会在本地校验阶段失败，不提交超分或插帧任务；选择保持原帧率仍可创建超分任务，但不生成费用预估。

源帧率只信任 `ffprobe` 的 `avg_frame_rate`，无效时回退 `r_frame_rate`。项目预设 FPS 和普通画布元数据不得用于服务端校验或付费预估。

## 任务数据与状态

继续使用同一条 `video_upscale_jobs` 任务记录，增加并冻结：

- 插帧处理模式；
- 插帧目标帧率；
- 插帧 LAS Task ID；
- 插帧输出 TOS 地址；
- 超分费用快照；
- 插帧折算分钟与费用快照；
- 总费用快照；
- 插帧计价规则版本。

现有 `run_id` 继续表示超分 Task ID，新字段单独保存插帧 Task ID，避免恢复任务时混淆阶段。任务状态仍使用原有公开生命周期，额外持久化内部处理阶段：

```text
上传输入 → 提交/查询超分 → 提交/查询插帧 → 下载最终结果 → 成功
```

选择保持原帧率时跳过插帧阶段。选择插帧时，超分返回的 `output_video_tos_url` 直接作为插帧 `video_url`，不在两个 LAS 阶段之间下载和重新上传。

## LAS 插帧调用

复用当前北京地域 LAS BaseURL、Bearer API Key、同主账号北京 TOS 和现有 LAS HTTP Client：

```json
{
  "operator_id": "las_video_interpolation",
  "operator_version": "v1",
  "data": {
    "video_url": "tos://bucket/video-upscale/output/upscaled.mp4",
    "output_tos_path": "tos://bucket/video-upscale/output/",
    "target_fps": 60,
    "mode": "fast",
    "preserve_audio": true,
    "output_basename": "job-id-interpolation"
  }
}
```

Poll 使用同一 `/api/v1/poll`，但 `operator_id` 固定为 `las_video_interpolation`。成功时优先使用返回的 `output_video_tos_url` 作为持久化上游地址；若只有 `output_video_url`，仍需经过现有公网下载安全校验。

TOS 继续使用现有输出目录，不要求用户手工创建文件夹。`output_basename` 带任务 ID 和阶段后缀，避免超分与插帧结果重名。

## 插帧计费

单价固定为 `0.5 元 / 折算分钟`：

```text
差值帧率 = 目标帧率 - 输入帧率
帧率倍数 = ceil(差值帧率 / 30)
折算分钟 = 视频时长（秒）÷ 60 × 分辨率基础系数 × 帧率倍数
插帧预计费用 = 0.5 × 折算分钟
```

分辨率按插帧输入，即超分输出视频的总像素数分类。使用官方参考最大像素数，而不是只看短边：

| 输出像素数 | `ultra-fast / fast` 基础系数 | `medium` 基础系数 |
| --- | ---: | ---: |
| ≤ 927,408（720P） | 1 | 4 |
| ≤ 2,086,876（1080P） | 3 | 8 |
| ≤ 3,709,632（1440P） | 4 | 14 |
| ＞ 3,709,632 | 10 | 24 |

该写法与官方表格等价：差值帧率 ≤30、≤60、≤90 时分别乘以 1、2、3；超过 90 时继续按 `ceil(差值帧率 / 30)` 扩展。

例如输入 60fps、输出 120fps、720P、`medium`、时长 5 分钟：差值为 60、帧率倍数为 2、基础系数为 4，费用为 `0.5 × 5 × 4 × 2 = 20 元`。

## 费用展示

能力接口增加插帧可用状态、模式、目标规则、单价、分辨率系数和计价规则版本。弹窗使用能力接口规则实时计算，不在组件中硬编码价格。

费用卡片分别显示：

- LAS 超分费用；
- 插帧输入分辨率；
- 源帧率、目标帧率和差值帧率；
- 插帧模式与基础系数；
- 插帧折算分钟；
- 插帧预计费用；
- 预计总费用。

只有时长、源帧率和输出尺寸都可靠时才显示完整金额。选择插帧但缺少可靠帧率时，界面显示“上传后由服务端识别，识别成功前不会提交付费任务”，提交按钮不显示虚假金额。金额内部保留完整精度，界面显示两位小数，并固定标注“预估金额，实际费用以火山引擎账单为准”。

## 重试、恢复与扣费安全

- 超分尚未提交时重试：可重新上传并提交超分。
- 已有超分 Task ID：只能 Poll 同一超分任务，不得重新 Submit。
- 超分成功但插帧尚未提交：复用已保存的超分 TOS 输出提交一次插帧。
- 已有插帧 Task ID：只能 Poll 同一插帧任务，不得重新 Submit。
- 插帧成功但下载或本地归档失败：只重新获取和保存现有结果，不重新提交任何 LAS 任务。
- 服务重启按持久化阶段恢复；无法判断某次 Submit 是否成功时标记人工可重试失败，不自动创建可能重复扣费的任务。
- 不修改原视频节点；最终结果继续写入同一个右侧派生节点。

## 错误处理

- 非法目标帧率或模式：本地校验失败，不调用 LAS。
- LAS 插帧返回 `FAILED / TIMEOUT`：任务失败并显示安全错误信息，保留超分结果和两个 Task ID 供诊断。
- 插帧响应 `processed=false`：不把它标记为成功插帧；返回明确的参数未处理提示。
- TOS 地址不属于可解析格式、最终结果为空或格式异常：沿用现有安全失败处理。
- 能力接口不可用：禁用创建任务，不使用前端硬编码价格或能力兜底。

## 测试

- Go 纯函数覆盖三种模式、四档像素边界、差值帧率 30/60/90/>90、23.976×2、60→120 官方 20 元示例、非法目标帧率和未知元数据。
- Go 服务测试覆盖 `double / to60` 校验、无帧率零付费 Submit、费用快照持久化和重试恢复阶段。
- Provider 测试覆盖正确 operator、target_fps、mode、音频、TOS 串联、插帧 Poll 和 `processed=false`。
- 前端测试覆盖三种帧率选择、三种模式、费用明细、未知帧率、不可用 60fps、两位小数和提交参数。
- 自动测试只使用纯函数、假 Provider 和本地媒体，不创建真实 LAS 任务。

## 不在本阶段范围内

- 插帧独立于超分的单独画布工具；
- 自定义任意目标帧率输入框；
- 4K 超分、HDR、字幕抹除、音频降噪；
- 本地 RIFE 或其他 GPU 插帧方案；
- 将费用预估作为扣费上限、配额或正式账单系统；
- 新的真实付费测试。
