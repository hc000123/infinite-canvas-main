# 单设备登录与会话管理设计

## 背景

当前系统使用前端持久化 JWT 登录。JWT 默认固定 168 小时过期，后端会在每次请求时校验签名、有效期、用户状态和可选 IP 绑定；登录成功、失败、IP 审批和部分账号操作已经写入 `user_activity_logs`。管理后台能够看到最近登录时间和操作记录中的 IP、User-Agent，但系统没有独立登录会话，也没有把稳定会话 ID 写入 JWT 和请求上下文。

因此当前存在以下缺口：

- 无法准确表示一个账号当前是否在线以及在哪个设备登录。
- 无法立即撤销已经签发的某一个 JWT。
- 无法实现新设备登录后旧设备立即失效。
- 无法区分被新登录顶替、管理员强制下线、主动退出和自然过期。
- 后台不能展示当前会话的登录时间、最后活跃时间、设备、IP 和过期状态。

## 目标

本次将登录状态调整为服务端可控的单会话模型：

1. 普通用户、管理员和超级管理员都只允许一个有效登录会话。
2. 新登录成功后立即顶掉旧登录，不拒绝新设备。
3. 连续 7 天没有有效请求则自动失效；单次会话最长 30 天必须重新登录。
4. 管理员可以强制普通用户下线；超级管理员可以强制普通用户和管理员下线。
5. 超级管理员不能强制其他超级管理员下线。
6. 强制下线必须填写原因，并记录完整审计信息。
7. 后台展示当前会话的必要信息，同时保持 IP、凭证和本地画布数据安全。

## 非目标

- 不支持一个账号同时保留多个可信设备。
- 不新增“记住我”或由用户选择会话时长的开关。
- 不实现复杂的短访问凭证与刷新凭证轮换体系。
- 不依赖浏览器指纹判断真实物理设备，也不承诺防止用户主动复制完整浏览器环境。
- 不改变画布、项目和素材仍主要保存在浏览器本地的现状。

## 核心规则

### 单会话

`users.active_session_id` 是账号当前有效会话的唯一指针。每次成功登录在同一事务中：

1. 将原有效会话标记为 `replaced`。
2. 创建新的 `login_sessions` 记录。
3. 将用户的 `active_session_id` 指向新会话。
4. 签发包含新 `sessionId` 的 JWT。

任何旧 JWT 即使尚未到自身过期时间，也会因为 `sessionId` 不再等于用户当前有效会话而立即失败。并发登录最终只以 `users.active_session_id` 指向的会话为准。

注册后自动登录、账号密码登录、登录审批兑换和仍然保留的第三方登录入口都必须走同一个会话创建流程，不能存在绕过单会话规则的签发路径。

### 有效期

- `last_active_at + 7 天`：空闲过期时间。
- `created_at + 30 天`：绝对过期时间。
- JWT 的 `exp` 与绝对过期时间一致，服务端会话负责额外执行 7 天空闲检查。
- 有效请求最多每 5 分钟更新一次 `last_active_at`，避免每个请求都写数据库。
- 后台查询、轮询和 AI 任务状态请求都属于用户主动打开应用期间的有效活动；失败鉴权请求不刷新活跃时间。

会话达到任一过期条件后，后端将其标记为 `idle_expired` 或 `absolute_expired`，并在用户仍指向该会话时清空 `active_session_id`。

### 下线来源

会话状态使用受控值：

- `active`：当前有效。
- `replaced`：被同账号的新登录顶替。
- `logged_out`：用户主动退出。
- `admin_revoked`：管理员或超级管理员强制下线。
- `idle_expired`：连续 7 天无活动。
- `absolute_expired`：达到 30 天最长时限。
- `account_changed`：禁用账号、重置密码或安全相关账号变更导致失效。

旧会话保留用于审计，不物理删除。后台“在线”仅表示存在通过当前规则校验的 `active` 会话，不代表浏览器窗口此刻一定处于前台。

## 数据结构

### users

新增：

| 字段 | 说明 |
| --- | --- |
| `active_session_id` | 当前唯一有效登录会话 ID；无有效会话时为空 |

### login_sessions

新增登录会话表：

| 字段 | 说明 |
| --- | --- |
| `id` | 随机会话 ID，主键 |
| `user_id` | 登录用户 ID，索引 |
| `status` | 会话状态，索引 |
| `ip_address` | 登录时由服务端解析的 IP |
| `user_agent` | 截断后的原始 User-Agent |
| `device_name` | 服务端从 User-Agent 归一化出的浏览器、系统摘要 |
| `created_at` | 登录时间 |
| `last_active_at` | 最近有效请求时间 |
| `absolute_expires_at` | 30 天绝对过期时间 |
| `revoked_at` | 被替换、退出、强制下线或账号变更的时间 |
| `revoked_by` | 强制下线的操作者 ID；系统或本人操作时为空 |
| `revoke_reason` | 强制下线原因或受控系统说明 |
| `updated_at` | 最近更新时间 |

不保存 JWT、密码、Authorization 头、API Key 或可复用登录凭证。IP 和 User-Agent 仅供安全审计，并沿用现有后台权限边界。

### JWT

`TokenClaims` 新增 `sessionId`。后端不再接受没有 `sessionId` 的历史 JWT；项目尚未上线，不增加旧 Token 兼容分支，更新后所有现有登录自然失效并需要重新登录一次。

## 鉴权流程

所有 `UserAuth`、`AdminAuth`、`SuperAdminAuth` 和 `OptionalAuth` 统一使用同一会话校验：

1. 校验 JWT 签名、算法和 `exp`。
2. 读取用户，确认账号存在且未禁用。
3. 确认 JWT `sessionId` 等于 `users.active_session_id`。
4. 读取会话并确认属于该用户且状态为 `active`。
5. 检查 7 天空闲和 30 天绝对过期。
6. 继续执行现有 IP 绑定规则。
7. 将会话 ID 写入 `RequestMeta.SessionID`，必要时节流更新最后活跃时间。

会话校验失败时返回统一 `{ code, data, msg }`，但使用可区分的业务状态码和安全化原因：

- `AUTH_SESSION_REPLACED`：账号已在其他设备登录。
- `AUTH_SESSION_REVOKED`：账号已被管理员强制下线，可返回管理员填写的安全化原因。
- `AUTH_SESSION_IDLE_EXPIRED`：登录状态因长时间未使用失效。
- `AUTH_SESSION_EXPIRED`：登录状态已到最长有效期。
- `AUTH_SESSION_INVALID`：其他无效或缺失会话。

前端请求层统一识别这些状态，清除内存及持久化 Token，保留按用户隔离的本地画布、项目和素材数据，并跳转登录页。登录页只显示必要原因，不显示操作者 ID、内部会话 ID或其他敏感信息。

## API

### 用户侧

- `POST /api/auth/logout`：撤销当前会话并清空用户当前会话指针。退出操作必须先请求服务端，网络失败时仍清除本地凭证，服务端会话最迟按有效期失效。
- `GET /api/auth/me`：保持当前用户响应；失效会话返回明确会话错误，不再静默伪装成正常登录用户。

### 普通用户管理

- `GET /api/admin/users/:id/session`：管理员和超级管理员查看普通用户当前会话摘要。
- `POST /api/admin/users/:id/force-logout`：管理员或超级管理员强制普通用户下线，请求体为 `{ reason }`。

### 管理员账号管理

- `GET /api/admin/admins/:id/session`：仅超级管理员查看管理员当前会话摘要。
- `POST /api/admin/admins/:id/force-logout`：仅超级管理员强制管理员下线，请求体为 `{ reason }`。

强制下线的 `reason` 去除首尾空白后必须为 2–200 个字符。Service 层再次验证目标角色，不能依赖前端隐藏按钮：

- `admin` 只能操作 `user`。
- `superadmin` 可以操作 `user` 和 `admin`。
- 任何人都不能通过管理接口强制 `superadmin` 下线。
- 已离线目标返回当前状态，不伪造新的下线记录，也不重复写审计。

## 账号变更联动

以下安全事件必须撤销当前会话：

- 用户或管理员重置该账号密码。
- 账号被禁用或删除。
- 普通用户与管理员之间的角色调整。

仅修改昵称、邮箱、头像、算力点或 IP 白名单不强制下线。开启 IP 审批后，当前会话继续按签发时规则运行；下一次登录使用新策略，避免配置操作意外打断正在编辑的画布。

## 审计

在现有 `user_activity_logs` 中增加并展示：

- `security.session_replaced`
- `account.logout`
- `security.session_force_logout`
- `security.session_idle_expired`
- `security.session_absolute_expired`
- `security.session_account_changed`

登录成功及后续用户操作都写入真实 `session_id`。强制下线记录操作者、目标用户、目标会话、原因、服务端 IP 和时间；用户详情展示面向管理员的摘要，不暴露 JWT 或内部凭证。

## 管理后台

### 普通用户列表与详情

用户列表增加“登录状态”和“最后活跃”两列：

- 在线：当前会话通过有效性校验。
- 离线：无有效会话。

用户详情新增“当前登录”卡片，展示：

- 在线状态
- 登录时间
- 最后活跃时间
- 最长有效期
- 登录 IP
- 浏览器与操作系统摘要
- 当前会话状态

有权限且目标在线时显示“强制下线”按钮。确认弹窗要求输入原因，提交成功后立即刷新会话卡片和操作记录。

### 管理员账号页

超级管理员管理管理员账号时展示相同的当前会话摘要，并可强制 `admin` 下线。超级管理员行不显示强制下线按钮。

### 用户侧失效体验

- 被新登录顶替：“账号已在其他设备登录，请重新登录。”
- 被管理员强制下线：“账号已被管理员下线：{原因}”
- 空闲过期：“登录状态已过期，请重新登录。”
- 30 天过期：“为保障账号安全，请重新登录。”

画布及本地业务数据不因清除登录状态而删除。重新登录同一账号后继续使用原本按用户隔离的本地数据；不同账号不能读取前一账号的本地空间。

## 异常与并发

- 两次登录并发时，以事务最终写入的 `active_session_id` 为准，另一会话即使暂时创建成功也无法通过后续鉴权。
- 强制下线与新登录并发时，Service 层在事务内重新读取目标当前会话，只撤销当时仍被用户指向的会话。
- 会话记录缺失、用户指针不一致或状态异常都按无效会话处理，不自动修复为在线。
- 最后活跃时间更新失败不影响当前业务请求，但记录服务端日志；鉴权读取失败按安全失败处理。
- 前端同时收到多次会话失效响应时只执行一次清理和跳转，避免重复提示。

## 验收

后端至少覆盖：

1. 所有角色第二次登录都会使第一次登录立即失效。
2. 新登录事务最终只保留一个用户当前会话指针。
3. 7 天空闲和 30 天绝对过期分别返回正确原因。
4. 主动退出后原 Token 不能继续调用接口。
5. 管理员只能强制普通用户下线。
6. 超级管理员可以强制普通用户和管理员下线，但不能操作超级管理员。
7. 强制下线原因必填并正确写入审计。
8. 禁用、删除、重置密码和角色安全变更会撤销会话。
9. 登录审批和其他现有登录入口同样遵循单会话规则。
10. 活动记录包含真实会话 ID，且不保存敏感凭证。

前端至少覆盖：

1. 用户详情与管理员账号页正确展示当前登录信息和权限按钮。
2. 强制下线必须填写原因。
3. 被顶替、被强制下线和自然过期显示不同提示。
4. 多个并发请求同时失败时只清理和跳转一次。
5. 清除登录凭证不会删除画布、项目和素材的本地数据。

人工验收使用两个独立浏览器或无痕窗口验证新登录顶替旧登录，再分别验证管理员和超级管理员权限边界、强制下线原因、后台在线状态及重新登录后的本地数据恢复。
