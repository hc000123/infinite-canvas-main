# 火山 Ark Seedance 2.5 新增模型适配设计

## 背景

项目现有火山 Ark 视频通道以 Seedance 2.0 为默认能力边界：厂商预设只创建一个 2.0 本地模型与 Endpoint 映射，视频请求把时长限制在 4–15 秒、参考素材限制为 9 图 / 3 视频 / 3 音频，并禁止纯音频输入。

火山方舟已经公开 Seedance 2.5。新模型继续使用 `POST /contents/generations/tasks`，但支持 4–30 秒、480p / 720p、最多 30 张图片 / 10 个视频 / 10 个音频，并允许仅音频输入。视频编辑任务还要求 `duration = -1`，首帧、首尾帧、视频编辑和视频延长等任务对 `ratio` 有更严格的 `adaptive` 规则。

本次在保留 Seedance 2.0 的前提下新增 Seedance 2.5，不替换用户已有的 2.0 配置。

## 目标

- 火山 Ark 渠道可同时配置和公开 Seedance 2.0、Seedance 2.5。
- 两个本地模型分别映射自己的火山 Endpoint，避免共用或覆盖 Endpoint。
- 前端设置、素材收集和任务 payload 按当前模型应用正确能力。
- 后端代理在请求发往火山前再次执行模型感知的规范化与兜底校验。
- 不改变即梦 CLI、星链云或通用 OpenAI 视频渠道行为。
- 不调用真实视频生成接口进行验证。

## 非目标

- 不迁移或自动改写现有 Seedance 2.0 Endpoint。
- 不增加 Draft、离线推理、优先级、任务过期时间等本次界面尚未提供的高级参数。
- 不重构所有视频供应商为新的通用能力框架。
- 不为 2.5 新建专属画布节点或独立页面。

## 模型与 Endpoint 配置

项目继续使用“本地模型名 -> 火山 Endpoint ID”的既有路由方式：

| 本地模型名 | 用途 | Endpoint |
|---|---|---|
| `doubao-seedance-2-0` | 现有 Seedance 2.0 | 保留现有 2.0 EP |
| `doubao-seedance-2-5` | 新增 Seedance 2.5 | 用户填写独立 2.5 EP |

火山厂商预设增加 2.5 Endpoint 输入，并生成两条模型映射。已有火山渠道再次应用预设时，保留已保存的 API Key 和可识别的 2.0 映射；只有用户明确填写 2.5 EP 时才发布可用的 2.5 模型，不用空 Endpoint 创建不可路由模型。

手动渠道向导继续复用现有多行 Endpoint 映射，不增加另一套配置结构。

## 能力规则

能力判断以本地模型名为主。Endpoint ID 只负责上游路由，不用于推断模型版本。

| 能力 | Seedance 2.0 | Seedance 2.5 |
|---|---:|---:|
| 输出时长 | 4–15 秒 | 4–30 秒；编辑任务固定 `-1` |
| 分辨率 | 沿用现有规则 | 480p、720p |
| 图片参考 | 最多 9 张 | 最多 30 张 |
| 视频参考 | 最多 3 个 | 最多 10 个 |
| 音频参考 | 最多 3 个 | 最多 10 个 |
| 纯音频输入 | 不支持 | 支持 |
| 首帧 / 首尾帧比例 | 沿用当前可选比例 | 固定 `adaptive` |
| 视频编辑 / 延长比例 | 沿用当前可选比例 | 固定 `adaptive` |

2.5 多模态参考的各类型上限分别校验，不额外增加文档未声明的总素材数限制。前端收集素材时按模型上限截取，payload 构造和后端代理仍分别做显式校验，避免静默丢弃超限输入。

## 请求数据流

1. 用户从公开模型中选择 `doubao-seedance-2-5`。
2. 画布或视频页从当前配置解析模型能力，并据此显示、规范化时长和分辨率。
3. 素材收集按 2.5 上限保留有序的图片、视频、音频引用。
4. payload 构造根据任务类型处理参数：
   - 文生和普通多模态参考生成可使用 4–30 秒及用户选择的合法比例。
   - 首帧、首尾帧、视频编辑、视频延长使用 `ratio: adaptive`。
   - 视频编辑使用 `duration: -1`。
5. 后端根据本地模型能力校验输入，再把 `model` 替换为对应 Endpoint ID 后提交火山。
6. 查询任务和结果归档继续复用现有 Ark 流程。

## 错误处理

- 2.5 未配置 Endpoint：沿用现有模型不可路由提示，不创建任务。
- 2.5 素材超限：指出具体超限类型与允许数量。
- 2.0 纯音频：继续返回现有阻断提示。
- 2.5 非法分辨率：规范化为 720p；不把 1080p 或 4K 发给上游。
- 2.5 编辑任务的具体正时长：前后端均规范化为 `-1`。
- 空提示词但存在合法音频或其他素材：允许提交；文本和素材均为空时仍阻断。

## 测试与验收

自动化覆盖应包括：

- 火山预设同时保存 2.0 和 2.5 的独立 Endpoint 映射。
- 未填写 2.5 Endpoint 时不发布不可路由模型。
- 2.5 保留 30 秒，2.0 仍收敛到 15 秒。
- 2.5 只输出 480p / 720p。
- 2.5 接受纯音频，2.0 继续拒绝纯音频。
- 2.5 接受 30 图 / 10 视频 / 10 音频边界，并拒绝任一类型溢出。
- 2.5 首帧、首尾帧、编辑和延长任务使用 `adaptive`。
- 2.5 编辑任务使用 `duration: -1`。
- 现有 2.0 payload 与 Endpoint 路由保持不变。

按项目日常开发约定，本次实现完成后不主动运行构建或完整测试；不执行任何真实视频生成。可通过代码审查和用户后续页面验收确认配置与交互，真实付费冒烟必须另行获得明确授权。
