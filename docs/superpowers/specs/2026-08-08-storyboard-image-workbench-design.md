# 分镜制作工作台设计

## 目标

将顶部现有“生图”入口升级为按项目和集数工作的分镜制作工作台。工作台直接复用该集现有分镜表，让用户逐镜维护槽位、生成多张候选图，并为每个镜头确定唯一的最终分镜图。

改造不得影响现有资产生图能力：资产主体工作台继续内嵌生成；视频工作流与旧资产卡携带资产上下文进入 `/image` 时，继续使用现有资产生图界面和结果回写链路。

## 已确认范围

首版包含：

- 选择项目和集数。
- 自动读取该集现有分镜表。
- 新增单个或批量空分镜槽位。
- 删除和拖拽排序槽位。
- 编辑逐镜画面提示词。
- 从素材库、本地上传和剪切板添加逐镜参考图。
- 使用 `@参考图N` 在提示词中显式引用参考图。
- 配置逐镜模型、比例、清晰度、质量和单次生成数量。
- 复用上一镜或其他镜头的生成配置。
- 为当前镜头生成多张候选图。
- 候选图按镜头持续保存，支持失败槽位重试。
- 每个镜头只能选取一张最终分镜图，并可取消或改选。
- 下载候选图、把候选图保存为正式资产。
- 移动端使用横向槽位轨道，配置区与候选区纵向排列。

首版不包含 4K 超分、去水印、视频生成或云同步。

## 方案选择

### 采用：`/image` 按上下文分流

- 普通打开 `/image` 时渲染分镜制作工作台。
- 查询参数包含 `libraryAssetId`、`assetId` 或 `briefId` 等明确资产上下文时，渲染现有资产生图工作台。
- 顶部导航把“生图”改名为“分镜”，路径仍为 `/image`，避免无必要的路由迁移。
- 资产卡当前的 `buildImageWorkbenchHref`、提示词预填、来源项目/集数和保存回写保持原契约。

选择该方案是因为它同时满足“替换顶部入口”和“资产生图不受影响”，且不需要建立第二条路由兼容链。

### 未采用：新增 `/storyboard`

路由语义更纯粹，但需要迁移导航、维护 `/image` 重定向，并增加旧链接验收面。

### 未采用：嵌入单集视频工作流

项目上下文最强，但会让已较复杂的视频工作流继续变重，也不符合独立顶部工作台的目标。

## 页面结构

### 顶部上下文栏

显示项目选择器、集数选择器、镜头数量和本地自动保存状态。无可用项目或集数时显示明确空状态，并提供进入项目中心的动作。

默认选择顺序：

1. URL 中有效的 `projectId` 和 `episodeId`。
2. 上次在分镜工作台选择的项目和集数。
3. 第一个未归档且包含集数的项目及其第一集。

无有效分集时不创建隐式数据，也不允许生成。

### 分镜槽位轨道

顶部使用横向可滚动轨道展示当前集全部镜头。每个槽位包含：

- 镜头序号。
- 最终分镜图缩略图；没有最终图时显示轻量占位。
- 镜头标题。
- 已选、生成中、失败等简洁状态。

点击切换当前镜头。槽位支持拖拽排序，并提供新增 1 个和批量新增 5 个空槽位。删除需要确认；删除槽位时同时删除它的未转正候选记录和相关本地图片，正式资产不删除。

### 当前镜头配置区

左侧配置区只编辑当前镜头，包含：

- 镜头标题、场次、景别、机位运动等基础分镜字段的紧凑摘要或编辑入口。
- 分镜画面提示词。
- 参考图轨道及素材库、剪切板、本地上传入口。
- 模型与图片参数。
- “复用上一镜配置”和“从其他镜头复用”动作。
- “为当前镜头生成”主按钮。

首次打开镜头时，如果尚无独立生图提示词，则从 `visualDescription`、`action`、`emotion`、`shotSize`、`cameraMovement` 等现有分镜字段组合出可编辑初稿。之后保存用户编辑值，不再反复覆盖。

复用配置复制提示词、参考图引用和图片参数，但不复制候选结果、最终选择、镜头标题或分镜结构字段。

### 当前镜头候选区

右侧仅显示当前镜头的候选图片。新结果追加，不覆盖历史候选。每张候选卡常驻显示尺寸和生成耗时，动作包括：

- 选为最终分镜 / 取消选取。
- 下载。
- 加入当前镜头参考图。
- 保存为正式资产。
- 删除候选。

每个镜头最多有一个选中候选。选取新候选时直接替换旧选择，但旧候选仍保留。取消选取只清除最终选择，不删除候选或已保存的正式资产。

## 数据设计

### 复用正式分镜表

`useStoryboardStore.tableShots` 仍是槽位结构和顺序的唯一数据源。`StoryboardTableShot` 增加首版所需的可选字段：

- `imagePrompt`：逐镜生图提示词。
- `imageConfig`：逐镜模型、尺寸、质量和数量快照。
- `referenceImageIds`：逐镜参考图 ID 顺序；引用标签按该顺序稳定生成。
- `selectedCandidateId`：当前最终分镜候选 ID。

新增、删除、排序和基础镜头编辑直接调用同一个 storyboard store，不创建独立分镜副本。

### 工作台图片

在 storyboard store 中增加按镜头归属的工作台图片集合。参考图和候选图使用同一种记录，通过 `role: "reference" | "candidate"` 区分，记录：

- `id`、`projectId`、`canvasId`、`episodeId`、`shotId`。
- `dataUrl` 与可选 `storageKey`。
- `width`、`height`、`bytes`、`mimeType`、`durationMs`。
- 生成时的 `prompt`、`model`、`size`、`quality` 和参考图数量。
- `role` 和可选 `sourceAssetId`；素材库引用保存来源资产 ID，本地上传和剪切板没有来源资产。
- 候选图可选 `savedAssetId`，用于防止同一候选重复保存正式资产。
- `createdAt`。

图片正文继续通过现有图片存储与 `localforage` 持久化，不把 base64 大字段写入普通 localStorage。hydrate 时通过 `resolveImageUrl` 恢复可显示 URL。

删除参考图、候选图或镜头时，只有在没有其他资产或工作台图片引用相同 `storageKey` 时才清理本地图片。正式资产由资产库管理，工作台不得连带删除。

### 工作台上下文

项目来自 `useCreativeProjectStore`，集数来自 `useScriptStore`，分集主画布来自 `useCanvasStore`。分镜表以 `canvasId + episodeId` 过滤。

如果集数存在但尚无分集主画布，工作台通过项目现有的 `ensureEpisodeMainCanvas` 创建该集主画布，再新增分镜槽位。创建动作不触发模型调用。

上次选择的项目和集数属于小型界面偏好，可使用 user-scoped localforage 保存；分镜业务数据不得放入 localStorage。

## 生成与选取数据流

1. 用户选择项目、集数和镜头。
2. 工作台读取当前镜头持久化的提示词、参考图和图片参数。
3. 用户点击生成后，先冻结本次请求快照。
4. 无参考图时调用现有 `requestGeneration`；有参考图时调用现有 `requestEdit`。
5. 每个生成槽位单独请求并单独落盘，成功结果追加到当前镜头候选集合。
6. 部分失败不回滚成功结果；失败槽位保留错误和重试动作。
7. 用户选取候选时，仅更新当前镜头的 `selectedCandidateId`。
8. 用户保存资产时复用现有 `addAssetOnce`，写入项目、集数、镜头、提示词和生成参数追踪信息，并回写候选的 `savedAssetId`。

生成始终是用户主动操作，不能因为切换镜头、复用配置或加载页面而自动触发付费请求。

## 资产模式兼容边界

现有资产生图页的以下行为必须保持：

- URL 提示词和来源上下文预填。
- `libraryAssetId` 对视频工作流资产卡的原位版本回写。
- `briefId` 对 Brief 结果的回写。
- Production Bible 绑定。
- Skill 能力抽屉、提示词库、参考图、参数、生成记录和结果保存。
- `returnTo` / `returnLabel` 返回链路。

分镜模式不得复用资产模式的全局生成记录作为候选归属依据；候选必须明确绑定 `shotId`。

## 组件与文件边界

`web/src/app/(user)/image/page.tsx` 只负责解析上下文并选择模式：

- `AssetImageWorkbench`：承接现有页面逻辑，行为保持不变。
- `StoryboardImageWorkbench`：装配项目/集数选择、槽位轨道、当前镜头配置与候选区。

分镜模式按以下边界拆分：

- `storyboard-workbench.ts`：纯数据筛选、默认提示词、配置复用和路由判定。
- `use-storyboard-workbench.ts`：项目、集数、画布、镜头选择与持久化协作。
- `use-storyboard-generation.ts`：请求快照、并发生成、重试和候选归档。
- `components/storyboard-shot-rail.tsx`：槽位展示、选择、拖拽、新增与删除。
- `components/storyboard-shot-editor.tsx`：提示词、参考图和参数编辑。
- `components/storyboard-candidate-grid.tsx`：候选、选取、下载、保存与删除。

组件直接读取对应 store 或页面 hook，不层层透传全局状态。主题继续使用 `studio-*` token、Ant Design 和现有画布主题，不硬编码独立黑白主题。

## 空状态与错误处理

- 没有项目：提示先创建项目，提供“前往项目中心”。
- 项目没有集数：提示先添加剧本集数，不创建虚假集数。
- 集数没有分镜：显示空槽位轨道和“新增镜头”，不自动生成分镜内容。
- 提示词为空：禁用生成并说明原因。
- 模型未配置：复用现有配置弹窗。
- 参考图读取失败：保留其他参考图，指出失败项。
- 部分生成失败：成功候选正常保存，失败槽位可单独重试。
- 切换镜头时仍在生成：请求继续归档到发起时冻结的 `shotId`，不得写入当前新镜头。
- 候选源图丢失：卡片显示“图片已不可用”，允许删除记录，不阻塞其他镜头。
- 删除当前镜头：自动选择相邻镜头；没有相邻镜头则进入空状态。

## 验收标准

1. 顶部导航显示“分镜”，普通 `/image` 首屏要求先选项目和集数，并展示该集现有分镜槽位。
2. 切换项目或集数时，只显示对应分镜，不串数据。
3. 新增、删除和排序槽位后，画布及其他读取分镜表的页面看到相同顺序与内容。
4. 每个镜头独立保存提示词、参考图、参数、候选池和最终选择；刷新后仍可恢复。
5. 复用配置不复制候选或最终选择。
6. 有无参考图分别走现有 edit / generation 请求路径。
7. 并发生成时切换镜头，结果仍归档到原镜头。
8. 同一镜头只能有一个最终候选，支持取消和改选。
9. 候选可下载，并可保存一次为正式资产；重复保存不会重复建资产。
10. 从视频工作流资产卡进入 `/image?...` 后仍显示原资产生图界面，提示词预填、生成、保存、回写和返回路径不变。
11. `/assets/[subjectId]` 的内嵌资产候选生成完全不受影响。
12. 桌面端无面板重叠；390px 宽度无页面级横向滚动，槽位轨道可横向滚动。
13. 浅色和深色主题都使用项目现有 token，状态文字与按钮对比度清楚。
14. 不因加载、切换或复用动作触发真实付费生成。
