# 缓存选择下载与视频提示词查阅设计

## 目标

缓存管理页允许用户先选择当前项目中的缓存文件，再下载所选内容；视频缓存能够查阅生成该视频时保存的提示词。功能不得改变缓存清理、媒体生成或完整项目包逻辑。

## 交互设计

- 每张状态为 `ready` 的缓存卡片左上角显示复选框，缺失文件不可选择。
- 筛选区下方增加轻量选择工具条，展示已选数量，并提供“全选当前结果”“清空”和“下载所选”。
- “全选当前结果”只影响当前筛选结果，不隐式选择被筛选隐藏的文件；已选的其他可用文件继续保留，用户可通过“清空”一次取消。
- 切换项目时清空选择，避免跨项目误下载；文件删除后同时从选择中移除。
- 选择一个文件时直接下载原文件；选择多个文件时下载只包含所选文件的 ZIP。
- 视频预览弹窗在播放器下方展示当次缓存记录的提示词，并附模型、服务商信息和复制按钮。旧缓存或上传视频没有提示词时，显示明确的未记录提示，不推断或补写。

## 数据与接口

现有 `ProjectCacheContext` 已包含 `prompt`、`model` 和 `provider`，不新增字段或迁移。前端直接读取视频文件的 `context` 展示生成信息。

新增项目作用域接口：

`POST /api/v1/project-cache/projects/:id/package/selection`

请求体仅包含 `fileIds`。服务端必须验证：

- 用户已登录；
- 项目缓存属于当前用户；
- 文件 ID 非空、无重复且全部属于该项目；
- 所选文件均存在且状态可用。

接口返回 ZIP，保留文件在项目缓存中的相对目录，并写入 `selection-manifest.json`，记录导出时间、项目 ID 和所选文件元数据。单文件下载继续使用现有文件接口，不经过 ZIP。

## 组件边界

- `cache-view-model.ts` 负责选择集合的纯计算，便于测试筛选结果全选、取消和删除同步。
- `CacheFileGrid` 与缓存卡片只负责展示选择状态并回调，不负责下载。
- 缓存页面负责项目级选择状态以及单文件/多文件下载编排。
- `CacheFilePreviewModal` 负责视频生成上下文展示，不修改缓存内容。
- Go service 负责严格解析所选文件并写 ZIP；handler 只校验请求、调用 service 并返回下载响应。

## 错误处理

- 未选择文件时下载按钮禁用。
- 选择中含缺失或不属于当前项目的文件时，服务端拒绝整个请求，不返回部分 ZIP。
- 下载失败保留当前选择，便于重试。
- 视频没有提示词时仍可正常预览和下载，只显示未记录状态。

## 测试

- 前端纯函数测试：全选当前筛选结果、保留其他已选项、取消当前结果、移除失效选择。
- 前端接线测试：卡片复选框、下载所选按钮和视频提示词区存在。
- Service 测试：多选 ZIP 只包含指定媒体及选择清单；拒绝跨项目、未知和缺失文件。
- Handler 测试：选中文件包返回 ZIP 下载头；未登录或无效请求返回统一错误结构。
