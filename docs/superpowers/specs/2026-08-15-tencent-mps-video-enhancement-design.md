# 腾讯 MPS 视频增强接入设计

## 目标

在画布现有“视频超分”入口中增加腾讯云 MPS 音视频增强渠道。用户每次提交任务时可选择“火山 LAS”或“腾讯 MPS”；原视频保持不变，成功结果继续作为右侧单一派生节点加入画布并归档到资产。

本次只增加供应商选择和腾讯增强链路，不改变现有火山超分、智能插帧、费用快照、任务恢复和结果归档行为。

## 方案选择

采用“同一入口、逐任务选择渠道”：

- 不使用后台全局二选一，避免切换供应商必须反复修改全局配置。
- 不新增第二个“腾讯增强”节点按钮，避免重复入口和概念分裂。
- 后台分别保存火山与腾讯配置；能力接口只公开已可用渠道及非敏感能力。
- 任务创建时冻结渠道、腾讯模板 ID、场景和存储位置，管理员后续修改默认配置不影响已创建任务。

## 产品范围

腾讯渠道支持当前画布已有的两个输出目标：

| 场景 | 1080p 模板 | 2K 模板 | 说明 |
| --- | ---: | ---: | --- |
| 漫剧增强 | 327004 | 327006 | 默认，适合 AI 动画、漫剧和非真人素材 |
| 真人增强 | 327003 | 327005 | 适合真人拍摄内容 |
| 老片修复 | 327022 | 327023 | 适合损失严重的低清旧片 |

暂不开放 720p、4K、小脸优化模板和自定义模板 ID，避免扩大现有目标边界及错误配置。腾讯模板决定编码和增强参数，因此腾讯渠道不显示火山的“兼容 / 均衡 / 母版”质量选项。腾讯渠道保留源音频，不提供关闭音频选项。

火山智能插帧只属于 LAS 流程。选择腾讯 MPS 时帧率保持随源，不显示插帧设置，也不串联火山插帧。

## 后台配置

“后台设置 → 私有设置 → 视频处理”保留现有 LAS 配置，并增加“腾讯 MPS 视频增强”配置区：

- 启用开关；
- SecretId、SecretKey，保存后仅回显已配置状态；
- COS Bucket，例如 `media-1300000000`；
- COS 地域，默认 `ap-beijing`；
- 输入前缀，默认 `video-upscale/input/`；
- 输出前缀，默认 `video-upscale/output/`；
- 默认场景，默认“漫剧增强”；
- “测试连接”只执行只读身份与存储检查，不调用 `ProcessMedia`，不创建计费任务。

腾讯配置与火山 LAS API Key、火山 TOS AK/SK 完全隔离。SecretId、SecretKey 不进入能力接口、任务响应、日志或前端持久化数据。

## 前端交互

视频节点仍只有一个“视频超分”动作。弹窗在目标清晰度之前增加渠道选择：

- 只有一个渠道可用时直接选中，不增加无意义步骤；
- 两个渠道都可用时显示“火山 LAS / 腾讯 MPS”分段按钮；
- 选择腾讯后显示“漫剧增强 / 真人增强 / 老片修复”；
- 源规格、目标规格、时长、云端付费提示和提交确认继续保留；
- 腾讯未配置时不作为可选项，并给管理员入口提示；
- 提交按钮明确显示供应商，例如“开始腾讯 MPS 增强”。

腾讯文档没有在本次材料中给出可直接计算的完整单价，且增强会同时产生“增强 + 转码”两笔费用。因此腾讯渠道不沿用火山公式生成虚假金额，费用区显示“腾讯 MPS 将按增强与转码分别计费，实际费用以腾讯云账单为准”。获得稳定的模板计价数据后，再独立增加腾讯费用估算规则。

## API 与数据模型

复用现有接口：

- `GET /api/v1/video-upscale/capabilities`
- `POST /api/v1/video-upscale/jobs`
- `GET /api/v1/video-upscale/jobs/:id`
- `POST /api/v1/video-upscale/jobs/:id/retry`

能力响应由单一 `provider` 改为 `providers` 列表，每项声明供应商 ID、名称、可用状态、目标、场景、计费提示及插帧能力。保留现有顶层火山能力字段到本次前端切换完成后再评估清理，避免一次改动无关消费者。

创建任务增加：

- `provider`: `volcengine-las` 或 `tencent-mps`；
- `enhancementScene`: 腾讯渠道接受 `comic`、`live`、`restore`，火山渠道忽略。

`video_upscale_jobs` 增加并冻结：

- 腾讯场景与模板 ID；
- COS 输入对象、输出 Bucket、地域和前缀；
- 腾讯请求 ID；
- 任务供应商继续使用已有 `provider` 字段。

不把 SecretId 或 SecretKey写入任务表。数据库结构变更同步更新 `docs/backend-database.md`。

## 腾讯云数据流

1. 服务端先把上传视频私有保存并用 `ffprobe` 校验规格，所有付费调用前完成格式、目标与场景校验。
2. 使用腾讯 COS 官方 SDK把输入上传到配置 Bucket 的 `video-upscale/input/` 前缀。
3. 使用腾讯云 Go SDK 调用 MPS `ProcessMedia`，输入与输出均指向同一账号配置的 COS，`Definition` 使用冻结的预设模板 ID。
4. 保存返回的 Task ID 与 Request ID 后进入轮询；已有 Task ID 时只调用 `DescribeTaskDetail`，不得重复提交。
5. 成功后从 `TranscodeTaskSet` 中定位对应模板的输出对象，生成短期签名下载地址。
6. 立即下载结果到现有本地公开结果目录，复用画布派生节点、缓存和资产归档逻辑。

Provider 层负责各云厂商的上传、提交、查询和结果地址解析；公共任务状态机只处理上传、提交、查询、下载和持久化，不出现火山或腾讯专属文案。腾讯不实现插帧接口，公共状态机根据任务冻结的供应商能力跳过插帧阶段。

## 幂等、恢复与错误处理

- 提交前保存 `upscale_submitting`；提交成功立即保存 Task ID。
- 在 Submit 请求过程中中断且没有 Task ID 时标记 `submission_uncertain`，禁止自动重提，避免重复计费。
- 已有 Task ID 的处理中任务在服务重启后只恢复 `DescribeTaskDetail` 轮询。
- 腾讯任务成功但结果下载或本地保存失败时，只重新解析、签名和下载原任务结果，不重新调用 `ProcessMedia`。
- 权限、COS 地域、Bucket、模板未授权、输入不存在和腾讯任务失败映射为安全中文错误；日志保留 Request ID，不输出密钥和签名 URL。
- 重试必须按任务原供应商恢复，不能因后台默认渠道变化而切换供应商。

## 测试与验收

所有自动测试使用假 Provider、假 HTTP/SDK 客户端和本地测试视频，不调用真实腾讯云付费接口。

- Go 单元测试覆盖模板映射、输入校验、腾讯配置脱敏与保留、COS 路径、ProcessMedia 参数、DescribeTaskDetail 状态和结果解析。
- 状态机测试覆盖腾讯提交、轮询、下载、重启恢复、`submission_uncertain` 与重试不重复计费。
- Handler 测试覆盖 `provider`、`enhancementScene` 入参与错误响应。
- 前端测试覆盖单/双渠道展示、腾讯场景选择、火山专属选项隐藏、腾讯计费提示与提交参数。
- 针对性验收执行 Go 相关包测试、前端相关测试和 TypeScript 检查；不做真实增强任务。

## 非目标

- 腾讯 720p、4K、小脸优化和自定义模板；
- 腾讯音频增强、SDR2HDR、单独降噪或色彩增强入口；
- 自动在火山失败后切换腾讯，避免产生第二笔费用；
- 腾讯回调服务与公网回调地址；首版使用现有轮询机制；
- 未获得完整官方计价规则前的腾讯费用金额估算；
- 真实付费样片测试，除非用户后续单独明确授权。
