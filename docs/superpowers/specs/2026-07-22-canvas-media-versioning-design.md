# 画布媒体节点内版本设计

## 目标

已生成成功的图片或视频节点再次修改提示词并生成时，不再向画布增加结果节点，而是在原节点内追加一个版本。每个版本同时保存媒体、提示词、生成参数和参考素材快照，用户切换版本时可以核对当次生成结果与提示词差异。

首版只覆盖图片和视频结果节点。空节点、配置节点和文本节点保持现有生成行为。

## 核心规则

1. 已有内容的图片或视频节点再次生成时，固定生成一个新版本；图片全局多图数量不参与节点内版本生成。
2. 节点 ID、位置、尺寸关系和连线不变，生成成功后只更新节点当前展示版本。
3. 老节点第一次生成新版本时，将当前媒体、原提示词和生成参数整理为 `v1`，新结果成为 `v2`。
4. 从任意历史版本发起生成时，新结果都追加到版本列表末尾，不覆盖或插入历史版本。
5. 生成失败不新增版本、不替换当前媒体，编辑草稿继续保留。
6. 所有版本保留；首版不提供版本删除、重命名、分支或两版并排差异功能。

## 提示词状态

版本提示词和编辑草稿必须分开保存：

- `prompt` / `promptDocument` 表示当前选中版本实际生成时使用的提示词，只随版本切换变化。
- `promptDraft` / `promptDraftDocument` 表示用户尚未生成的编辑内容。
- 打开节点面板时，输入框显示草稿；没有草稿时以当前版本提示词作为初始内容。
- 用户输入只更新草稿，不直接修改当前版本快照。
- 点击“生成新版本”时以草稿作为新版本提示词；成功后新版本成为当前版本并清空草稿。
- 切换版本时如果草稿与当前版本提示词不同，弹出“提示词修改尚未生成，是否放弃”；确认后丢弃草稿并切换，取消则留在当前版本。

该规则保证用户以当前提示词为基础修改时，旧版本的提示词始终完整保留；新版本完成后再切回旧版本，输入框会重新回填旧版本当时使用的提示词。

## 版本数据结构

在 `CanvasNodeMetadata` 中增加：

- `mediaVersions?: CanvasMediaVersion[]`
- `currentMediaVersionId?: string`
- `promptDraft?: string`
- `promptDraftDocument?: CanvasPromptDocument`

`CanvasMediaVersion` 至少包含：

- 标识：`id`、`versionNumber`、`kind`、`createdAt`。
- 媒体：`content`、`storageKey`、宽高、字节数、MIME、视频缓存和尾帧字段。
- 提示词：`prompt`、可选的结构化 `promptDocument`。
- 生成参数：模型、图片质量、画幅、分辨率、时长、音频、水印、种子、任务模式等当次有效值。
- 参考快照：图片、视频、音频引用，引用顺序和角色。
- 任务与归档：任务 ID、账本字段、完成时间、`sourceAssetId` 和火山素材状态。

版本工具函数维护一份明确的“版本拥有字段”清单。切换版本只替换这些字段，保留节点的生产包绑定、分镜绑定、批次关系、画布来源和其他结构字段，避免版本切换破坏工作流关系。

## 生成数据流

### 图片节点

1. 识别来源为已有内容的图片节点，进入 `in-place version` 模式。
2. 在内存中构造当前版本快照；节点没有版本记录时，该快照作为 `v1`。
3. 保持当前图片可见，节点叠加生成中状态。
4. 图片生成成功并完成本地持久化后，构造下一版本并追加到原节点。
5. 将新版本字段投影到节点当前 metadata，清空草稿并保持原节点选中。
6. 继续按现有流程归档“我的素材”，把返回的素材 ID 写入新版本和当前节点。

### 视频节点

流程与图片一致，但沿用当前视频提示词审核、参考素材解析、任务轮询、本地缓存、分镜状态和素材归档。已有内容的视频节点不再调用创建变体节点的布局逻辑；新任务状态附着到原节点，完成后追加版本。

可恢复的视频任务在原节点上继续轮询。恢复成功后才追加版本；明确失败时保留旧版本和草稿。

### 首次生成

- 空图片或空视频节点继续原地填充第一个结果。
- 配置节点、文本节点或连接菜单发起生成时继续创建结果节点。
- 第一个成功结果暂不强制立即写入版本数组；在首次再次生成或打开版本控件时可规范化为 `v1`，避免对所有旧数据做迁移。

## 版本切换界面

当节点拥有两个及以上版本时：

- 媒体节点顶部中间显示轻量控件：`‹  v2 / 5  ›`。
- 左右按钮切换相邻版本；点击版本编号展开版本列表。
- 列表项显示缩略图、`vN`、生成时间、模型/尺寸摘要和提示词首行。
- 当前版本使用画布主题强调色标记，不增加厚重工具栏。
- 节点提示词面板编辑器上方同步显示版本编号和生成时间。
- 切换版本后，媒体、提示词、参数面板和任务详情一起更新。
- 已有内容节点的提交按钮文案改为“生成新版本”；首次生成仍显示“生成”。

首版通过逐版切换核对提示词，不新增文本差异算法或双栏比较器。

## 状态与失败处理

- 生成过程中禁止重复提交和版本切换，当前媒体保持可见。
- 请求被用户取消或提示词审核未通过，不新增版本。
- 生成成功但素材归档失败时，节点版本仍保存成功，并提示素材同步失败。
- 当前版本对应的本地文件缺失时显示明确错误，不静默切换到其他版本。
- 节点删除时，现有递归存储键收集逻辑会识别版本数组中的 `storageKey`；节点仍存在时历史版本文件不会被清理。
- 复制节点时复制整个版本历史；复制后的节点拥有独立节点 ID，但版本媒体仍引用同一份只读本地文件。

## 组件与代码边界

- `utils/canvas-media-versions.ts`：版本创建、规范化、追加、切换、当前版本解析和版本字段投影，保持纯函数。
- `components/canvas-media-version-control.tsx`：节点内版本控件和列表。
- 图片、视频生成 hooks：只负责在成功时调用版本工具函数，不承担版本展示逻辑。
- 节点提示词面板：负责草稿和当前版本提示词的编辑语义；切换确认由画布 UI hook 统一处理。
- `canvas-client-page.tsx` 继续作为装配层，不直接堆版本业务逻辑。

## 测试与验收

自动测试覆盖：

1. 老节点首次再次生成形成 `v1 + v2`，原节点 ID 和连线不变。
2. 从历史版本生成时追加最大版本号后的新版本。
3. 版本切换同步媒体、提示词、参数、参考和任务字段，同时保留结构字段。
4. 修改草稿不改变历史版本提示词；成功生成清空草稿，失败保留草稿。
5. 图片结果节点再次生成固定一个版本，不创建批次子节点。
6. 视频可恢复任务完成后追加版本，失败时旧版本仍为当前版本。
7. 版本数组内的图片和视频存储键可被清理扫描器识别。

页面验收路径：

1. 对已生成图片修改提示词并生成，画布节点数量与连线数量不变，版本变为 `v2 / 2`。
2. 在 `v1` 与 `v2` 间切换，图片和输入框提示词分别恢复为当次内容。
3. 修改提示词但不生成，切换版本时出现放弃确认；取消后草稿仍在。
4. 对视频节点重复上述流程，确认视频、模型、画幅、时长、参考素材和任务详情随版本切换。
5. 制造一次生成失败，确认旧媒体仍可播放/查看，版本数量不变，修改后的提示词仍保留。

## 不做事项

- 不改变首次生成和配置节点的多结果布局。
- 不给文本节点增加版本历史。
- 不提供历史版本删除、重命名、分支、合并或双栏 diff。
- 不修改后端生成接口，也不新增云端版本表。
- 不把素材库作为画布版本切换的运行时依赖。
