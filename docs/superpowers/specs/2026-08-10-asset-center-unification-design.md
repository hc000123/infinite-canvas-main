# 资产中心统一体验设计

## 背景

当前资产页面同时展示或处理普通媒体文件、资产主体、形态、候选图、正式版本、设定库条目、项目库状态、分集绑定和工作流结果。各对象本身已有数据结构，但用户需要先理解多套概念和入口，才能完成“找到一个角色并在画布里使用其当前主图”这一基础任务。

本次采用渐进式统一方案：保留现有资产数据和 Zustand store，通过统一的信息架构、派生查询和动作入口，把日常心智模型收口为：

```text
资产主体（角色 / 场景 / 道具）
  └── 形态（默认只有基础形态，需要时再新增）
       ├── 当前版本
       ├── 待选结果
       ├── 历史版本
       └── 参考资料
```

未绑定资产主体、但已经显式保存到本地资产库的文件统一进入“待整理”，不作为正式资产主体展示。普通画布生成结果继续只进入项目缓存，不因本次改造自动创建本地资产。

## 目标

- 资产首页默认展示资产主体，不混排主体、版本、候选图和设定库条目。
- 用户不需要理解底层 store，即可从主体进入形态、当前版本、待选结果和历史版本。
- 简单资产默认只有“基础形态”，不要求用户先理解或创建形态。
- 画布按资产主体选择内容，默认一步插入基础形态的当前版本。
- 零散文件有明确的“待整理”去向，可归入已有主体或据此创建主体。
- 复用现有本地数据、素材版本锁定、项目/分集绑定和生成归档能力。

## 非目标

- 本轮不建设云端共享资产库、不改变本地优先的保存方式。
- 不重写画布、分镜、Workflow 和项目缓存的数据协议。
- 不让普通画布生成结果自动成为正式资产。
- 不自动替用户选择待选结果或覆盖当前版本。
- 不把视频、音频和文本混入图片版本历史；它们作为主体关联素材展示。

## 统一术语

| 术语 | 含义 | 当前数据来源 |
| --- | --- | --- |
| 资产主体 | 一个角色、场景、道具或站位对象 | `AssetSubject` |
| 形态 | 主体在特定造型、时间、状态下的一套视觉定义 | `AssetVariant` |
| 基础形态 | 创建主体时自动建立的默认形态 | 默认 `AssetVariant` |
| 待选结果 | 尚未确认为正式版本的生成或上传图片 | `AssetWorkbenchImage(role=candidate)` |
| 当前版本 | 某个形态默认用于画布、分镜和生成参考的正式图片 | `AssetVariant.currentAssetId` |
| 历史版本 | 已转正且绑定同一主体和形态的其他图片资产 | `Asset` + `assetBinding` |
| 参考资料 | 辅助生成但不是正式版本的图片或关联媒体 | `AssetWorkbenchImage(role=reference)` 及关联素材 |
| 待整理 | 尚未绑定 `subjectId` 的本地资产 | 未绑定主体的 `Asset` |

用户界面不再使用“候选资产”“设定库资产”“普通素材资产”等并列名称。Workflow 的设定库数据继续作为上游生产数据存在，但在资产中心只表现为主体描述、形态提示词或来源记录。

## 信息架构

### 资产中心 `/assets`

资产中心按项目查看，主导航只有：

- 全部资产主体
- 角色
- 场景
- 道具
- 站位/其他
- 待整理

主体页只展示主体卡片。卡片包含基础形态主图、类别、编号、名称、形态数、待选结果数和就绪状态。基础形态按主体下创建时间最早的形态确定；其他形态由用户进入主体后选择。文件类型、生成来源、模型、引用过期等高级筛选不占据默认首屏，移动到“更多筛选”或主体工作台内。

“待整理”展示未绑定主体的图片、视频、音频和文本，并提供：

- 归入已有主体
- 新建主体并归入
- 保持待整理
- 删除或批量整理

图片归入主体时需要选择形态，默认选择基础形态；默认成为正式版本并设为当前版本，但提交前明确展示这一结果。视频、音频和文本归入主体后进入关联素材，不成为图片版本。

### 资产主体工作台 `/assets/[subjectId]`

主体工作台继续复用现有路由，页面顺序调整为：

1. 主体标题、分类、编号和描述。
2. 形态导航；只有基础形态时弱化形态层级。
3. 当前版本大图和核心动作。
4. 待选结果。
5. 历史版本。
6. 参考资料和关联素材。
7. 可折叠的生成配置。

生成结果只进入待选结果。用户点击“设为当前版本”后，系统创建或复用正式图片资产、绑定当前主体和形态，并更新 `currentAssetId`。未选结果继续保留，不参与画布默认选择。

### 画布资产选择器

画布选择器调整为：

- 本集资产：当前项目和分集适用的资产主体。
- 全部资产：当前项目的所有资产主体。
- 外部素材库：服务端或外部媒体库，仍按文件选择。

资产主体卡片点击后默认插入基础形态的当前版本。卡片提供二级入口切换其他形态或选择锁定的历史版本。基础形态没有当前版本时，主体不可直接一键插入，入口改为“去完善资产”，打开对应主体工作台。

待整理内容不出现在正式资产选择列表中，避免临时文件被误当成角色或场景主参考。

## 技术设计

### 保留的数据结构

继续使用 `useAssetStore` 中的：

- `subjects: AssetSubject[]`
- `variants: AssetVariant[]`
- `workbenchImages: AssetWorkbenchImage[]`
- `assets: Asset[]`

不新增第二套持久化资产中心 store，不复制主体、形态或版本状态。现有 localForage key 保持不变。

### 新增派生模型

在资产页面目录增加纯函数，构建以下只读视图：

```ts
type AssetSubjectSummary = {
  subject: AssetSubject;
  variants: AssetVariant[];
  primaryVariant: AssetVariant;
  currentAsset?: ImageAsset;
  pendingCount: number;
  versionCount: number;
  relatedMediaCount: number;
  readiness: "empty" | "pending" | "ready";
};

type UnorganizedAsset = {
  asset: Asset;
  suggestedCategory?: AssetCategory;
  projectId?: string;
};
```

所有计数、封面、当前版本和待整理判断都从现有数据派生，避免多份状态失去同步。

### 统一写入动作

在 `useAssetStore` 增加最少量的领域动作，使一次整理操作在单次 `set` 中完成：

- `organizeAsset`：把已有资产绑定到主体/形态；图片可设为当前版本。
- `createSubjectFromAsset`：创建主体、基础形态并绑定已有资产。
- `promoteWorkbenchImage`：把待选结果转为正式版本并更新当前版本。

页面 hooks 只负责表单、确认框、提示和异步文件准备，不直接拼装多次 store 更新。涉及素材上传时，先完成文件保存，再执行 store 动作；store 动作失败时保留原待整理文件或待选结果。

### 上游数据边界

- 资产拆解、Brief 和 Workflow 仍可以产出主体建议或视觉设定。
- 只有用户确认“建立资产主体”或“写入资产”后，才写入 `AssetSubject`、`AssetVariant` 或正式 `Asset`。
- Production Bible 作为上游结构化设定保留，但资产中心不再把它展示成另一种可与主体并列选择的资产。
- 所有来源追溯继续保存在现有 metadata 中。

## 组件边界

资产首页保留 `page.tsx` 作为装配层，主要新增或调整：

- `asset-center-sidebar.tsx`：主体分类和待整理导航。
- `asset-subject-grid.tsx`：主体列表与空状态。
- `asset-subject-card.tsx`：主体摘要卡片，不承载查询逻辑。
- `asset-inbox-section.tsx`：待整理列表和批量选择。
- `asset-organize-modal.tsx`：归入已有主体或新建主体。
- `asset-center-model.ts`：主体摘要、待整理和筛选纯函数。
- `use-asset-organize-actions.ts`：确认、错误提示和 store 动作接线。

现有 `AssetCard`、版本面板、候选面板、参考资料面板和媒体预览继续复用；不为了改名复制组件。

## 数据流

### 上传或普通生成

```text
上传 / 从项目缓存显式保存到资产
  → 保存为本地 Asset
  → 无明确业务来源时不创建正式主体绑定
  → 显示在“待整理”
  → 用户归入主体
  → 图片成为正式版本；其他媒体成为关联素材
```

### 主体生图

```text
主体 + 当前形态 + Prompt + 参考资料
  → 图片生成
  → AssetWorkbenchImage(candidate)
  → 用户选择“设为当前版本”
  → 正式 ImageAsset + AssetBinding
  → 更新 AssetVariant.currentAssetId
```

### 画布插入

```text
选择资产主体
  → 解析指定形态，默认基础形态
  → 解析 currentAssetId
  → 创建锁定版本的画布节点
  → 保留 subjectId / variantId / assetId / version 引用
```

## 错误处理

- 主体无当前版本：禁止直接插入，提供“去完善资产”。
- 当前版本文件丢失：展示缺失状态，不自动回退到其他历史版本。
- 待选结果转正失败：保留待选结果和生成信息，提供重试。
- 整理已有文件失败：保持在待整理，避免出现一半绑定、一半未绑定。
- 删除形态或主体继续使用现有引用检查和确认逻辑，不静默清理画布引用。
- 外部素材解析失败：记录单项失败，其他批量项可以继续完成。

## 分阶段实施

### 第一阶段：资产中心收口

- 增加派生模型和测试。
- 资产首页改为主体优先，并增加待整理入口。
- 收口默认筛选，保留高级筛选能力。
- 统一术语和空状态文案。

### 第二阶段：主体工作台收口

- 弱化单一基础形态的层级感。
- 调整当前版本、待选结果、历史版本和参考资料的页面顺序。
- 把生成设置改为次级、可折叠区域。
- 统一待选结果转正动作。

### 第三阶段：画布选择器收口

- 改为主体卡片优先。
- 默认插入当前版本。
- 增加形态和历史版本二级选择。
- 未就绪主体跳转工作台。

### 第四阶段：上游入口清理

- 资产拆解、Brief、Workflow 的正式写入统一经过资产主体动作。
- 删除资产中心中设定库条目与正式主体并列展示的旧入口。
- 清理不再使用的旧筛选、文案和简单转发组件。

## 验证

自动测试重点：

- 主体摘要的当前版本、形态数、待选数和就绪状态。
- 未绑定资产进入待整理，已绑定资产不进入待整理。
- 图片整理后正确绑定主体/形态并更新当前版本。
- 视频、音频、文本整理后不进入图片版本历史。
- 待选结果转正的幂等性和失败保留。
- 画布选择器默认解析当前版本并保存锁定版本引用。
- 无当前版本和文件缺失状态。

页面验收重点：

- 用户进入资产页后能直接理解角色、场景、道具是正式资产。
- 简单主体不需要额外理解形态即可生成和使用。
- 从上传文件到归入主体不超过一次选择和一次确认。
- 从画布打开资产选择器到插入当前主图不超过两次点击。
- 候选、当前版本和历史版本在视觉和操作上没有歧义。
