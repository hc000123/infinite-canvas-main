# 资产主体工作台设计规格

## 目标

在保留现有普通素材、文件夹、项目、分集、收藏、版本和任务血缘能力的基础上，把“我的资产”升级为项目化图片资产生产系统。人设、场景、道具、站位以“主体”为长期生产对象，每个主体拥有独立工作台，可管理多个形态、参考资料、生成配置、候选图和正式版本；文本、视频、音频以及不需要主体化管理的图片继续作为“其他素材”存在。

本阶段仅覆盖图片生产资产，不包含角色音色、视频生成、三视图专用算法、云同步和团队协作。

## 核心原则

1. **主体与文件分离**：主体描述“谁/什么”，图片描述某次产出。一个主体可以有多个形态和多个正式图片版本。
2. **候选与正式资产分离**：上传或生成结果先进入候选池，只有用户点击“选为资产”后才创建正式 `Asset`。
3. **项目默认隔离**：创建主体必须选择项目；引用选择器默认只显示当前项目，用户主动切换“全部项目”后才能跨项目复用。
4. **配置跟随形态**：提示词、模型参数和参考资料属于形态，切换形态时整体切换，避免不同造型互相污染。
5. **沿用现有基础设施**：图片存储继续使用 IndexedDB/localforage 与现有 image storage；生成继续调用现有 image API、模型配置、任务记录和算力链路；正式资产继续使用现有版本、引用和过期检查能力。

## 信息架构

### 资产库首页 `/assets`

页面保留当前项目筛选、搜索、排序、导入、文件夹和其他素材管理，并将业务入口整理为五类：

- 人设
- 场景
- 道具
- 站位
- 其他素材

前四类展示主体卡片。卡片包含主体名称、项目、形态数量、当前主图、最近更新时间和“进入工作台”入口。没有主图时展示明确的待生产状态。创建前四类资产时，第一步只填写名称、所属项目和可选备注，保存后直接进入主体工作台。其他素材继续走现有编辑/导入流程。

首页不承担生成配置和候选挑选，避免再次把管理视图与生产视图混在一起。

### 主体工作台 `/assets/[subjectId]`

工作台采用稳定的三段式布局：

- 顶部：返回资产库、项目/分类面包屑、主体名称、保存状态和主体操作。
- 左侧生产栏：形态切换、提示词、参考资料、模型、画质、比例、张数和生成按钮。
- 右侧结果区：当前主图与正式版本、候选池、上传候选入口及候选操作。

桌面端左侧固定宽度、右侧自适应；窄屏改为纵向布局。视觉沿用现有 studio 主题变量与 Ant Design token，保持编辑工作台的低视觉重量，不引入另一套硬编码主题。

### 快速引用

工作台内“从资产引用”打开选择器：

- 默认作用域为当前项目。
- 可显式切换到“全部项目”。
- 支持按主体名称、形态名称和资产标题搜索。
- 选中的正式图片作为当前形态的参考资料，不复制正式资产。
- 跨项目引用在条目上显示来源项目，避免用户误以为图片属于当前项目。

## 数据模型

沿用 `AssetSubject` 和 `AssetBinding`，新增以下本地持久化实体：

```ts
type AssetCategory = "character" | "scene" | "prop" | "blocking" | "other";

type AssetVariant = {
  id: string;
  subjectId: string;
  name: string;
  prompt: string;
  referenceImageIds: string[];
  currentAssetId?: string;
  config?: {
    imageModel?: string;
    quality?: string;
    size?: string;
    count?: string;
  };
  createdAt: string;
  updatedAt: string;
};

type AssetWorkbenchImage = {
  id: string;
  subjectId: string;
  variantId: string;
  role: "reference" | "candidate";
  source: "upload" | "generated" | "asset" | "candidate";
  title: string;
  dataUrl: string;
  storageKey?: string;
  width: number;
  height: number;
  bytes: number;
  mimeType: string;
  sourceAssetId?: string;
  selectedAssetId?: string;
  generation?: {
    prompt: string;
    model: string;
    quality: string;
    size: string;
    createdAt: string;
  };
  createdAt: string;
};
```

`AssetBinding` 增加可选 `variantId`，同时保留 `variantName` 作为可读快照。形态重命名时同步更新该形态下正式资产的 `variantName`。这样主体、形态有稳定 ID，现有按形态名称展示的代码也可以继续工作。

`AssetVariant.currentAssetId` 指向当前主图。曾经被选为资产的图片仍保留为正式 `Asset`，因此现有资产版本与引用过期机制不被替换。候选的 `selectedAssetId` 用来标记它已进入正式资产，防止重复选择。

主体创建后自动创建一个默认形态：人设为“基础形象”，其他分类为“基础状态”。形态名称在同一主体内唯一。

## 关键流程

### 创建主体

1. 用户在资产库选择人设、场景、道具或站位。
2. 输入名称、项目和备注。
3. 创建 `AssetSubject` 与默认 `AssetVariant`。
4. 跳转 `/assets/[subjectId]`。

名称为空、项目不存在或同项目同分类重名时阻止创建，并给出中文提示。

### 上传参考资料

图片经现有 `uploadImage` 存入 IndexedDB，随后创建 `role=reference` 的 `AssetWorkbenchImage` 并加入当前形态 `referenceImageIds`。用户可以删除引用关系；只有确认不再被其他形态或正式资产使用时，图片清理流程才回收底层存储。

从资产库引用时创建轻量引用记录，保存 `sourceAssetId` 以及可恢复的图片快照。源资产之后变更时，工作台仍能显示当时选入的参考图，用户可主动重新选择新版本。

### 生成候选

1. 校验提示词和当前图片模型配置。
2. 从当前形态生成请求快照；生成过程中修改表单不会影响在途任务。
3. 有参考图时调用 `requestEdit`，无参考图时调用 `requestGeneration`。
4. 每张图独立执行并显示进行中、成功或失败状态；成功结果通过 `uploadImage` 持久化为候选。
5. 请求继续传递当前项目、主体和图片生成来源信息，沿用本地任务记录及服务端算力记账。
6. 批次部分失败时保留成功结果，并允许对失败槽位重试；全部失败时显示服务返回的错误。

页面刷新后，已经持久化的参考图、候选图、形态配置和正式版本全部恢复。在途网络请求不伪装成可恢复任务；刷新后用户可重新发起生成，原任务账目仍由现有任务系统记录。

### 选为资产

1. 用户在候选图上点击“选为资产”。
2. 创建正式 image `Asset`，写入项目、主体、分类、`variantId`、`variantName`、提示词、模型参数和生成来源。
3. 将候选 `selectedAssetId` 指向正式资产。
4. 将形态 `currentAssetId` 更新为该资产；之前主图自动进入历史版本，不删除。
5. 主体卡片与工作台当前主图立即更新。

已选候选再次操作时显示“已选为资产”，不重复创建。用户也可以从历史正式版本重新设为当前主图。

### 继续迭代与复制

- “作为参考图”把候选或正式版本加入当前形态参考资料。
- “复制到其他形态”复制图片快照和生成配置到目标形态候选池，不改变原资产归属。
- “新建形态”可选择空白创建或复制当前形态配置；复制配置时复制提示词、模型参数和参考资料引用，不复制当前主图。
- 删除形态前必须至少保留一个形态；删除时只移除该形态的工作台资料，已经创建的正式资产继续保留，但解除该形态的当前主图关系。

### 批量导入

现有批量导入继续负责普通素材。主体工作台增加“上传候选”，支持一次上传多张图片，全部进入当前形态候选池。批量建立多个主体不在本阶段范围，避免引入依赖文件名规则的隐式归类。

## 组件与代码边界

- `use-asset-store.ts`：主体、形态、工作台图片的状态与持久化动作；不包含页面交互。
- `asset-workbench.ts`：分组、校验、正式资产输入、参考图转换等纯函数。
- `use-asset-workbench-generation.ts`：生成批次、失败重试、图片持久化与任务上下文。
- `assets/[subjectId]/page.tsx`：装配 store、hook 和页面状态。
- `assets/[subjectId]/components/`：形态导航、生产表单、参考资料、候选池和版本区。
- 现有 `/image` 页面保持独立，不为本功能做大规模重构；两个工作台共同复用 `requestGeneration`、`requestEdit`、`ModelPicker`、`ImageSettingsPanel`、图片存储和模型配置。

页面私有状态留在页面目录，不新增全局 UI store。业务数据全部进入现有 localforage 持久化 store，不使用 localStorage。

## 错误与边界处理

- 主体不存在：展示空状态并提供返回资产库按钮。
- 项目已删除：主体仍可查看，但生成前要求重新绑定有效项目。
- 当前主图被删除：清空 `currentAssetId`，历史列表按剩余正式资产展示。
- 引用源资产被删除：使用工作台引用快照继续显示，并标记“来源已删除”。
- 图片持久化失败：不创建候选，显示失败原因。
- 生成部分失败：成功候选保留，失败卡展示原因与重试入口。
- 删除主体：确认后删除主体、形态与未转正的工作台图片；正式资产解除主体绑定但不删除。

## 测试与验收

### 纯函数与 store

- 创建主体自动产生正确默认形态。
- 同主体形态名称唯一，且至少保留一个形态。
- 形态重命名同步正式资产绑定快照。
- 候选只能转正一次，转正后成为当前主图。
- 切换当前主图不删除历史正式资产。
- 当前项目与全部项目引用作用域正确。
- 删除主体不会删除正式资产。
- 持久化重新载入后形态、参考图和候选图完整恢复。

### 页面验收

- 资产库可以创建四类主体并进入正确工作台。
- 工作台可新增、重命名、复制和删除形态。
- 可上传参考图、引用当前项目资产，并显式跨项目引用。
- 无参考图与多参考图生成均能得到候选，失败槽位可重试。
- 上传多张本地图片可直接成为候选。
- 候选可选为正式资产、设为参考、复制到其他形态。
- 当前主图、历史版本和主体卡封面同步更新。
- 浅色/深色主题、桌面和窄屏布局均保持可用。

## 实施范围

本次实现数据模型、资产库主体入口与卡片、独立主体工作台、形态管理、参考图、内嵌生成、候选挑选、当前主图、项目范围引用和批量上传候选。角色音色、三视图专用生成、视频资产工作台、批量创建主体、云同步、共享权限和团队协作明确不进入本次实现。
