# 后台 AI 使用与算力统计设计

## 目标

把分散的“AI 任务日志”和“算力点日志”收口为一个后台入口，并提供按北京时间自然周期统计的实际净消耗与用户占比。

本次范围包括：

- 后台侧边栏只保留一个“AI 使用”入口。
- 页面上方展示今日、本周、本月的实际净消耗。
- 选择任一周期后，展示该周期内每个用户的净消耗、任务数和占比。
- 页面下方通过“任务明细 / 算力流水”两个页签保留现有查询、详情、刷新、返还和管理员调整能力。

不新增数据表，不修改现有 AI 任务、Agent Run 或算力流水的持久化方式。

## 方案选择

采用“单页统计 + 双页签明细”。

没有采用统一事件流，因为一次 AI 调用可能同时对应消费和返还两条流水，管理员调整又没有 AI 任务。把这些记录强行压成同一种行结构会造成重复、字段空缺和筛选含义混乱。

没有采用独立统计页，因为它会继续保留任务、流水、统计三个入口，没有解决后台信息分散的问题。

## 页面结构

现有 `/admin/ai-tasks` 调整为“AI 使用”页面：

1. 顶部为三个周期卡片：今日总消耗、本周总消耗、本月总消耗。
2. 卡片同时显示周期起止、消费次数和使用人数；当前选中周期使用主题色弱高亮。
3. 卡片下方为“用户占比”表格，默认选择本月，按净消耗从高到低排序。
4. 用户占比表格显示用户、净消耗、消费次数和占比进度；分页后仍以该周期全体用户总消耗为分母。
5. 页面下方为“任务明细 / 算力流水”页签。
6. “任务明细”沿用现有筛选、任务表格、详情抽屉、上游刷新和失败返还。
7. “算力流水”沿用现有关键词查询、流水表格、新增、编辑和删除能力。

删除后台侧边栏中的独立“算力点日志”入口，并删除 `/admin/credit-logs` 页面组件。算力流水 API 及管理员写入接口继续保留，供合并后的页签使用。项目尚未上线，不保留旧页面路由转发组件。

## 统计口径

### 实际净消耗

统计只使用以下两类流水：

- `ai_consume`：原始消费，金额为负数。
- `ai_refund`：失败或取消后的返还，金额为正数。

`admin_adjust` 不进入任何使用统计。

同一用户、同一 `relatedId` 的消费和返还视为一次使用记录：

```text
净消耗 = max(消费绝对值合计 - 返还合计, 0)
```

真实业务调用都会写入稳定 `relatedId`。为避免异常或历史空关联流水互相合并，`relatedId` 为空时使用消费流水自身 ID 作为统计分组键。

统计按原始消费流水的首次创建时间归入周期，返还无论何时发生都回写到原消费周期。这样跨日返还不会让返还当天出现负使用量，也能让历史周期最终反映真实净消耗。

该口径覆盖普通 AI 任务和 Agent Run；超级管理员未实际扣点的免费调用没有消费流水，因此不进入“实际净消耗”。

### 时间周期

服务端固定使用 `Asia/Shanghai` 计算边界，再转换成数据库中现有的 RFC3339 时间字符串查询：

- 今日：北京时间当天 00:00 至次日 00:00。
- 本周：北京时间周一 00:00 至下周一 00:00。
- 本月：北京时间当月 1 日 00:00 至下月 1 日 00:00。

周期使用左闭右开区间，避免相邻周期重复统计边界记录。

### 用户占比

只返回净消耗大于 0 的用户，按净消耗降序、用户 ID 升序稳定排序。占比计算为：

```text
用户占比 = 用户净消耗 / 该周期总净消耗
```

总净消耗为 0 时，所有占比为 0，并显示空状态。已删除用户仍保留稳定用户 ID，并沿用现有删除用户展示规则。

## 后端设计

新增只读接口：

```text
GET /api/admin/ai-usage-summary?period=month&page=1&pageSize=10
```

响应继续使用 `{ code, data, msg }`，`data` 包含：

```json
{
  "periods": [
    { "key": "day", "startAt": "...", "endAt": "...", "netCredits": 120, "usageCount": 8, "userCount": 3 },
    { "key": "week", "startAt": "...", "endAt": "...", "netCredits": 680, "usageCount": 41, "userCount": 9 },
    { "key": "month", "startAt": "...", "endAt": "...", "netCredits": 2100, "usageCount": 126, "userCount": 15 }
  ],
  "selectedPeriod": "month",
  "users": [
    { "userId": "user-1", "user": { "id": "user-1", "username": "demo", "displayName": "演示用户" }, "netCredits": 630, "usageCount": 32, "ratio": 0.3 }
  ],
  "userTotal": 15,
  "page": 1,
  "pageSize": 10
}
```

职责边界：

- `handler/` 只解析 `period/page/pageSize`、调用 service 并返回 `OK` / `FailError`。
- `service/` 计算北京时间周期、规范周期参数、补齐用户摘要和占比。
- `repository/` 只执行消费/返还配对聚合、周期总量和用户分页查询。
- `model/` 定义统计响应、周期枚举和查询结构。

周期总量与用户占比共享同一条净消耗聚合口径，避免卡片总量与占比表分母不一致。统计查询不读取或解析 AI 请求 JSON。

## 前端设计

`web/src/app/(admin)/admin/ai-tasks/page.tsx` 保持装配层职责，组合以下页面私有模块：

- `components/ai-usage-summary.tsx`：周期卡片、选中状态、用户占比表格。
- `components/ai-task-log-panel.tsx`：从现有任务页面迁移筛选、任务表格和详情抽屉。
- `components/credit-log-panel.tsx`：从现有算力流水页面迁移查询、表格和编辑/删除弹窗。
- `use-admin-ai-usage-summary.ts`：读取统计、切换周期和用户分页。
- 现有 `use-admin-ai-tasks.ts` 保持任务行为。
- `use-admin-credit-logs.ts` 移入 `ai-tasks/` 目录并保持流水行为。

页面使用现有 Ant Design、后台主题 token 和 `adminUsageUserDisplay`，不新增页面私有全局 CSS，不硬编码浅色/深色主题分支。

## 数据刷新

- 打开页面时并行读取统计、当前任务页和当前流水页签所需数据。
- 切换统计周期或占比页码只刷新统计接口。
- 任务返还成功后同时失效任务详情、任务列表、算力流水和使用统计缓存。
- 新增、编辑或删除管理员流水后刷新算力流水；由于 `admin_adjust` 不参与统计，不刷新统计缓存。
- 手动刷新上游任务若触发返还，同时刷新统计与流水。

## 错误与空状态

- 统计接口失败时只在统计区域显示错误和重试按钮，不阻断任务与流水页签。
- 选中周期没有净消耗时，卡片显示 0，用户占比区域显示“该周期暂无实际 AI 消耗”。
- 用户摘要缺失时沿用“已删除用户 + 用户 ID”展示，不丢弃聚合记录。
- 非法周期回退为 `month`；分页继续沿用 `Normalize` 的范围限制。

## 验证

后端测试覆盖：

- 北京时间日、周、月边界，含月末和周日。
- 消费无返还、部分返还、全额返还和跨日返还。
- 管理员调整不进入统计。
- AI 任务与 Agent Run 的不同 `relatedId` 都进入统计。
- 空 `relatedId` 不会互相合并。
- 用户占比、排序、分页、删除用户摘要和零总量。

前端测试覆盖：

- 周期卡片与默认本月选择。
- 切换周期只改变统计查询。
- 占比展示和零总量空状态。
- 任务返还/刷新触发统计与流水缓存失效。
- 侧边栏只保留“AI 使用”，页面包含两个明细页签。
